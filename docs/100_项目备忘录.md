# 项目备忘录

## 已知问题：对话结果表格首次加载可能超过展示上限

- **状态**：已接受。对应 [3.1 历史对话结果快照表方案](3.1_历史对话结果快照表方案.md) §3.2–§3.3 的 `api.max_display_rows` 改造；该配置目前尚未实施。
- **原因与表现**：前端要收到首次 results API 响应后才知道 `max_display_rows`。按 3.1 方案实现时，首次请求会以回退值 200 计算请求行数，因此仍可能取回 100 行。若服务端配置为 10 或 50，页面按配置只展示 10 或 50 行，但内存中可能已有 100 行。
- **临时导出行为**：在 3.1 的服务端 CSV 导出端点上线前，现有 `exportCsv` 仍从已加载行生成 CSV；因此可能导出 100 行，即使页面只展示 10 或 50 行。导出行数不等同于页面展示上限。
- **后续**：接受首次请求可能多取行的现状；服务端 CSV 导出端点上线后，文件存在时导出全部已保存行，文件缺失时导出快照表中的行，与页面展示上限无关。
