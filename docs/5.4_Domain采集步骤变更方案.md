# 5.4 Domain 采集步骤变更方案

记录日期：2026-10-20。状态：**讨论共识；尚未修改代码**。

本文承接 [5.1_数据源工作区采集运行与发布运行模型.md](5.1_数据源工作区采集运行与发布运行模型.md) 和 [5.2_采集模板与发布模板表结构.md](5.2_采集模板与发布模板表结构.md)，明确 Domain 步骤的数据库描述由何处读取、何时生成、何时保留。本文只讨论 `database.description` 的生命周期；`domains` 及其表归属仍需随采集变化重新生成。

当前文件名为 **`db_domains.yaml`**，而非 `db_domain.yaml`。现有目录是 `output/<source_id>/<job_id>/domain/db_domains.yaml`；目标模型中，工作区边界对应 `output/<source_id>/<workspace_id>/domain/db_domains.yaml`。每次新增 `collection_run_id` 不代表必须重新生成该文件，同一工作区内的运行可以复用它。

## 1. 已达成共识的目标行为

### 1.1 工作区尚无 Domain 文件：首次生成

1. `db_domains.yaml` 尚不存在时，采集页面以 `db_source_info.description` 作为数据库描述的初始输入；用户可以在执行前修改本次输入。若数据源描述为空，是否要求用户填写仍待界面规则确定。
2. 用户勾选并执行 `domain` 后，LLM 根据本次输入和当前表结构生成初版 `database.description`、`domains` 及表归属，并写入工作区的 `db_domains.yaml`。
3. 执行前在页面上修改的输入是生成提示，不要求作为另一份长期有效的数据库描述写入 `job_info.db_desc`、采集模板或 `db_source_info.description`。生成后的 YAML 是该工作区描述的生效来源。

### 1.2 文件已经生成：读取、手工编辑与重跑

1. 再打开同一工作区时，页面从有效的 `db_domains.yaml` 的 `database.description` 读取当前描述，不再从 `job_info.db_desc` 或数据源描述推断该工作区的当前值。
2. 用户修改描述并点击保存时，直接更新 YAML 的 `database.description`；仅保存描述不调用 LLM，也不因保存动作重算 `domains`。
3. 以后**选中并执行** `domain` 时，仍根据当前表结构重新生成 `domains` 和表归属，以覆盖新增、删除或变化的表。重跑前先读取已有 `database.description`，并按 §1.3 备份旧文件；该描述可以作为领域分析的上下文，LLM 新返回的数据库描述不覆盖该值。写回文件时保留用户最后确认的 `database.description`。
4. 本次未勾选 `domain` 时，不执行 Domain 生成，也不修改 YAML。其他步骤在满足各自前置条件时，可以复用同一工作区已有的 Domain 产物。**不因文件存在而自动执行或自动勾选 Domain。**

这里的“仅首次调用 LLM 生成”专指 **`database.description` 的自动生成**。用户以后主动重跑 Domain 时，仍可以调用 LLM 更新 `domains`；只是生成结果中的 `database.description` 不再替换 YAML 现值。

### 1.3 重跑 Domain 时备份步骤目录

- Domain 采用 [第 6 章的统一步骤目录备份规则](6_工作区采集作业与发布作业四层模型.md)：准备向 `domain/` 写入新产物时，在 `domain/.backup/` 下创建 `bak_yyyyMMdd_HHmmss_SSS/`，把 `domain/` 中除 `.backup/` 自身以外的旧文件和目录全部移入该备份目录，保留原文件名；以 `.` 开头的文件也在备份范围内。目标模型示例为 `output/<source_id>/<workspace_id>/domain/.backup/bak_20261020_103700_100/db_domains.yaml`。首次生成且目录没有旧文件时，无须备份。
- 用户手工编辑并保存过的 `db_domains.yaml` 同样属于下次重跑前的旧文件。备份发生在清理或写入新产物之前；备份失败时记录告警，删除未成功备份的旧文件后继续生成，不因备份失败阻断本次运行。不完整的备份不得视为可恢复的完整版本。仅写入运行结果标志文件不触发再次备份，但下次生成新产物时，已有标志文件一并备份。
- 时间戳使用系统约定时区（当前为 `Asia/Shanghai`）；同一毫秒内发生重名时不能覆盖已有备份。旧产物已移走或备份失败后已删除的情况下，生成或校验失败不能保证旧文件仍位于当前 `domain/`，应以本次步骤失败记录和实际文件状态为准。

### 1.4 本阶段不做自动完整性提醒

本阶段由用户判断是否勾选 Domain。即使文件存在，只要表结构变化，用户仍可主动重跑 Domain。将来可以比较当前受管表清单和 YAML 中的表归属，在发现新表未归类、旧表已删除等情况时提醒用户；**这属于后续能力，本阶段不实现自动检测、提醒或自动重跑**。

## 2. 与当前代码的差异

| 环节 | 当前实现 | 目标规则 |
| --- | --- | --- |
| 采集页打开描述 | 重跑时优先用本 `job_id` 的 `job_info.db_desc`，没有再用数据源描述；不读取 YAML | 首次无 YAML 时用数据源描述初始化；已有有效 YAML 时用其中的 `database.description` |
| 点击描述弹窗的“保存” | 仅保存到当前页面状态，选中并执行 Domain 后才发送给后端 | 首次生成前的输入仍为页面草稿；已有 YAML 的描述编辑须直接保存到该文件 |
| 执行 Domain | 请求描述 → `job_info.db_desc` → 数据源描述；生效值写入 `job_info.db_desc`，可选同步到数据源 | 首次生成后以 YAML 为生效来源，不再向 `job_info.db_desc` 保存另一份当前描述；Domain 执行不自动同步修改数据源描述 |
| 生成文件 | 清理 Domain 目录，LLM 重新生成 `database.description` 与 `domains`，写出整份 YAML | 首次同时生成两者；后续重跑只采用新 `domains`，保留已有 `database.description` |
| 重跑前备份 | 清理顶层文件时直接删除旧 `db_domains.yaml`，没有同目录备份 | 写入前将步骤目录旧内容移入 `.backup/bak_yyyyMMdd_HHmmss_SSS/`；备份失败则告警、删除未备份的旧文件并继续生成 |
| 已有文件的描述编辑 | 发布页显示 `database.description`，但编辑接口拒绝改动该字段，只允许编辑 `domains` | 允许用户显式编辑并保存 `database.description`，无需调用 LLM |
| 跳过 Domain | 重跑已有作业时可取消勾选；下游在满足既有步骤成功记录与文件校验时读取旧产物 | 保持可选执行与产物复用；不把 Domain 变成每次采集必跑步骤 |

## 3. 对模板与运行记录的影响

- 采集模板可以选择是否执行 `domain`，但**不把工作区当前的 `database.description` 复制进 `collection_template.step_config`**。因此 5.2 中原先以 `domain_description` 为固定参数的示例不再适用；`step_config` 只保留给其他确实需要固定、且执行入口会消费的运行参数。
- 发布模板仍只保存发布步骤集合；发布时读取工作区当时有效的 Domain 产物，不绑定某份旧 YAML。
- 成功创建的完整 `.backup/bak_yyyyMMdd_HHmmss_SSS/` 可用于查看旧版 `database.description` 与 `domains`；备份失败时可能没有可恢复的完整旧版。若以后要求按 `collection_run_id` 或 `publish_run_id` 准确追溯当次使用的版本，还须建立运行与文件版本或校验值的关联；备份目录名本身不足以确定某次运行读取了哪一版。具体关联和备份保留期限尚未设计。

## 4. 尚待明确的实现边界

1. **无效文件的处理。**已有 `db_domains.yaml` 但内容损坏或不完整时，不能仅凭“文件存在”当作可复用产物；报错、修复和重新生成的具体交互待设计。
2. **写入时的一致性。**Domain 重跑必须先取得旧 `database.description` 并尝试备份，再处理新 `domains`；备份失败按统一规则告警并继续。用户编辑描述与重跑并发时的版本校验方式待设计。
3. **人工编辑的其他内容。**本次只确定保留 `database.description`。用户手工修改过的 Domain 名称、描述和表归属，在主动重跑 Domain 后如何处理，尚未形成保留或合并规则。
4. **首次输入原文的历史。**首次提供的描述是生成提示，YAML 记录的是 LLM 生成后的 `database.description`。是否需要另外保留那句原始提示，尚未决定；不能把两者当成相同内容。
