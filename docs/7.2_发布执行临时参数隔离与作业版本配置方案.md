# 7.2 发布执行临时参数隔离与作业版本配置方案

编写日期：2026-10-28。状态：**问题分析与修改建议，尚未实施。**

实施边界：**直接按新配置结构实现，不兼容旧版本、旧数据或旧参数格式，不做旧数据迁移，不增加兼容适配或读取旧 YAML 的运行回退逻辑。** 新建或编辑作业时，从当前采集 YAML 自动初始化配置草稿属于正常的配置编辑流程，不属于旧数据兼容；编辑存量作业时也可自动加载缺失的草稿初值，并按新结构保存新版本，但不自动转换或修改既有版本。运行时以新版本配置及本次允许的覆盖为准，不读取 YAML 作为隐式回退。

字段数量口径以本次澄清为准：**LLM 每表最多推荐一个维度值字段，人工可为同一表配置一个或多个字段。** 7.1 的 0/1 推荐校验继续保留；其基于当时 Web 限制提出的人工配置及发布单列限制，由本文的新规则取代，不得再据此拒绝人工多字段配置。7.1 文首已补充后续变更指针，不将其中旧限制当作实施依据。

断代后的预期表现：存量版本若缺少新契约要求的 `dim_value.tables` 或 `domain.domains`，运行时明确报告对应步骤必需配置缺失，需编辑作业并保存新版本。此为预期行为，不提供自动转换、迁移或兼容执行分支。

## 1. 问题与预期行为

在发布作业执行页勾选“修改步骤或参数”后，编辑 `dim_value`、新增表和字段并保存，目前会将结果写回工作区的 `dim/dim_tables.yaml`。例如将 `public.screenings` 的 `hall_id` 加入配置，即使只是准备本次手工执行，也改变了后续运行读取的配置。

问题复现入口示例：

```text
/workspaces/ws_68/publish/jobs/pub_job_91/run?revision_no=1&mode=custom
```

这一行为与系统的版本及运行模型冲突：

- **执行页修改**：步骤选择及参数覆盖只对本次运行有效，不修改工作区配置文件，不修改作业或已有版本。
- **作业配置修改**：希望后续复用的步骤和参数，应通过作业编辑保存为新版本；已有版本保持不可变。
- **运行留痕**：临时参数可以写入本次运行的记录，用于审计。这不等于保存回正式配置。

本次需求不改变发布本身的目标写入行为：用户执行发布后，下游数据库或向量库仍会按本次有效配置发生预期更新。“临时”限定的是配置的作用范围，不代表发布结果自动回滚。

## 2. 当前原因与相关入口

执行页 `frontend/src/views/RunExecuteView.vue` 复用了 `DimValueConfigDialog.vue`。该弹窗原有保存语义是调用配置 PUT 接口，覆盖工作区 YAML，因此不能直接作为临时参数编辑器使用。

相关代码入口：

| 范围 | 文件及核查内容 |
| --- | --- |
| 发布执行页 | `frontend/src/views/RunExecuteView.vue`：custom 参数状态、弹窗事件、预检及运行提交。 |
| 配置弹窗 | `frontend/src/components/DimValueConfigDialog.vue`：当前保存会调用工作区配置 PUT；需区分临时应用与文件保存。 |
| 前端 API | `frontend/src/api/workspaces.ts`、`types.ts`：运行参数及预检请求类型。 |
| 参数解析 | `metaweave/backend/jobs/job_params.py`、`run_request.py`：参数白名单、版本默认值与 custom 覆盖。 |
| 发布编排与预检 | `metaweave/backend/publishing/publish_service.py`、`precheck.py`：创建前校验、运行快照及执行期复查。 |
| Dim 配置及加载 | `metaweave/backend/profile_loading/dim_value_config_api.py`、`dim_value_loader.py`：配置校验复用及加载器注入。 |
| 作业版本 | `metaweave/backend/jobs/job_service.py` 等：保存默认配置时生成新版本。 |

以上为修改入口，不代表当前运行接口已支持下文的新参数。

## 3. 推荐方案：运行参数覆盖

执行页编辑过程中只维护内存中的草稿；点击“应用到本次执行”后，将草稿作为本次运行的 `dim_value` 参数覆盖提交。后端解析出有效配置，用其完成预检、运行登记和加载，不覆盖共享 YAML。

```text
读取引用版本的默认配置
        ↓
custom 执行页编辑内存草稿
        ↓
应用到本次执行 → 校验本次有效配置
        ↓
提交运行 → 固化有效配置到运行步骤
        ↓
加载器使用运行配置执行发布
```

不采用“先覆盖 YAML，执行后恢复”的方案。该方式在并发运行、执行异常或进程退出时可能留下错误配置，也会让其他运行读到临时值。

### 3.1 临时配置结构

建议沿用运行请求现有的 `step_config` 外层结构，扩展 `dim_value` 可接收完整表清单：

```json
{
  "step_config": {
    "dim_value": {
      "tables": [
        {
          "schema_name": "public",
          "object_name": "screenings",
          "embedding_col": ["hall_id", "screening_name"]
        }
      ]
    }
  }
}
```

示例仅展示新增参数部分；运行请求的 `mode`、版本、步骤等字段继续沿用现有接口契约。字段名为示意，实际必须存在于该表的画像中。人工配置允许每表一个或多个字段。字段推荐和置信度属于只读辅助信息，不进入执行配置；用户采用推荐后，对应字段作为普通执行配置提交。

### 3.1.1 LLM 推荐与人工配置分离

- `dimension_value_columns` 只描述 LLM 原始推荐，仍仅允许 0 或 1 个元素；返回多个仍按 7.1 整组清空，不放宽推荐校验器。
- 自动 Dim 生成器继续有推荐写入一个字段、无推荐留 `null`；其只表示自动生成结果的 `Optional[str]` 不必改成多列类型。
- 人工可以在 YAML 中写单个字符串或字段列表，例如 `embedding_col: [product_name, product_alias]`。YAML 校验允许两种形态，不能将列表归为未配置，也不检查“最多一个”；空配置和非法元素仍需处理。
- 前端草稿、版本参数及运行参数统一将 `embedding_col` 表示为字段名数组；单字段也是单元素数组。自动 YAML 初始化时将不含逗号的单字符串转为单元素数组、列表保留全部字段、`null` 转为空数组；含逗号的字符串同样按未指定转为空数组，并提示“请使用字段列表格式”，不得包成单元素数组后误报字段不存在，也不得拆分。新版本及运行快照保存规范化数组，不新增旧版本格式回退。
- 保留的文件 GET/PUT API 支持 `string | string[] | null` 的配置值，GET 必须完整返回人工配置的列表；PUT 须接受合法非空字段列表，不再将列表视为未指定字段并因此拒绝保存。当前 PUT 对列表走未指定字段错误分支，并非专门的多字段数量错误。空配置仍按既有未配置规则处理；文件接口保持文件编辑职责，不被运行路径调用。多字段使用列表，不新增逗号串写法：文件读取遇到含逗号的字符串仍按现有规则视为未指定，不拆分、不截取；PUT 继续拒绝逗号串，要求改用字段列表。
- 加载器对每个字段分别读取维度值并向量化，不将多个字段拼接为一个实体名称；检查构造配置、注入和加载路径不能截取首项。
- 置信度只属于 LLM 推荐的字段，不扩展为对整个人工清单的评分。人工清单与原推荐对比时按字段集合判断：多选了其他字段也属于“当前配置与模型推荐不同”，不产生新的置信度。

### 3.2 完整替换语义

临时提交的 `tables` 表示本次 `dim_value` 的**完整执行范围**，不是与 YAML 做合并的增量：

- 草稿新增的表参与本次发布。
- 草稿删除的表不参与本次发布，后端不得从默认配置或 YAML 自动补回。
- 草稿中每张表的字段数组也是完整替换：删除的字段不从默认值或 YAML 补回，追加的字段全部参与本次发布。
- 未提交 `dim_value.tables` 时继承引用版本的默认值。
- 显式空列表不等同于缺失，不得回退默认值；返回既有 `dim_value_empty_tables` 错误码及文案：“dim_value 未配置任何表：请为 dim_value 添加表并指定值向量化字段，或取消勾选 dim_value”。若外层统一包装逐步骤预检失败，应保留此具体原因码，可在 details 标注来自本次参数，不新增平行错误码。
- 只允许覆盖本次选中且引用版本允许的步骤；custom 参数不写回版本。

## 4. 前端交互

自动初始化不需要用户点击按钮：移除新建页和作业编辑器中 Domain、Dim 的“从当前配置初始化”按钮。新建发布作业时自动读取两份 YAML；编辑时已有版本配置优先，仅缺少对应草稿时读取 YAML。每个页面上下文只初始化一次；两份读取独立失败、局部提示，失败仍可手工编辑。读取中禁用草稿编辑和保存；异步响应不得覆盖已应用草稿或其他工作区/版本的状态。执行页始终从引用版本及运行草稿初始化，不因此增加 YAML 回退。自动读取与是否写回文件互相独立，不修改任何文件保存语义。

本期 Dim/Domain 弹窗只支持运行草稿和版本草稿两种用途，均不保存工作区文件，不能仅改按钮文字而仍调用 PUT。

1. custom 执行页打开弹窗时，通过 props 传入当前草稿或引用版本默认配置，并深拷贝为独立编辑状态。临时模式不得调用 GET `dim-config` 或 GET `domain-config` 初始化清单，也不使用其文件指纹作为应用草稿的条件。默认配置缺失按新契约报错，不回退 YAML。
2. 弹窗按钮使用“应用到本次执行”，校验后只将表清单回传执行页，不调用工作区配置 PUT。
3. 取消或关闭弹窗不应用未确认的修改；重新打开时显示已经应用到本次执行的草稿。
4. 表及字段候选、推荐使用不依赖被编辑 YAML 的只读接口。Dim 候选及字段取自当前工作区 JSON 画像；Domain 候选取自同工作区 MD 清单及对应普通文件，移除 `list_domain_tables` 中加载 Domain YAML 的前置要求，不改为从 JSON 枚举。Dim 推荐原来随 YAML GET 返回，需抽离为独立只读读取能力，可复用按工作区定位的推荐校验逻辑，不能为获取推荐重新调用配置 YAML GET。候选或推荐失败时局部提示，不阻断已有草稿展示；会话内新增表仍可显示推荐未加载，不要求立即获取推荐。
5. 临时参数或步骤选择变化后，相关预检结果失效；需用新的有效参数重新校验。
6. 默认执行模式不提供隐式修改配置的入口；需要临时参数时进入 custom 模式。
7. 需要长期保留时，通过作业编辑创建新版本；执行页不隐式创建版本或修改当前版本。

执行页离开或取消执行后，不持久化临时草稿为正式配置。**本期 UI 不保留 Dim、Domain、Rel 的持久化文件编辑入口，不新增独立宿主页面。** Dim/Domain 弹窗删除持久化保存分支及仅为其服务的文件指纹状态、PUT 调用；后端文件 GET/PUT API 保留，供自动 YAML 初始化及后续独立工具使用，保留 API 不代表本期要实现第三种弹窗模式。执行页只应用运行草稿，作业编辑/新建页只应用版本草稿，后者最终随作业保存。

第 4 项的推荐加载规则明确如下：临时弹窗每次打开时，对 props 中的全部表（版本默认清单或已应用草稿，包括上一次会话新增并已应用的表）统一通过独立只读能力读取推荐，按结果展示推荐、无推荐或信息不可用；只有本次会话新添、尚未应用的行显示“推荐未加载”。点击“应用到本次执行”不保存文件，重新打开即可为这些表加载推荐，不要求先执行发布或保存作业。临时模式的提示相应改为“应用后重新打开可查看”，不沿用 7.1 持久化模式的“保存后”文案。

推荐读取能力抽离后，文件 GET `dim-config` 响应保留 7.1 的推荐字段及既有语义不变，供自动初始化和后续独立工具使用；它与独立推荐读取复用同一读取和校验逻辑，不从文件 GET 响应中删除推荐字段。临时与版本草稿弹窗均不得为取得推荐而调用该 YAML GET；新建/编辑页自动 YAML 初始化由父页面负责。

## 5. 后端预检与执行一致性

### 5.1 解析同一份有效配置

由统一解析逻辑得到“引用版本默认值 + 本次允许的临时覆盖”的有效参数。`tables` 按完整清单替换，不逐表深合并。

预检、创建运行和执行必须使用相同解析规则，避免前端按临时配置通过、后端仍按 YAML 拒绝或加载其他表。

### 5.2 临时配置预检

当前以工作区文件为输入的发布校验需要扩展为可以接收版本配置和临时参数，具体接口形式在实现时结合现有 API 统一确定。原只读工作区检查可保留，但不能冒充对临时草稿的校验。

- 不因基础 YAML 某表未指定字段，就直接禁止用户进入临时编辑。应区分上游产物就绪与本次有效配置是否完整。
- 用户应用草稿后，针对实际清单校验表和字段、每表非空字段数组、重复表、源及工作区边界等条件。数组仅含真实存在的非空字段名，按原始大小写核对；规范化时按首次出现顺序去重，不限制最多一个字段。每表字段为空仍按未配置处理，不与整个 `tables: []` 的零表错误混淆。
- 临时配置不豁免既有源启用、上游产物、采集 marker、路径和发布准入检查；需分离的是 YAML 作为有效参数来源的角色。
- 正式创建运行时重新校验本次参数，不信任前端历史预检结果。失败时沿用集中预检的整单拒绝语义。

### 5.2.1 新模型下的准入最小集

下表适用于 default 和 custom：有效参数来自版本快照及允许的覆盖，YAML 在新建或编辑作业时自动用于初始化草稿。

| 发布步骤 | 保留的准入与依赖检查 | 不再要求的运行条件 |
| --- | --- | --- |
| `dim_value` | 当前工作区 `dim` 目录顶层唯一成功采集 marker；当前工作区 JSON 画像中的真实表和 `column_profiles` 字段范围；本次完整清单非空、每表至少一个有效字段，允许多个；既有源启用、登记边界、路径安全和加载源库检查。 | `dim_tables.yaml` 存在、可解析、包含某表或字段已填写。不要求运行表清单与自动识别的维表列表相同，用户可从合法候选中添加表。 |
| `domain` | 当前工作区 `domain` 目录顶层唯一成功采集 marker；同工作区 MD manifest 合法，所引用表在清单中且对应 MD 仍是普通文件；数据库名、schema 与来源边界；本次完整域清单及有效表归属校验。 | `db_domains.yaml` 存在、可解析或内容与本次清单一致。不将 YAML 中的旧域归属作为运行配置。 |

不额外新增 JSON、MD 成功 marker 依赖。候选读取和发布校验使用同一来源与范围规则，不能仅依赖前端下拉列表；执行期仍复查所需外部条件。Domain 的现有候选接口本就源自 MD 清单，需去掉的是 YAML 耦合，不是将候选来源替换为 JSON。

**草稿可编辑与发布可执行分开判断：**YAML 缺失、损坏或字段未配置，均不能阻断从 props 打开临时弹窗；marker 缺失或失败不阻断草稿展示，但正式预检及执行仍拒绝。候选缺失可限制新增或字段选择，不得因此丢弃已有草稿。

输入 manifest 只登记实际读取的产物，不把未读取的 Domain/Dim YAML 伪记为运行输入。有效配置在运行步骤参数中留痕；采集 marker 按既有来源机制核验，MD、JSON 等实际读取文件按各自规则记录。

### 5.3 运行快照与加载器注入

运行创建成功时，将解析后的完整有效清单固化在 `publish_run_step.step_config` 中；运行详情可查看这些实际参数，而非仅查看用户提交的差异。

执行器从运行快照构造 Dim 配置对象并注入加载器，不写共享 YAML，也不在执行时重新从最新 YAML 或最新作业版本解析执行范围。执行期按既有机制复查源、依赖及可变外部条件；条件不满足时正常阻断或失败，不静默改用另一份配置。

如现有加载器已接受配置对象，应复用该能力；不得为传递临时参数而临时覆盖共享文件。

## 6. 正式配置与版本保存

配置完整且已选择步骤时，应允许点击“保存新版本”，不以尚未手动点击“发布校验”为由禁用按钮。保存流程自动执行已有发布校验，失败时显示逐步骤原因并保留配置草稿；手动“发布校验”按钮保留，供提前检查。初始化、校验或保存进行中禁用重复提交。

为保证“修改正式参数应创建版本”的要求，建议将完整 Dim 表清单纳入发布作业版本的 `step_config.dim_value.tables`。

- 新建作业时自动读取工作区 `dim_tables.yaml` 初始化草稿；编辑作业时优先使用版本配置，仅缺少对应草稿时自动读取 YAML；用户确认保存后，将其快照作为版本默认参数。
- 修改正式表清单、字段或步骤时创建新版本，不修改旧版本。
- default 运行使用引用版本的完整默认清单，custom 从该版本开始覆盖。
- YAML 保留为采集产物及配置初始化来源，不再作为已保存版本运行时可随时变化的默认参数。

新发布作业版本选择 `dim_value` 时，必须按新结构保存完整的 `step_config.dim_value.tables`。创建、编辑及执行均按新契约校验；缺少必需配置时直接报配置错误，不提供旧版本兼容、历史数据迁移或 YAML 回退路径。

版本清单固定不代表候选范围永久不变：采集重跑后表被删除、重命名或字段消失，下次 default 运行应在创建前整单拒绝，列出具体失效项并提示“编辑作业创建新版本”，不能笼统提示重跑采集。custom 可调整本次清单后重新校验，无需强制保存版本；配置创建完成后仍按运行快照选择范围，外部条件失效则阻断或失败，不自动改选其他表或字段。

运行参数快照提供配置审计，不保证源数据与外部产物永久不变，因此不将其表述为对历史发布结果的完全复现。

## 7. Domain 临时配置隔离

### 7.1 已确认的问题

Domain 存在与 Dim 相同的问题，并非仅为待核查风险：发布执行页的 custom 编辑入口直接打开 `DomainConfigDialog.vue`，弹窗保存调用 `putDomainConfig`，后端 `write_domain_config` 备份旧文件后原子替换：

```text
output/<source_id>/<workspace_id>/domain/db_domains.yaml
```

执行页随后仅刷新发布预检，不创建新作业版本。即使用户取消发布，业务域名称、描述和表归属的文件修改也已生效，后续读取该工作区 Domain 文件的采集或发布可能受影响。文件备份、指纹冲突检查及不更新采集 marker，均不能实现“只对本次运行有效”。

当前 `PUBLISH_STEP_PARAMS` 对所有发布步骤均为无可配置参数；采集步骤的 `domain.description` 是首次生成输入，不是发布 Domain 清单，不能拿它替代本次配置覆盖。

### 7.2 参数结构与作用范围

与 Dim 一样，将正式默认值纳入发布作业版本，将 custom 覆盖纳入本次运行。建议为发布 `domain` 增加 `domains` 参数：

```json
{
  "step_config": {
    "domain": {
      "domains": [
        {
          "name": "放映业务",
          "description": "影院放映场次及相关业务",
          "tables": ["your_database.public.screenings"]
        }
      ]
    }
  }
}
```

`your_database` 仅为示意，实际使用现有候选表接口返回的完整 ID，格式为 `database.schema.table`，不改成 Dim 的二段式表名。暂只覆盖业务域名称、描述、表归属，不覆盖工作区、数据源绑定、数据库名或 `llm_inference` 等生成设置。数据库信息和候选范围由后端按工作区解析，不能由调用者改绑。

`domains` 是完整替换清单，不与 YAML 或版本默认值逐域合并；被删除的域或表归属不得自动补回。未提交该属性则继承引用版本；显式 `[]` 不等同于缺失，沿用 Domain 无有效表归属不可发布的规则拒绝，不回退默认值。取消本次 Domain 发布应取消选择步骤。

### 7.3 编辑与版本保存

- 执行页通过 props 传入本次 Domain 草稿或引用版本默认值；使用独立草稿，取消不影响已应用内容。临时模式不调用配置 YAML GET，候选读取按 §4 和 §5.2.1 与 YAML 解耦。
- 临时模式按钮为“应用到本次执行”，仅回传规范化业务域清单，禁止调用 `PUT /api/workspaces/{id}/domain-config`，不写 YAML、不备份文件、不新建版本。
- 应用草稿后使相关预检失效；再次打开时显示本次已应用草稿，离开执行页不持久化为正式配置。
- 作业编辑页优先使用版本参数，无对应草稿时自动从工作区 YAML 初始化，确认保存时将完整 `domains` 清单保存到新版本；不覆盖已有版本。default 执行读取引用版本清单，custom 执行在其上覆盖。
- 新发布作业版本选择 `domain` 时，必须按新结构保存完整的 `step_config.domain.domains`；缺少必需配置时直接报配置错误，不兼容旧版本，不迁移历史数据，也不读取共享 YAML 作为运行回退值。

Domain 与 Dim 遵循 §4 的同一 UI 边界：本期不保留持久化文件编辑入口，弹窗仅编辑运行或版本草稿；后端文件 GET/PUT API 保留，但不为其新增 UI 宿主。

### 7.4 校验、运行快照与执行

统一解析版本默认值和本次覆盖，得到完整 Domain 有效清单，供参数预检、运行创建和执行共同使用。

- 复用并按需抽离现有不含文件写入副作用的校验：域名称及描述非空、域名称唯一、域内表名不重复；表必须符合 §5.2.1 的同工作区 MD 清单、普通文件及来源边界规则，继续遵守既有发布对有效表归属的要求。不要直接调用带文件保存副作用的配置接口。
- 临时清单合法性应与基础文件内容校验分开，允许用户用临时清单修复当前归属问题；不豁免依赖采集 marker、源启用及其他发布准入条件。正式创建运行必须重新检查本次有效清单。
- 在 `publish_run_step.step_config` 中固化完整有效 `domains`，不仅保存用户差异。执行期复查外部依赖，但不得重新从共享 YAML 读取清单并覆盖运行快照。
- `domain_loader.py` 当前读取 YAML 并映射发布行，应拆分为“读取文件”和“校验、映射文档”两层，让运行路径可注入 Domain 配置对象，复用映射规则而不修改物理文件。
- 临时清单不写回 YAML，不触碰采集 marker；发布内容按现有事务及来源替换语义写入目标，不额外引入追加或回滚语义。

Domain 临时发布不会重算现有 Rel、SQL 等采集产物。同次发布其他步骤仍各自遵循其有效配置与依赖校验，不将临时 Domain 自动扩散为其他步骤的配置覆盖。

因此，本次发布写入 `table_domain` 的归属可能与共享 YAML 不同；后续 Rel、SQL 采集仍使用共享 YAML，结果可能与本次临时发布的域归属不同。这是临时配置不落盘的预期边界，不自动同步或重算，也不承诺二者一致。如需长期调整发布默认值，应创建新版本，但保存版本不会更新采集依据。本期没有修改共享 YAML 的 UI 入口；需要改变后续采集依据时，只能手工修改服务器上的 YAML，或重跑 Domain 采集重新生成。重跑会重新进行模型推断，不保证生成用户期望的归属，也不是将临时发布清单保存回文件的替代操作。独立文件编辑工具另行建设，不属于本期已提供能力；本期不新增 UI 收敛路径。

## 8. 验收建议

1. 在 custom 执行页新增 `public.screenings` / `hall_id` 后点击“应用到本次执行”，工作区 YAML 内容及版本记录不变，未调用配置 PUT。
2. 取消弹窗不应用修改；应用后再次打开仍显示本次草稿；离开执行页不会持久化草稿为正式配置。
3. 执行时仅按提交的完整清单加载；删除的表不从 YAML 或版本默认值补回。空列表校验失败，不被当作无覆盖。
4. 临时参数变化使旧预检失效；创建运行前重新校验有效参数，执行使用同一配置快照。
5. YAML 未配置、缺失或损坏时，临时弹窗仍从 props 展示版本配置或已应用草稿，可修改并重新校验，不调用配置 YAML GET。候选及推荐接口不依赖该 YAML；候选失败仅局部降级。marker 缺失或失败时草稿仍可展示，但发布准入按 §5.2.1 拒绝，不被临时参数绕过。
6. 单字段及人工多字段配置均可通过校验；重复表、字段有效性、步骤白名单和工作区边界继续校验。每表字段数组按规则去重，空字段配置仍拒绝；推荐信息不作为可执行参数提交，LLM 多字段推荐仍整组清空。
7. 本次完整有效参数保存在运行步骤，可从运行详情核对；运行不修改作业默认版本。
8. 两次运行使用不同临时清单时互不污染共享配置，异常退出也不留下需要恢复的临时 YAML。
9. 作业编辑保存正式清单产生新版本；default 与 custom 均以引用版本为基准。选择 `dim_value` 的新版本必须包含完整默认清单，缺少必需配置时直接报错；不实现旧版本兼容、旧数据迁移或 YAML 回退。
10. YAML 初始化、后续采集重跑与版本默认清单彼此边界明确；已创建运行不因文件变化而重新选择表清单。下次 default 执行遇到版本中的表或字段已不在当前合法候选范围时，创建前整单拒绝，列出失效项并提示编辑作业创建新版本；custom 可修正本次清单后重新校验。
11. Domain custom 模式新增或修改域名称、描述、表归属后，“应用到本次执行”不调用配置 PUT，YAML 内容、备份目录和采集 marker 不变；取消弹窗或取消发布不产生文件修改。
12. Domain 预检、运行快照和实际发布使用同一完整清单；删除的域及表归属不被补回；空清单、重复域名、未知表及其他非法配置按既有规则拒绝。更改草稿后旧预检失效，不以旧 YAML 的内容校验替代有效清单校验。
13. Domain 作业配置修改生成新版本，default 使用引用版本；选择 `domain` 的新版本必须包含完整默认清单，缺少必需配置时直接报错，不实现旧数据兼容或迁移。创建运行后修改或重采集 YAML，不改变该运行已固化的域清单。
14. 不同 Domain 临时运行不互相覆盖配置，异常退出不留下临时文件改写；目标发布仍遵守既有事务及来源替换语义。临时 Domain 不隐式改写 Rel、SQL 产物或其他步骤参数。
15. `RunExecuteView.vue`、`JobConfigEditor.vue`、`CreateJobView.vue` 三处不再提供 Rel 文件编辑按钮及挂载，Rel 步骤仍可选择与执行；后端 `rel_config_api.py` 行为不变。本期不新增独立文件编辑页面；`RelEditDialog` 无引用时删除。
16. default/custom 均按 §5.2.1 的准入最小集处理：有成功 marker、所需候选产物及合法有效清单时，不因 Domain/Dim YAML 缺失或损坏而拒绝；marker 非成功、候选越界、MD 引用文件失效仍拒绝。输入 manifest 不登记未读取的 YAML。
17. Dim 显式 `tables: []` 返回 `dim_value_empty_tables` 及既有文案，不回退默认值、不新增平行错误码；缺少新结构必需配置的存量版本按断代约定报错，不迁移、不自动转换。
18. 临时 Domain 发布不会改写共享 YAML；后续 Rel、SQL 采集仍按 YAML 执行，即使归属与本次 `table_domain` 不同也不自动同步，不将这一预期边界当作配置未生效。
19. Dim 作业编辑按钮修改版本草稿，新建页面编辑首次版本草稿；弹窗应用、取消均不写 YAML，只有确认保存作业才写入相应版本。新建时自动 YAML 初始化失败不阻断手工配置，不重复初始化覆盖用户草稿。
20. 临时弹窗重开时，props 中的全部表均尝试独立读取推荐，包括前一次新增且已应用的表；仅本会话新添未应用的行显示“推荐未加载”。推荐读取失败局部降级，不调用配置 YAML GET；持久化 GET 的推荐字段仍保留并与独立读取使用相同校验口径。
21. Domain 作业编辑与新建页的编辑按钮均只编辑版本草稿，不调用文件 PUT；自动 YAML 初始化失败可手工配置，取消不保存，确认保存作业才生成对应版本。Dim/Domain 弹窗不存在持久化保存分支或专用文件指纹状态，本期 UI 没有持久化文件编辑宿主，后端文件 API 保留。
22. YAML 单字符串、人工多字段列表及 null 分别初始化为单元素数组、完整数组及空数组；文件 GET 不将列表置空，文件 PUT 不拒绝合法多字段。版本和运行快照保留全部字段；实际加载逐字段采集，不拼接、不截取首项。
23. 人工在单字段推荐上追加第二个字段后，弹窗可完整展示、移除及再次应用；只显示原始推荐的置信度，按字段集合提示与推荐不同，不对人工新增字段编造评分。单字段自动推荐的生成行为及非法多字段推荐清空规则保持不变。
24. custom 对本次未选中的步骤提交 `step_config`，或对引用版本不包含的步骤提交覆盖，均必须返回 HTTP 400，不能静默忽略或自动选中步骤，不创建运行、不写版本或 YAML。分别覆盖 Domain、Dim 新参数路径，防止扩展参数后破坏既有步骤子集约束。
25. YAML `embedding_col: hall_id, screen_name` 在自动初始化时转为空数组，提示使用字段列表格式，不拆分、不作为一个真实字段名校验；运行加载器构造只接收已校验数组，不借核心模型字符串分支重新启用逗号拆分。人工多字段读写的新测试替换旧单列限制断言，自动推荐单字段相关测试继续有效。
