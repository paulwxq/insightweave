# 6.3 WebUI 设计稿索引与实现约定

本文配合 [第 6 章：工作区采集作业与发布作业四层模型](6_工作区采集作业与发布作业四层模型.md)、[6.1 建表语句汇总](6.1_建表语句汇总.md)、[6.2 MetaWeave 改造实施方案](6.2_MetaWeave改造实施方案.md) 使用，用于索引 [docs/webui/insightweave/](webui/insightweave/) 下的 WebUI 设计稿，并约束页面路由、用户路径、视觉风格和未覆盖页面的实现方式。

本文不是第二套业务设计：已确认的数据模型、表结构、接口和发布规则以 doc 6、6.1、6.2 为准；实际后端代码用于核对实现状态。代码与文档不一致时，视为实现差异或待办，不用代码反向覆盖已确认规则；文档未覆盖而代码已实现的内容，先补充文档，再作为约定。

设计稿目录中的每个文件都有同名 `.html` 与 `.png` 两种格式。**HTML 是布局与样式的可读来源，PNG 是预览图**；两者不一致时以 HTML 为准并重新导出 PNG。设计稿中的名称、ID、步骤、运行状态和数字均为演示数据，不是接口契约。

## 1. 读者与权威顺序

| 读者 | 使用方式 |
| --- | --- |
| 前端开发 | 按本文路由、页面状态和视觉规范实现；页面细节参考对应 HTML。 |
| 编程 AI / 代码生成代理 | 先读本文的“禁止照抄项”和“未覆盖页面规则”，再参考 HTML，不得自行发明业务规则。 |
| 产品 / 设计 | 用本文核对页面覆盖、用户路径和设计稿差异。 |
| 后端开发 | 用页面地图确认前端需要哪些接口，不把设计稿 mock 数据当作接口字段。 |

发生冲突时按以下顺序裁决：

1. **业务规则、数据模型、DDL、API**：doc 6、6.1、6.2 中已确认的约定。实际后端代码用于核对实现状态，不作为覆盖文档的依据。
2. **路由、页面状态、AI 实现约定**：本文。
3. **视觉布局、间距、颜色、组件形态**：设计稿 HTML。
4. **快速预览**：设计稿 PNG。
5. **演示名称、ID、步骤、状态、数字**：一律视为 mock，不作为契约。

如果后端代码尚未实现文档中的规则，前端按文档和接口契约实现，并把差异记录为后端待办；如果代码已实现而文档未覆盖，先补充文档，再作为约定。

## 3. 用户与页面路径

### 3.1 操作者

当前文档没有定义登录、角色或权限矩阵；`created_by_user_id` 允许为空。设计稿中的 `admin`、`zhangsan`、`liwei`、`chenmo` 等只是演示数据，**不得据此实现 RBAC 或用户体系**。

本文只描述操作路径，用“操作者”表示典型使用场景：

- **平台管理员 / 数据工程师**：登记数据源、创建和维护工作区、创建采集/发布作业、执行运行、查看运行结果与步骤详情。
- **业务分析师 / 数据使用者**：查看工作区与作业结果、查看数据资产、进入 NL2SQL 查询；不负责数据源和作业定义。
- **系统管理员**：进入系统设置（本批设计稿未覆盖）。
- **NL2SQL 使用者**：使用独立查询模块，不在本批工作区作业设计稿范围内。
- **编程 AI**：按本文和 HTML 设计稿实现页面，不自行扩展业务能力。

### 3.2 主路径

```text
数据源管理（20）
  └─ 工作区管理（21）
       ├─ 新建工作区（22）
       └─ 工作区详情（23）
            ├─ 采集作业列表（24）
            │    ├─ 新建采集作业/保存（28）
            │    ├─ 执行采集作业（29）
            │    └─ 作业详情/运行历史（26.1）
            │         └─ 运行步骤详情（26.2）
            └─ 发布作业列表（25）
                 ├─ 新建发布作业/保存（30）
                 ├─ 执行发布作业（31）
                 └─ 作业详情/运行历史（27.1）
                      └─ 运行步骤详情（27.2）

数据资产 / NL2SQL 查询：独立模块，不在这批设计稿中。
```

返回路径：

- 作业详情 / 执行页 → 对应作业列表（采集或发布）。
- 作业列表 → 工作区详情；返回列表时保留来源筛选和分页。
- 工作区详情 → 工作区管理或数据源详情。
- 详情页缺少或无权访问对象时，返回列表并显示提示，不显示空白页。

### 4.1 页面状态约定

- **列表页**：筛选、分页、空列表、加载失败、无匹配结果分别有独立状态；分页状态写入 query，可刷新恢复。
- **创建页（28/30）**：只保存作业和版本，不执行；保存成功后进入作业详情。采集新建页不检查产物就绪。发布新建页（30，实现按 32/33 设计稿）提供「发布校验」门控（2026-10-26 用户定案，推翻早前「保存页不禁用步骤」的约定）：步骤选择卡提供「发布校验」按钮（位于「全选」「清空」之前），调用只读 publish-check 接口；通过步骤名后显示绿色对号、勾选框可用，未通过显示红色叹号并在行内截断显示原因（悬停查看完整描述）、勾选框置灰，未校验时全部置灰。仅校验通过的步骤可勾选与编辑；「保存」要求已勾选全部通过校验的步骤，点击保存时复查所选步骤，未通过则报错不保存，未勾选的失败步骤不阻塞保存。Domain/Rel/Dim 编辑保存后自动复查校验状态。该校验为前端门控，后端创建作业接口不因此变更。发布新建页提供的 Domain/Rel/Dim 编辑写工作区配置文件，不属于作业保存内容（见「编辑入口」）。
- **执行页（29/31）**：进入时携带并展示 `revision_no` 和执行模式 `mode`。`default` 模式展示该版本完整步骤与默认参数，不允许临时修改；`custom` 模式允许选择非空子集（允许等于全集），并允许在版本允许的参数范围内临时修改，临时参数不写回作业。页内切换两种模式的入口是执行确认区的「修改步骤或参数」勾选框（默认不勾选即 `default`），勾选状态必须写回 `mode` query、不用组件局部状态，保证深链进入与刷新恢复行为一致。提交固定使用页面展示的 `revision_no`，不自动切换到最新版本。发布执行页四卡片（2026-10-26 定案）：作业信息 → 本次执行步骤 → 执行确认 → 运行结果（执行后显示）；执行确认卡右侧为「步骤校验」按钮、「修改步骤或参数」勾选框、「执行发布」按钮，校验通过前执行发布保持灰色；校验状态标记（绿对号/红叹号+截断原因）显示在本次执行步骤卡的步骤行（default/custom 均显示）；custom 勾选与 Domain/Rel/Dim 编辑仅限校验通过的步骤；执行页不再设独立发布预检卡（输入目录采集时间改在详情页发布预检卡查看）。正式请求仍由后端在创建运行前集中预检本次所选步骤，不通过返回 400 不创建运行。
- **作业详情（26.1/27.1）**：展示作业基本信息、当前版本、版本历史、运行历史；执行入口跳转 29/31。发布详情页（27.1，实现按 34 设计稿，2026-10-26 定案）自上而下为作业信息 → 配置版本 → 发布预检（按需展开）→ 运行历史：配置版本卡右下提供「发布校验」与「执行」（执行以当前查看版本发起，跳转 31；调度本期不提供），点击「发布校验」展开发布预检卡并可「重新校验」「收起」，预检结果不拦截执行（执行前的集中预检另做）；版本列表行提供「查看参数」弹窗（domain/dim_value/rel 三 tab 只读展示工作区配置文件，修改走编辑弹窗）；「创建新版本」在卡内联展开编辑器，步骤选择带发布校验门控（规则同新建发布页 32/33：通过校验的步骤才可勾选/编辑，保存前复查所选步骤，未勾选的失败步骤不阻塞）。运行历史每页 10 条、按执行时间倒序，展示 run_id、版本号、状态、执行时间；点击行打开运行详情抽屉（26.2/27.2 深链）。
- **步骤详情（26.2/27.2）**：展示本次运行中该步骤的状态、参数、耗时、输入清单和错误；采集步骤展示“读取的文件/生成的文件”，发布步骤展示“读取的文件/处理的下游目标”；不修改作业定义。
- **编辑入口**：Domain、Rel、Dim 的编辑弹窗（DomainConfigDialog/RelEditDialog/DimValueConfigDialog）在发布流程提供：新建发布作业页（30/32/33）步骤行、发布执行页（31）`custom` 模式步骤行、发布作业详情页（27.1）「创建新版本」编辑器步骤行（2026-10-24 定案恢复编辑入口；2026-10-26 定案详情页预检行与执行页预检行均不再提供编辑按钮——执行页预检卡已随四卡片改造移除，编辑集中在各步骤行）。采集新建页（28）仍只为 `domain` 提供 `--description` 默认输入弹窗。三个编辑按钮均需对应步骤通过「发布校验」后可用，编辑保存后自动复查校验状态。三个编辑写的是工作区配置文件（`db_domains.yaml`、rel 产物、`dim_tables.yaml`），不属于作业版本配置，也不是运行级临时参数：编辑后发起的运行按执行时点读取最新文件，文件对后续运行持续生效（与旧发布页行为一致）。执行页 `default` 模式按保存配置执行，步骤行不提供编辑入口。
- **Domain 临时输入**：采集执行页（29）的 `custom` 模式允许临时修改 Domain 的“首次生成输入”，不写回版本。该输入只在 YAML 文件不存在时参与首次生成；已有有效 YAML 时，重跑保留其中的 `database.description`，临时输入不会覆盖它；文件存在但损坏时明确报错，不按首次生成处理。修改当前描述须走工作区 Domain 文件编辑入口。

### 4.2 详情页动作

作业详情页统一使用以下动作：

- **按默认配置执行**：进入执行页 29/31，携带当前展示的 `revision_no` 和 `mode=default`；执行页展示该版本完整步骤与默认参数，不允许临时修改，确认后提交。
- **手工选择步骤执行**：进入执行页 29/31，携带当前展示的 `revision_no` 和 `mode=custom`；允许选择非空子集（可等于全集）并临时修改允许的参数，临时参数不保存回作业。
- **编辑基本信息**：只修改名称、说明，不产生新版本。
- **修改执行配置（保存新版本）**：修改步骤和默认参数，保存为新版本；入口在作业详情页，复用现有配置表单或弹窗，不新增整页路由。

执行页提交时使用页面展示的版本，不因作业刚保存了新版本而自动切换。若提交前发现版本已变化，提示刷新或重新确认，不静默改用最新版本。

本期**不提供**独立的自动失败重试、调度执行、运行取消、作业删除、版本删除或批量删除入口。设计稿中的“调度执行”“定时调度”“失败重试”属于后续能力或演示状态，首版不得实现为可用按钮；用户手工选择失败步骤发起一个新运行，是正常的手工执行能力，不属于自动重试机制。

### 4.3 发布执行页的采集时间

发布步骤所依赖输入目录的采集完成时间原约定在发布执行页（31）展示（设计稿 31 未体现，曾按防遗漏要求补充）；2026-10-26 四卡片定案后执行页不再设预检卡，采集时间改在发布作业详情页（27.1）的发布预检卡查看。

- 时间来自当前工作区对应目录顶层唯一的采集 marker，按 `Asia/Shanghai` 展示；不是文件修改时间、整次采集运行结束时间或发布时间。
- 一个发布步骤依赖多个目录时，按目录分别展示，不合并成一个“统一采集时间”。
- 不根据采集时间先后产生“过期”告警或禁用发布；是否重跑由用户判断。
- Domain、Rel、Dim 编辑保存成功后刷新预检，但不更新采集 marker 时间。
- marker 缺失、失败或无法读取时，展示预检返回的状态和原因，不显示推测时间。

### 4.4 运行创建后的页面状态与恢复

- 执行页提交成功后，在保留 `revision_no`、`mode` 等已有参数的前提下追加或更新 `run_id`，例如 `?revision_no=2&mode=custom&run_id=<uuid>`；页面按该 ID 查询并轮询，刷新后可以恢复同一运行。
- 恢复已有运行时，版本、实际步骤和有效参数以运行详情为准，不能用当前作业默认配置替代。
- 查询失败只重试查询，不自动重新提交执行；离开页面、关闭浏览器或停止轮询都不表示取消运行。
- 发布准入返回 `400` 时，展示具体步骤和原因，不生成运行结果卡片，也不写入运行历史。
- 运行历史中的某次运行可深链到同一运行详情/步骤详情，不通过“当前页第一条”猜测运行 ID。

### 8.2 编程 AI 必须遵守

1. **先读后写**：读本文、doc 6/6.1/6.2 和对应 API 类型，再读设计稿 HTML；不要只看 PNG 猜交互。
2. **只参考，不照抄**：HTML 是设计稿，不是生产代码；不要复制内联样式、绝对定位、固定尺寸或演示数据。
3. **复用壳子**：沿用 20–31 的侧边栏、页头、卡片、按钮、表格、状态徽章、空状态和步骤选择组件。
4. **复用 token**：颜色、字体、圆角、间距按 §5；不新增第二套品牌色或字体。
5. **使用 canonical 术语**：ID、步骤、状态按 §6；遇到旧设计稿名称按 §6.4 映射，不把 `profile`/`dict` 写进代码。
6. **保存与执行分离**：28/30 只保存；29/31 才执行。保存页不检查产物就绪，不因未就绪禁用步骤。
7. **执行只取子集**：执行页只允许当前版本步骤；步骤顺序由后端决定，前端排序只作提示。
8. **不实现未确认能力**：本期不做调度、取消、删除、作业启停、人工确认版本；设计稿中的相关按钮不接线。
9. **状态完整**：每个页面实现 loading、empty、error、disabled、partial_success、blocked、长文本和大表格状态；不要只实现成功态。
10. **不发明权限**：不根据设计稿中的 admin/zhangsan 等演示名实现登录或 RBAC；`created_by_user_id` 允许为空。
11. **未覆盖页面**：用现有组件组合，保持同样的页头、卡片、按钮和表格密度；实现假设写入代码注释或提交说明，不擅自增加业务字段或接口。
12. **响应式**：1440×937 只是设计画布；页面必须适配实际浏览器宽度，侧边栏和内容区不得写死像素导致横向滚动。

### 8.3 冲突处理

- 业务规则冲突：以 doc 6、6.1、6.2 的已确认约定为准；实际代码不一致时记录为实现差异，不反向覆盖文档。
- 路由/页面状态冲突：以本文为准。
- 视觉细节冲突：以 HTML 设计稿为准；HTML 与 PNG 不一致时以 HTML 为准。
- 设计稿没有覆盖：按 §8.2 组合实现，不新增页面风格；如涉及未定义业务规则，先提出待确认项，不静默假设。
