# 1. InsightWeave 服务启动指南

平台各服务的本地启动说明：工作目录、环境文件、启动命令与常见问题。

- 讨论与决策背景见 [0_项目整合讨论与共识.md](0_项目整合讨论与共识.md)。
- 目录现状：`frontend/`（统一 Vue 前端，2026-10-17 自 `metaweave/frontend/` 迁入）、`metaweave/`（元数据业务模块及 FastAPI）、`nl2sql/`（查询分析业务模块及 FastAPI）。

当前本地端口约定如下，分别在独立终端运行；后端先启动，再打开对应前端。端口由启动命令指定，并非 FastAPI 自动读取的项目默认值。

| 服务 | 工作目录（相对于平台根目录） | 本地地址 |
| --- | --- | --- |
| 统一 Vue 前端 | `frontend/` | `http://127.0.0.1:5173` |
| MetaWeave FastAPI | `metaweave/` | `http://127.0.0.1:8001` |
| NL2SQL FastAPI | `nl2sql/` | `http://127.0.0.1:8008` |
| NL2SQL Streamlit（迁移期可选） | `nl2sql/` | `http://127.0.0.1:8501` |

两个后端各使用本模块的 `.venv`。下面通过 `uv run --no-sync` 使用已安装环境，无需手动激活，也不会在每次启动时重新同步依赖；首次准备或依赖变化时先执行对应的 `uv sync`。环境文件由应用代码加载，无需先在 shell 中 `source .env`。

## 1. 前端（frontend/）

### 工作目录

```bash
/opt/projects/insightweave/frontend/
```

启动命令必须在本目录内执行：`vite.config.ts` 以 `process.cwd()` 为基准加载环境文件（`loadEnv(mode, process.cwd(), 'VITE_')`），在其他目录执行会读不到 `VITE_` 配置。

### 环境要求

- Node.js 与 npm（本机已验证：Node v22.22.2、npm 10.9.7）。

### 环境文件

`frontend/.env.development.local`（本机配置，已被 Git 忽略，不入库；模板见 `frontend/.env.example`）：

- `VITE_API_BASE_URL` —— 后端 FastAPI 地址，前端直连它访问 `/api/...` 接口。

格式要求（`vite.config.ts` 启动时经 `src/api/apiBaseUrl.ts` 强制校验，不合规直接启动失败）：

- 必须是完整的 `http://` 或 `https://` origin，例如 `http://127.0.0.1:8001`；
- 不能带 `/api` 路径，不能带末尾斜杠。

### 启动命令

```bash
cd /opt/projects/insightweave/frontend
npm ci        # 首次或依赖变动后执行；node_modules 不入库
npm run dev   # 开发服务器 → http://127.0.0.1:5173/
```

- 绑定 `127.0.0.1`，端口 `5173`，`strictPort: true`：端口被占用时启动失败，不会自动换端口。
- 页面数据依赖 MetaWeave 后端（见 §2），后端未启动时页面可打开但接口请求失败。

### 其他脚本

| 命令 | 作用 |
| --- | --- |
| `npm run typecheck` | `vue-tsc --noEmit` 类型检查 |
| `npm run build` | 类型检查 + 生产构建，产物写 `dist/` |

注意：production 构建不加载 `.env.development.local`，需显式提供环境变量（该地址仅本机验证用，非正式部署地址）：

```bash
VITE_API_BASE_URL=http://127.0.0.1:8001 npm run build
```

### 常见问题

- **启动报「缺少 VITE_API_BASE_URL」**：环境文件缺失或命令不在 `frontend/` 目录内执行；检查 `.env.development.local` 是否存在且格式合规。
- **启动报端口占用**：5173 已有实例在跑（strictPort 不换端口）。用 `ss -tlnp 'sport = :5173'` 检查，确认是自己的实例后在其终端按 `Ctrl+C` 停止，再重新启动。
- **页面打开但无数据**：后端未启动或 `VITE_API_BASE_URL` 指向错误；确认后端在 8001 端口监听且 CORS 已放行前端地址（后端 `metaweave/.env` 的 `PLATFORM_CORS_ORIGINS`）。

## 2. MetaWeave 后端（metaweave/）

### 环境与配置

- Python 3.12+、uv，独立虚拟环境为 `metaweave/.venv/`。
- FastAPI 和 Uvicorn 位于 `pyproject.toml` 的 `platform` 可选依赖中，仅安装基础依赖不足以启动 Web 后端。
- 本地环境文件为 `metaweave/.env`，应用按模块根路径加载；模板见 [metaweave/.env.example](../metaweave/.env.example)。
- 平台库必填变量：`PLATFORM_DB_HOST`、`PLATFORM_DB_USER`、`PLATFORM_DB_PASSWORD`；`PLATFORM_DB_PORT` 默认 `5432`，`PLATFORM_DB_NAME` 默认 `metaweave`，`PLATFORM_DB_SSLMODE` 按实际连接要求配置。
- `SOURCE_CREDENTIAL_KEY` 用于业务数据源密码加解密；沿用现有密钥，才能读取原平台记录中的加密密码。
- `PLATFORM_CORS_ORIGINS` 应包含实际前端 origin，例如 `http://127.0.0.1:5173`，不能带末尾斜杠；多个 origin 用逗号分隔。不要将后端地址误填为前端 origin。
- 主业务配置为 `configs/metadata_config.yaml`，日志配置为 `configs/logging.yaml`；采集、发布还需要对应源库、知识库及模型配置可用。

首次准备或依赖变化后执行（已安装完毕可跳过）：

```bash
cd /opt/projects/insightweave/metaweave
uv sync --python 3.12 --locked --all-extras
```

### 启动命令

在独立终端前台运行：

```bash
cd /opt/projects/insightweave/metaweave
uv run --no-sync uvicorn backend.api.logged_app:create_logged_app \
  --factory --no-access-log --host 127.0.0.1 --port 8001
```

- `create_logged_app` 是应用工厂，必须带 `--factory`；它初始化 API 日志后再构造 FastAPI 应用。
- `--no-access-log` 关闭 Uvicorn 原生访问日志，避免与项目请求摘要重复；项目日志仍会写入。
- 开发时需要自动重载，可在命令末尾加 `--reload`；普通运行可不加。
- 当前前端 `VITE_API_BASE_URL` 应为 `http://127.0.0.1:8001`，现有接口前缀为 `/api/...`。

### 检查与日志

在另一终端执行只读检查：

```bash
# OpenAPI 是否可访问（不替代平台库连通性检查）
curl --fail --silent --show-error --output /dev/null \
  --write-out 'OpenAPI HTTP %{http_code}\n' http://127.0.0.1:8001/openapi.json

# 平台库数据列表查询（不输出数据源详情）
curl --fail --silent --show-error --output /dev/null \
  --write-out 'Data sources HTTP %{http_code}\n' http://127.0.0.1:8001/api/data-sources
```

接口文档：`http://127.0.0.1:8001/docs`。当前未定义独立 `/health` 路由，不要以该路径判断 MetaWeave 服务是否正常。

日志位于 `metaweave/logs/api.log`（请求摘要）和 `metaweave/logs/backend/*.log`（模块业务日志）。只使用 `backend.api.main:create_app` 不会自动获得上述项目文件日志；也不要把项目日志 YAML 直接传给 Uvicorn 的 `--log-config`。

### 常见问题

- **找不到 uvicorn、SQLAlchemy 等依赖**：确认在 `metaweave/` 执行，并已安装 `platform` 依赖；按上面的锁定安装命令补齐。
- **缺少平台库变量、CORS origin 非法**：检查 `metaweave/.env`；若 shell 已设置同名变量，应用不会用 `.env` 覆盖它。
- **OpenAPI 可访问，列表接口返回 503**：服务已启动，但平台库连接或表结构可能未就绪；查看 API 与业务日志。应用启动不会自动创建平台库和平台业务表。
- **列表正常，采集或发布失败**：继续检查相应源库、模型服务、Milvus、Neo4j 和文件产物，列表成功不代表全部依赖正常。

## 3. NL2SQL 后端（nl2sql/）

### 环境与配置

- Python 3.12+、uv，独立虚拟环境为 `nl2sql/.venv/`。
- FastAPI、Uvicorn 属于基础依赖；Streamlit 和 requests 位于 `web` 可选依赖，保留用于迁移期功能对照。
- 本地环境文件为 `nl2sql/.env`，默认配置由 `src/services/config_loader.py` 加载；模板见 [nl2sql/.env.example](../nl2sql/.env.example)。
- 系统配置：`src/configs/config.yaml`；日志配置：`src/configs/logging.yaml`。应在 `nl2sql/` 启动，避免相对日志路径写到其他目录。
- 按当前配置准备业务 PostgreSQL（`DB_*`）、Neo4j（`NEO4J_*`）、Milvus（`MILVUS_*`）和实际选用的 LLM/Embedding 凭据。
- 当前开启 LangGraph 持久化且使用独立连接参数，需配置 `LANGGRAPH_DB_HOST`、`LANGGRAPH_DB_PORT`、`LANGGRAPH_DB_NAME`、`LANGGRAPH_DB_USER`、`LANGGRAPH_DB_PASSWORD`；不要误认为只配置业务库 `DB_*` 就能满足对话持久化要求。
- Web API（/api/v2）运行参数（均可用环境变量覆盖，缺省值如下）：
  - `NL2SQL_MAX_CONCURRENT_RUNS=2`：全局在途查询名额，满额时新提交返回 429。
  - `NL2SQL_QUERY_RATE_LIMIT_PER_MINUTE=20`：guest 共享的提交频率限制（含被拒绝的重复提交），超限返回 429 并附 `Retry-After`。
  - `NL2SQL_CORS_ORIGINS=http://127.0.0.1:5173`：本机 Origin 白名单；前端使用 `localhost` 或其他端口时必须显式配置，不沿用通配。
  - `NL2SQL_ALLOWED_HOSTS=127.0.0.1,localhost`：允许的 Host。

首次准备或依赖变化后执行（已安装完毕可跳过）：

```bash
cd /opt/projects/insightweave/nl2sql
uv sync --python 3.12 --locked --all-extras
```

### 启动命令

在独立终端前台运行：

```bash
cd /opt/projects/insightweave/nl2sql
uv run --no-sync uvicorn src.api.main:app --host 127.0.0.1 --port 8008
```

- `src.api.main:app` 是已创建的 FastAPI 应用实例，**不加 `--factory`**。
- 开发时需要自动重载，可在命令末尾加 `--reload`。
- 当前应用只挂载 `/api/v2` Web 链路（db_deepagent 执行链），不再挂载旧 `/api/v1` query/history 路由；旧路由文件保留供脚本用途。
- 启动生命周期仅初始化日志与 Web 运行时（执行器/限流参数）；平台 Store 惰性构建，`/api/v2/health` 不触发任何数据库连接。首次查询或会话读取时才连接平台 PostgreSQL（`LANGGRAPH_DB_*` 所指库），相关表需已由 maintenance 初始化。

### 检查与日志

```bash
curl --fail --silent --show-error http://127.0.0.1:8008/api/v2/health
```

预期返回统一封装 `{"code":200,"message":"success","data":{"status":"ok"},"trace_id":"…"}`。该接口只表明 API 已响应，不检查 LLM、知识库或业务库是否可用；按源可用性检查用 `GET /api/v2/sources/{source_id}/readiness`。

接口文档：`http://127.0.0.1:8008/docs`。当前接口如下：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/v2/health` | API 健康检查（不连库） |
| GET | `/api/v2/sources/{source_id}/readiness` | 按源完整就绪检查（登记/业务库/知识成套/版本） |
| POST | `/api/v2/sessions` | 创建 Web 会话（固定 guest） |
| GET | `/api/v2/sessions` | 会话列表（`source_id` 过滤、分页） |
| GET | `/api/v2/sessions/{session_id}` | 会话详情 |
| GET | `/api/v2/sessions/{session_id}/turns` | 历史轮次，仅 question/answer（D3） |
| POST | `/api/v2/sessions/{session_id}/query` | 同步执行一轮问答（D4）；可能执行 SQL，不作只读启动检查 |
| GET | `/api/v2/sessions/{session_id}/results/{result_ref}` | 当前轮结果表格分页（v2 cell 信封） |

所有响应使用 `{code, message, data, trace_id}` 统一封装，`code` 为 HTTP 状态数字值；查询终态（partial/failed 等）返回 HTTP 200 并在 `data.status`/`data.error_code` 表达，请求拒绝使用稳定 `data.error_code` 与对应 HTTP 状态（429 附 `Retry-After`）。`GET readiness` 在源兼容且完成检查时即使 `ready=false`（缺知识/业务库不匹配）也返回 HTTP 200、检查项在 `data.checks`；仅源不存在/停用（404/409）、配置不兼容（422）、依赖读取失败（503）按错误封装返回。本机 Origin/Host 不在白名单时分别返回 403/400，写接口非 JSON 返回 415。

当前代码日志写入 `nl2sql/logs/api.log` 和 `nl2sql/logs/nl2sql.log`，以 `src/configs/logging.yaml` 为准。旧文档提及的 `fastapi.log`、`sql_subgraph.log` 不作为当前日志位置。

### Vue 查询页面（frontend/）

统一 Vue 应用已接入 NL2SQL 查询页（路由 `/query` 与 `/query/:sessionId`，侧栏“新建查询”入口）。前端使用独立的后端地址变量：

```bash
VITE_NL2SQL_API_BASE_URL=http://127.0.0.1:8008
```

该变量与 MetaWeave 的 `VITE_API_BASE_URL` 一样只接受 origin，`/api/v2` 由客户端添加；两个变量互不回退。NL2SQL 未配置时 MetaWeave 页面不受影响，仅查询页提示未配置。开发期在 `frontend/` 执行 `npm run dev`（默认 `http://127.0.0.1:5173`，与后端默认 CORS 白名单一致）；使用其他地址时同步调整 `NL2SQL_CORS_ORIGINS`。

### 迁移期可选：启动 Streamlit

统一 Vue 应用已提供 `/query` 查询页（见上节）；Streamlit 入口仅作迁移期功能对照保留，Vue 验收通过后将按设计文档 P5 单独清理。需要对照时，在另一个终端执行：

```bash
cd /opt/projects/insightweave/nl2sql
API_BASE_URL=http://127.0.0.1:8008/api/v1 \
  uv run --no-sync streamlit run frontend/app.py \
  --server.address 127.0.0.1 --server.port 8501
```

浏览器访问 `http://127.0.0.1:8501`。这里的 `frontend/app.py` 是 **NL2SQL 模块内部的 Streamlit 入口**，与平台根目录的 Vue `frontend/` 不同。

Streamlit 的 `API_BASE_URL` 包含 `/api/v1`，而 Vue 的 `VITE_API_BASE_URL` 只接受 origin，二者不能直接互换。命令中显式传入地址以避免本地 `.env` 中的旧地址覆盖预期连接；修改 NL2SQL 后端端口时同步调整该变量。

### 常见问题

- **找不到 src 包或配置文件**：确认当前工作目录是 `insightweave/nl2sql/`，且使用该模块环境。
- **找不到 streamlit**：补齐 `web` 可选依赖，或使用上面的 `--all-extras` 锁定安装命令。
- **health 正常，查询或历史失败**：检查对应数据库、知识库、模型凭据和业务响应 `code`；用 `readiness` 接口定位具体未通过项（登记/业务库/知识成套/Embedding）。
- **端口和旧 README 不一致**：本指南统一约定 NL2SQL 使用 `8008`；端口由 `--port` 决定，不会从 `config.yaml` 的 `api.max_recent_sessions` 设置推导。
- **Vue 查询页提示未配置**：检查 `frontend/` 的 `.env.local` 或 `.env.development.local` 是否包含 `VITE_NL2SQL_API_BASE_URL`（仅 origin，不带 `/api/v2`）。

## 4. 停止服务与验证范围

各前台服务在自己的终端按 `Ctrl+C` 停止；NL2SQL 会在正常退出时关闭历史读写线程池及持久化连接。端口被占用时先核对具体进程，不按模糊名称批量结束服务。

本指南根据当前启动入口、配置加载、依赖声明及日志代码核对编写（2026-10-17）。本次文档补充未启动服务、未执行数据库初始化或查询；实际运行结果应以启动日志、接口检查及浏览器验证为准。
