# 结构与维度值检索

## 适用场景

找表找列、规范化维度值、多表关联、补查桥接表、结构冲突和 SQL 校验后的检索修正。

## 检索对象与工具映射

| 需求或线索 | 动作 | 返回信息如何使用 |
| --- | --- | --- |
| 整体业务意图、指标词 | `search_schema(query=..., kinds=["tables", "columns"])` | 形成候选事实表、金额／时间／标识字段；不凭相似度直接认定指标口径 |
| 维度名称（如“服务区”） | 必要时单独 `search_schema(query="服务区", kinds=["columns"])` | 列命中的父表标识加入候选，并用 inspect_tables 核对 |
| 维度值候选（如“杭州湾”） | `search_schema(query=..., kinds=["dim_values"], value_texts=["杭州湾"])` | 核对命中的维度表、列、规范值和 dim_evidence_id；不能只取值而丢掉列绑定 |
| 已有候选表 | `inspect_tables(table_ids=...)` | 核对真实列、类型、表类别与时间提示；卡片与实时结构冲突时以实时结构为准 |
| 多表查询需要关联 | `plan_joins(base_table=..., target_tables=...)` | 使用返回的 JOIN 条件与路径，补查 bridge_tables；检查基表粒度和关联基数是否会重复累计指标 |
| 缺少可参考的 SQL 写法 | 按需 `search_schema(query=..., kinds=["sql_examples"])` | 案例仅作参考，重新核对当前表结构、时间、对象和口径，并重新校验 SQL |

`search_schema` 对一个 query 生成的向量用于该调用中的表、列和案例检索；每个 value_texts 单独检索维度值。整句检索召回不足时，把“指标词”“维度名称”分别作为 query 补查，不把所有名词都放入 value_texts。列命中所属表的补查由你根据返回发起。

## 维度值与失败分支

- 达到配置阈值的命中是候选证据，不等于已消除语义歧义；仍须确认归属表与列符合用户所指对象。多个候选可能代表不同实体时，补查或澄清，不能只取最高分。
- 未命中值不产生证据。先确认候选列，再用 `probe_dimension_values(mode="exact")` 查证；需要查找包含原文的规范写法时用 contains；低基数状态／渠道值可用 distinct 确认。探针只能使用该受控接口。
- contains 返回多个真实值时，不能默认全部合并成用户指定对象；依据已有业务说明消歧，仍不明确则请用户选择。返回截断时不能声称已列出全部候选。
- 检索阈值由服务端配置，工具不接受 min_score；不通过降低阈值、原文透传、主查询中擅自改为模糊匹配或替换成相似实体来绕过未命中问题。
- 空值检查：已确认文本列的 `= ''`／`<> ''`，或任意合法列的 IS NULL／IS NOT NULL，无需先检索空字符串；NULL、空字符串和空白字符串分别处理，不得把 IS NOT NULL 当成排除空字符串。
- 检索成功但无命中、后端失败、Neo4j 无路径和表不在图分别处理：后端失败不解释为业务不存在；无路径不编造 JOIN 键，也不做无依据的笛卡尔积。
- 多表关联可能放大行数时，根据确认的键、粒度和基数选择先聚合、存在性过滤或其他正确写法，不能直接对重复后的金额求和；无法确认关联口径时报告限制或澄清。

## 完成条件

所选表列已通过 inspect_tables 核对；所有需要的字符串过滤值都有绑定表列的证据（空值检查例外除外）；需要的 JOIN 路径和桥接表已核对；指标粒度与关联方式一致。证据足够即转入 SQL 编写，不为凑齐检索类型继续调用工具。
