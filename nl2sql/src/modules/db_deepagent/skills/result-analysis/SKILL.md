# 结果读取与回答组织

## 适用场景

SQL 执行后查看明细或汇总、比较多个结果、计算衍生指标，以及组织最终答案。

## 截断两义性

- `preview_truncated=true`：只是返回包里的预览行不完整，完整已保存行数以 saved_row_count 为准。
- `source_truncated=true`：数据库结果超过保存上限，未保存部分无法通过翻页取得，**已保存行不能当作总体**。涉及总额、占比、排名等总体结论时如实说明覆盖范围（“已保存前 N 行”），不用样本冒充总体，也不据样本推断完整总体。

## 比较与衍生指标

- 比较前核对时间、单位、过滤、粒度与分母是否可比。
- 环比基期为零时说明无法按通常公式计算，不编造百分比。
- 排名并列规则、舍入与单位在答案中交代。
- 引用历史结果说明上一问的结论、口径与截断情况时，先经 `reuse_evidence` 登记为本运行证据，再在 findings 中引用返回的新 evidence_id，并在回答中写明原结果生成时间与数据源。

## 证据与表述

- 每条数据结论都引用当前接口允许的执行／分析 evidence_id（execute_sql 返回过、或经 reuse_evidence 登记的）。
- 探针用于确认值，不能作为最终业务结论的执行证据；表卡片、历史 SQL 和模型推断同样不能证明销售额等数值。
- 空结果、执行失败和缺少数据分别表述，不能统一说成“销售额为 0”。
- 仅需一个汇总值且查询已返回完整、可解释的结果时，直接组织答案，不强制追加计算调用。

## 完成条件

answer 面向用户简洁完整地回答业务问题，默认不展开技术口径清单、不展示内部表字段、任务号或证据编号；详细统计口径（表名、字段、聚合方法、时间边界）写入 metric_definitions，findings 仍按既有规则完整提交并附 evidence_id；截断或未完成限制若影响答案含义，用简短业务语言在 answer 中说明。用户明确询问口径或计算方法时可在 answer 中解释。
