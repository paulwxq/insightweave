⚡ 快速路径 (Fast Path)

Router 判定一条 SQL 可以完成的问题进入此路径。

1️⃣ simple_planner：创建单个子查询
2️⃣ sql_gen：调用 SQL 生成子图
3️⃣ 生成成功时由 sql_exec 执行 SQL；失败时跳过执行
4️⃣ 两种情况都进入共享的 summarizer
实现说明：
  • simple_planner 不调用 LLM，直接使用原始问题创建子查询
  • sql_exec 和 summarizer 与复杂路径共用

🧠 复杂路径 (Complex Path)

Router 判定需要多条 SQL 或依赖前一步结果的问题进入此路径。

1️⃣ planner：规划子查询；失败时直接进入 summarizer
2️⃣ inject_params：注入已完成子查询的结果
3️⃣ sql_gen_batch：逐个调用 SQL 生成子图
4️⃣ 共享的 sql_exec：执行待处理 SQL，可按配置并发
5️⃣ check_completion：继续下一批，或进入 summarizer
实现说明：
  • 批次内 SQL 生成按子查询顺序调用子图
  • sql_exec 只有在待执行 SQL 多于一条且配置允许时才并发
  • 所有子查询均完成或失败后结束循环

💡 问题分类示例

⚡ Simple - 走快速路径

单个独立查询

"广州服务区的销售额是多少？"

单表聚合

"2024年总销售额是多少？"

简单筛选

"销售额超过100万的服务区有哪些？"

简单对比（单SQL）

"北京和上海服务区的销售额对比"

🧠 Complex - 走复杂路径

依赖前一步查询结果

"先找出昨日客流最高的服务区，再用查到的服务区编号查询其库存。"

多个独立查询

"分别查询广州服务区的销售额和北京服务区的车流量。"

🔧 Router 与共享节点

Router 通常调用配置的 LLM 判断 simple 或 complex；调试配置 routing.force_complexity 可以覆盖判断。分类依据是能否用一条 SQL 完成，而不是问题中提及的维度数量。实际路由代码见 src/modules/nl2sql_father/nodes/router.py 和 src/modules/nl2sql_father/graph.py。

sql_exec 在两条路径中都是同一个节点。Fast Path 执行后直接进入 summarizer；Complex Path 执行后先进入 check_completion。summarizer 统一处理正常结果与失败说明，是否调用 LLM 由结果及配置决定。

⚡ Simple Planner 节点

根据原始问题创建单个子查询，为 Fast Path 准备参数。

核心特点
  • 纯函数，不调用 LLM
  • 创建单个子查询
  • 设置 current_sub_query_id
后续流向
  • 将当前子查询交给 sql_gen
  • SQL 生成成功后进入 sql_exec
  • SQL 生成失败后进入 summarizer
