# 维度值向量检索与无效提示词配置清理方案

> 状态：设计稿，待审核；本轮只编写方案，不修改运行代码。以下以当前代码为准。`dim_value_top_k` 是每次 `role="value"` 文本检索的候选上限，不是整个请求或 prompt 的总条数上限。

## 一、目标与范围

将 `schema_retrieval.dim_index_topk` 改名为 `dim_value_top_k`，将 `schema_retrieval.dim_value_min_score` 改名为 `dim_value_similarity_threshold`。正式 YAML 沿用现值 `3` 和 `0.75`，新键在代码中缺项时也默认这两个值，使缺键行为与当前正式 YAML 的业务门槛一致。Milvus 对 `dim_value_embeddings` 的每次搜索直接使用 `limit=dim_value_top_k`，然后按原始 COSINE 相似度保留分数不低于阈值的候选；不为低分候选补位，结果允许少于 K，甚至为零。Milvus 路径采用与当前历史 SQL 案例检索相同的“先限制候选数，再过滤相似度”方式。

目标还包括让**已通过该阈值的维度值命中进入 prompt 的“维度值匹配”段**。目前 formatter 另有固定 `0.5` 显示阈值；若仅修改检索适配器，未来把 YAML 阈值调至 `0.5` 以下时，合格命中仍会在 prompt 处消失。因此本方案同步去除这道重复的显示分数过滤，保留去重、格式化和空结果占位行为。

本期删除 YAML 中未被代码读取的 `sql_generation.prompt.max_dim_value_matches` 与 `max_table_cards`，不增加新的 prompt 总数上限；`dim_value_top_k` 仍是每次检索的候选上限。本期不改表/列 Schema、历史 SQL 的检索参数及实现，也不改变维度值命中的字段映射、候选表补入或 JOIN 逻辑。

同时删除未被读取、且不能限制实际 JOIN 关系数量的 `sql_generation.prompt.max_join_plans`。JOIN formatter 中写死的 `join_plans[:3]` 只截取**计划列表**，当前检索器最多生成一个计划，故这道展示截取在现有运行链路中不起作用；本方案建议一并移除它，直接展示已有计划。此项不限制单个计划的 JOIN 边数。

## 三、目标契约与参数边界

```yaml
schema_retrieval:
  # dim_value_embeddings：每个非空 role="value" 文本向量检索最多返回的候选数；Milvus limit 直接使用此值，阈值过滤后可能少于该值
  dim_value_top_k: 3
  # dim_value_embeddings：上述候选返回后须达到的最低 COSINE 相似度；达标且去重后写入 LLM prompt 的“维度值匹配”段
  dim_value_similarity_threshold: 0.75
```

新键只控制维度值检索，不作用于 `table_schema_embeddings` 或 `sql_example_embeddings`。`K=dim_value_top_k`、`T=dim_value_similarity_threshold` 时，**每个**非空 `role="value"` 文本执行：向 Milvus 请求最多 K 条候选 → Python 保留原始分数 `>= T` 的命中。单次返回满足 `0 ≤ 合格条数 ≤ 实际候选条数 ≤ K`，没有过滤后补足 K 条的步骤。多个 value 文本分别搜索，合并并去重后进入 prompt；因此**整个请求的维度值条数可以大于 K**，也可以因去重少于各次合格条数之和。不能把 K 误写成 prompt 全局上限。

去重仍可能合并重复业务值。去重后，formatter 不再按固定 `0.5` 分数过滤；这样单个保留下来的命中不会因另一个独立阈值从“维度值匹配”段消失。维度值可补入候选表，但表卡片还要经过现有的候选表归并、精确查询等步骤；不能据此保证每条命中的表都会在 prompt 中出现卡片。

### JOIN 计划与 JOIN 关系的数量边界

当前 `SchemaRetriever._retrieve_join_plans()` 仅遍历 `base_tables[:1]`，因此最多构造一个计划；一个计划可以有多条 `edges`，每条 edge 才对应一条 JOIN 关系。formatter 的 `join_plans[:3]` 只作用于计划列表，对这个计划内部的 `edges` 没有截断作用。以“一个计划含六条 edges”为例，当前 prompt 会展示这个计划及其六条 JOIN 关系；把 `max_join_plans` 从 `3` 改为 `5` 仍然如此。此前建议接入该参数并改成 `5`，不能实现“最多五条 JOIN 关系”，现予撤回。

本期从 YAML 删除 `max_join_plans`，并把 formatter 中的 `join_plans[:3]` 改为直接遍历 `join_plans`，不再保留一个与真实数量目标无关的写死上限。当前正常链路的 prompt 输出不变。若将来需要限制进入 prompt 的 JOIN 关系数，应基于 `edges` 及目标表的路径完整性单独设计，不能直接截取前五条 edge，否则可能留下无法连接目标表的残缺计划。

`max_table_cards` 同样不生效，本期从 YAML 删除，表卡片 formatter 继续遍历上游实际取到的全部卡片。不能仅对卡片字典做“前十张”截取：JOIN 计划可能引用被截掉的表，届时 prompt 有 JOIN 条件却没有对应字段说明。若以后需要控制表卡片数量，应连同候选表与 JOIN 路径一起设计一致的选择规则。

通用适配器接口 `search_dim_values(top_k, min_score)` 及 PgVector 实现本期保持原名，避免把 YAML 键改名误扩散为接口破坏。新 YAML 阈值作为 `min_score` 实参传入。仓库当前 `src/configs/config.yaml` 配置为 `vector_database.active: milvus`；PgVector 的 `search_dim_values()` 仍会在 `min_score > 0` 时向 PG 请求 `2×top_k` 条，再按分数过滤并截取至 `top_k`，本期不改其内部检索算法。**因此“两步筛选”准确描述的是本期改造的 Milvus 路径，不能宣称 PgVector 内部也已同步改成两步。** 移除 prompt formatter 的固定显示阈值也会作用于 PgVector 返回值，但 PgVector 适配器自身仍按传入的 `min_score` 过滤。

Milvus 使用的 `schema_retrieval.milvus_search_params.metric_type`、`params.ef` 仍影响向量度量和近似搜索候选，不是第三个业务数量/相似度门槛。现有 `ef: 100` 大于初始 K；YAML 中已有“应 >= 上述各 top_k”注释，本次只需确认它也涵盖新的维度值 K。

## 五、验收标准

1. 从正式 YAML 加载 `schema_retrieval`，确认 `dim_value_top_k=3`、`dim_value_similarity_threshold=0.75`，旧键不存在。使用合成的非默认值配置，通过真实构造函数与 mock 客户端确认两项新键接线正确；再用缺少这两个新键的合成配置确认代码回退到 `3`、`0.75`，不会回退到旧的 `5`、`0.0`。只给测试对象直接赋值无法证明配置读取正确。
