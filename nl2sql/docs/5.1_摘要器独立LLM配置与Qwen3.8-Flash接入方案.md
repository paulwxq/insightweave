# 摘要器独立 LLM 配置与 Qwen3.8-Flash 接入方案

> 状态：**已实施（2026-11-10）**，实施记录见文末。以下为实施前设计，保留原文。

**Goal：** 主 Agent 继续使用 `qwen3_8_max`，摘要器独立使用 `qwen3_8_flash`，分别配置生成参数和请求超时。

**Architecture：** 在两个现有 YAML 中分别注册模型和选择摘要 profile；新增 `build_summarizer_model(cfg)`，复用 `get_llm()` 创建摘要模型，再传给已接入的 SDK `summarizer=`。

**Tech Stack：** Python 3.12、DeepAgents 0.7.34、LangChain 1.4.9、Pydantic、pytest；不升级依赖。

**Spec：** [doc 5：已完成的 summarizer 接线](5_独立摘要器接入修改方案.md)。本次在其基础上增加独立模型配置。

**实施前提：** 项目尚未上线，代码、配置和测试直接切换到新设计。不支持旧摘要配置，不保留旧模型副本路径，不做历史数据或检查点迁移。

## 1. 模型与配置决策

| 项目 | 本次设置 |
| --- | --- |
| 主模型 profile / API 模型 ID | `qwen3_8_max` / `qwen3.8-max`，保持现状 |
| 摘要 profile / API 模型 ID | 新增 `qwen3_8_flash` / `qwen3.8-flash` |
| provider | 复用 `dashscope_openai`，通过现有 ChatOpenAI 兼容路径调用 |
| 地址 / 密钥 | 复用 `llm_providers.dashscope_openai` 与 `DASHSCOPE_API_KEY`，不增加密钥或 provider |
| 摘要生成初始参数 | `temperature: 0`、`max_tokens: 8192`、`enable_thinking: false` |
| 摘要请求超时 | 独立配置，初始 `120` 秒 |
| 摘要触发 / 近期保留预算 | 保持 `96000 / 24000` tokens |
| 待摘要历史额外裁剪 | 保持 `trim_tokens_to_summarize: null` |

官方模型 ID 为 `qwen3.8-flash`，上下文为 1,000,000 tokens；非思考模式最大输入为 991,808 tokens。1M 是摘要模型的能力，不作为扩大主 Agent 上下文或调整触发阈值的依据。[阿里云模型规格，2026-11-10 核对](https://help.aliyun.com/zh/model-studio/qwen3-8-flash)

`max_tokens: 8192` 是本项目为摘要设置的初始输出上限，不是模型上下文或输入上限。关闭思考模式用于控制摘要耗时和输出开销，是否降低实际费用以运行记录为准。

摘要请求超时暂取 `120` 秒：目前没有 Flash 在本项目实际摘要输入规模下的耗时记录，先不据模型名称或关闭思考模式推定 `60` 秒足够。实施后记录摘要调用耗时、输入/输出 tokens 和超时情况，再决定是否缩短；低阈值冒烟测试的耗时不能代表生产触发阈值下的耗时。

### 3.2 摘要模型选择：`src/modules/db_deepagent/config/db_deepagent.yaml`

将现有 `summarization` 段扩展为：

```yaml

  llm_profile: qwen3_8_flash
  overrides: {}                      # 仅覆盖摘要参数，不继承 model.overrides
```

## 4. 代码修改

### 4.1 `config.py`：接收新配置并检查引用

在现有 `SummarizationConfig` 增加前三个字段：

```python
class SummarizationConfig(_StrictModel):
    llm_profile: str = Field(min_length=1)
    overrides: dict[str, Any] = Field(default_factory=dict)
    request_timeout_seconds: float = Field(gt=0)
    summary_trigger_tokens: int = Field(gt=0)
    recent_context_tokens: int = Field(gt=0)
    trim_tokens_to_summarize: int | None = Field(default=None, gt=0)
```

在 `_check_summarization()` 原阈值检查后加入：

```python
profiles = get_config().get("llm_profiles", {})
if cfg.summarization.llm_profile not in profiles:
    raise DbAgentConfigError(
        "summarization.llm_profile: 引用的 LLM profile 不存在；"
        "请在 src/configs/config.yaml 的 llm_profiles 中注册"
    )
```

`llm_profile` 和请求超时为必填项；配置遗漏或 profile 不存在时明确失败。provider、模型 ID、密钥和参数合法性继续由 `get_llm()` 校验，配置检查阶段不创建模型。摘要配置不进入只针对 SQL validation 的 `validation_fingerprint`。

profile 存在后，若模型构造失败，按 `get_llm()` 或模型客户端的原始错误排查该 profile、对应 `llm_providers` 和 `.env`；密钥是否有效及服务端是否支持模型/参数，最终需真实请求验证。不将这些后续排查说明塞进“profile 不存在”的错误中，也不增加重复校验。

### 4.2 `agent.py`：新增独立摘要模型构造器

放在现有 `build_model()` 后，复用同一模型工厂及超时处理方式：

```python
def build_summarizer_model(cfg: DbAgentConfig) -> BaseChatModel:
    """按摘要专用 profile 创建模型并标记调用用途。"""
    from src.services.config_loader import get_config
    from src.services.llm_factory import get_llm

    s = cfg.summarization
    profile = get_config().get("llm_profiles", {}).get(s.llm_profile) or {}
    provider = profile.get("provider", "")
    overrides = dict(s.overrides)
    if provider != "dashscope":
        overrides.setdefault("timeout", s.request_timeout_seconds)

    summary_model = get_llm(s.llm_profile, **overrides).llm
    if provider == "dashscope":
        apply_request_timeout(summary_model, s.request_timeout_seconds)

    summary_model.metadata = {
        **(summary_model.metadata or {}),
        "dbda_call_kind": "summarization",
    }
    return summary_model
```

本次 Flash 走 `dashscope_openai`，超时在模型构造前传入，不能只在构造后修改 `request_timeout` 字段。优先级沿用主模型的规则：显式 `summarization.overrides.timeout` 高于 `summarization.request_timeout_seconds`，后者覆盖 profile 中的超时默认值。

摘要模型不调用主 Agent 的 `register_and_verify_harness_profile()`：它只负责写摘要，不负责工具调用或主图装配；主 Agent 的 Harness 注册保持原逻辑。
