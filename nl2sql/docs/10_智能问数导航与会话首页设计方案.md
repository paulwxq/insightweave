# 智能问数导航与会话首页设计方案

> 状态：代码已按正文实现，验收清单尚未勾选，等待审核。2026-11-11 的验证记录见文末；设计规则、边界和验收要求仍以正文为准。
> 实施时按本文任务逐步执行；Agent 委派沿用用户指定的 Orca 协作方式，不自行创建额外 Agent。

**目的（Goal）：** 将 NL2SQL 融入统一 Vue 前端，建立独立的“智能问数”入口和会话首页，让 guest 用户能够查看、筛选、搜索历史对话并快速新建查询。

**实现方式（Architecture）：** 保持“全局导航＋主内容区”的两列布局；历史记录从全局侧栏移入智能问数首页。查询页通过历史对话框切换会话，首页与对话框复用列表能力；后端在现有 guest 会话列表接口上补充标题搜索和真实数量统计。

**技术范围（Tech Stack）：** 现有 Vue 3、Vue Router、TypeScript、FastAPI 与 PostgreSQL Store；不升级依赖，不引入新的状态管理或搜索框架。

**依据（Spec）：** 本次对话中确认的两列布局、智能问数子菜单、guest 会话首页、数据库筛选、标题搜索和最后更新时间倒序要求。

## 1. 范围与约束

- 当前未启用认证，展示共享 `guest` 的 Web 会话；不区分不同浏览器使用者，不新增用户认证功能。
- 会话可以属于不同数据库，默认显示全部数据库的会话。
- 项目未上线，不增加旧路由兼容分支或历史数据迁移。
- 首期只做标题搜索，不做问答全文搜索、收藏、标签、文件夹、批量操作或新的分析项目体系。
- 不改 SQL 生成、执行、SDK 转存、证据账本、会话来源绑定和最终答案协议。
- 智能问数继续按数据源组织，不强制挂到采集/发布工作区下。
- 系统首页不在本轮全面重做；本轮重点是全局菜单及智能问数内部页面。
- 本文不授权自动实施、提交、推送或重启服务。

**上游契约与同步：** 本文拟调整根目录 [docs/2_NL2SQL_Vue接入设计.md](../../docs/2_NL2SQL_Vue接入设计.md) §4.2 的会话列表契约、§6.1 的页面与路由、§7.1 中与会话列表耦合的页面状态流，以及 [docs/9_侧边栏导航与返回路径修改方案.md](../../docs/9_侧边栏导航与返回路径修改方案.md) 中查询相关的菜单和页面映射。当前仅为待实施方案；实施完成时同步这些位置并添加回指本文的链接，不提前把新契约写成运行现状。根 doc 9 的“新建查询、会话历史不改”保留为该轮历史范围，增加本轮后续变更说明；其他模块导航与返回协议不变。

## 2. 导航与页面关系

### 2.1 全局导航

```text
首页
智能问数           ▾
    新建查询
    新建分析        （灰色，即将开发，不可点击）
数据资产
数据源管理
工作区管理         ▾
    全部采集作业
    全部发布作业
系统设置           （待开放）
```

- 点击“智能问数”文字进入不带筛选参数的 `/query`，显示全部数据库、空搜索的默认首页；点击相邻箭头展开/收起子菜单，两个动作分开。
- 子菜单固定两项。“新建查询”进入新建页面，不携带首页当前的数据库筛选，也不提前做就绪检查。“新建分析”沿用现有禁用语义：灰色、不可点击、无路由，用提示说明即将开放。本轮不实现分析页。
- 智能问数内部页面高亮所属模块。位于 `/query/new` 时子菜单强制展开，并同时高亮“新建查询”；此状态下箭头不可收起，规则与工作区管理位于全局作业页时一致。首页和已有会话页只高亮“智能问数”，子菜单可收起。“新建分析”不参与高亮。
- 移除全局侧栏顶部的“新建查询”和“新建分析”按钮；“新建分析”改放到上述子菜单，不再作为顶部禁用按钮保留。
- 移除侧栏底部历史对话及“分析项目待接入”占位内容。工作区子菜单、系统设置及其他模块的现有导航行为保持不变。
- 不新增常驻会话侧栏，避免形成三列布局。

### 2.2 建议路由

| 地址 | 页面 | 行为 |
| --- | --- | --- |
| `/query` | 智能问数首页 | 展示会话列表、数量、筛选和搜索 |
| `/query/new` | 新建查询 | 选择数据库并开始提问 |
| `/query/:sessionId` | 已有会话 | 恢复对话、查看结果及继续提问 |

`/query/new` 必须匹配静态新建路由，不能被当成 sessionId。同步修改所有原先把 `/query` 当作新建入口的调用点；打开已有会话的地址保持现有形式。

## 3. 智能问数首页

```text
智能问数                                      ＋ 新建查询
浏览历史对话，或开始一次新的数据查询

全部对话：46    当前筛选：8

数据库：[全部数据库 ▾]    [搜索对话标题……] [搜索] [重置]

对话标题                     数据库           最后更新时间
当前系统有多少个客户？       Orders 订单库    2026-11-11 12:19
哪些产品的订单最多？         Orders 订单库    2026-11-10 23:35
本月销售额是多少？           Sales 销售库     2026-11-10 16:20

                         加载更多
```

以上记录与数量仅为布局示意，产品页面必须使用真实数据。

### 3.1 列表与数量

| 项目 | 规则 |
| --- | --- |
| 会话范围 | 当前 guest 的有效 Web 登记会话；沿用既有完整失效会话、空会话的展示规则 |
| 会话次数 | guest 可展示会话总数（`total_all`），页面放在「查询会话」左侧，不受数据库筛选和搜索影响 |
| 当前筛选 | 同时满足数据库和标题条件的会话总数，分页前统计；列表标题旁显示「共 N 条对话」 |
| 总问答次数 | 全部有效会话登记 `turn_count` 缓存之和（`total_turns_all`），与 `total_all` 同集合，不受筛选和分页影响（doc 12）；页面放在「查询会话」右侧 |
| 排序 | `last_active_at` 倒序；同一时刻沿用 `session_id` 升序打破并列 |
| 行信息 | 标题、数据库显示名称、最后更新时间；失效或不可继续状态保留提示 |
| 打开 | 点击标题恢复已有会话，不触发新建查询的就绪检查 |
| 分页 | 每次 30 条，沿用“加载更多”，使用后端 `next_offset` |

首页和历史对话框统一用现有 `formatNl2sqlTime()` 展示绝对时间 `YYYY-MM-DD HH:mm`（`Asia/Shanghai`），不再在这个列表中使用相对时间；排序仍依据原始时间值，不依据格式化文本。

首页顶部为两张统计卡，排版以 [ui/12](ui/12.智能问数.html) 为准，数值口径见 [doc 12](12_智能问数首页问答次数统计修改方案.md)。「查询会话」左侧是会话次数（`total_all`），右侧是总问答次数（`total_turns_all`），说明为「已启动的会话与累计问答次数」。「分析统计」的分析次数和总问答次数都未接入，显示 —，说明为「全部分析与累计问答次数」。历史分析列的数量显示「共 — 份分析」，不使用查询侧的数字。加载未知时，查询会话的两个数字都显示 —；筛选完成后它们仍保持全局值。

不能用当前页长度或已加载条数充当总数。损坏登记沿用现有跳过、校正逻辑，不算入可展示总数；达到扫描上限时沿用既有失败语义，不能把部分结果包装为完整统计。

数据库名称从数据源登记信息映射；历史来源缺少登记信息时显示 `source_id`，不能因此隐藏会话。数据库停用或未就绪不妨碍查看历史，新建和继续提问仍按既有规则判断。

数据源已停用时，会话行的数据库名称旁也标注“已停用”，与筛选项使用相同文案，让用户理解为何没有行内新建动作。该标注与会话失效、不可继续提示分别展示，不能相互替代。

首页和历史对话框的数据库筛选使用全部已登记数据源，包含启用和停用来源；停用项标注状态但仍可选择以查看历史。不能复用查询流程对外返回的 `activeSources` 作为历史筛选范围；新建查询的可选范围仍只包含启用来源。沿用现有数据源列表接口，不新增接口。

数据源列表加载失败与会话列表加载失败分别处理：前者不阻止历史会话加载和打开，数据库名称暂用 `source_id`，不能显示“暂无对话”；未能确认来源已启用时，不提供“在此数据库新建”动作。

数据源列表加载中或失败时，地址中已有的 `source_id` 仍用于会话请求，不能自动清除或改为全部数据库。下拉保留当前来源的临时选项，以 `source_id` 展示名称；加载失败时显示原因和重试入口。加载成功且找到登记时，用该来源的 `display_name` 替换临时展示，停用则附加“已停用”，并移除对应的临时项；同一 `source_id` 只能出现一个选项。仅在加载成功后仍找不到登记时，继续保留 `source_id` 选项和筛选值。加载期间尚未确认启用状态时，行内新建动作先不出现。

数据源“重试”只重新请求数据源列表，用于补全名称、停用标注和行内新建可用性；不重新请求会话、不清空已加载会话，也不重置“加载更多”的进度。会话列表失败时使用会话自己的重试入口，重新请求会话数据，两种重试各自独立。

### 3.2 筛选与搜索

- 首页已应用的条件写入 `/query` 的地址：省略 `source_id` 表示全部数据库，省略 `q` 表示不搜索。刷新或通过浏览器返回到带条件的首页地址时，按地址恢复条件并重新加载第一页。加载更多的偏移只留在页面状态中，不写入地址，返回后从第一页重新加载。
- 只有切换数据库、提交搜索和重置使用 `router.replace` 更新当前首页地址，不为每次筛选新增浏览历史。打开会话、点击导航或标题栏“新建查询”、点击行内“在此数据库新建”均使用 `router.push`（或 RouterLink 默认导航），不能替换当前首页记录；从会话或新建页后退一次，回到当时筛选后的首页地址并从第一页重载。
- 点击全局“智能问数”菜单进入裸 `/query`，恢复全部数据库、空搜索；不额外记忆上一次首页地址，也不增加返回来源参数。
- 首页组件可能被路由复用，必须持续响应地址中 `source_id`、`q` 的变化，同步筛选控件、搜索输入和第一页列表，不能只在首次挂载时读取。包括从带条件首页点击“智能问数”回到裸 `/query` 的情况。
- 数据库默认“全部数据库”。切换后立即更新 `source_id` 并重新加载第一页，已提交的 `q` 保留。
- 搜索只匹配已存储的会话标题：关键字只去掉首尾空白；处理后为空就省略 `q`，等同不搜索。后端在现有枚举循环中，用原文判断 `title` 是否包含该关键字，区分大小写。不使用 SQL LIKE、Store 的 filter 或向量 query 做包含匹配。
- 大小写策略沿用本轮已经明确选定的原文匹配：保留大小写差异，不增加文本规范化。它是产品取舍，不是 Store 或 PostgreSQL 的能力限制；接受 `top 10` 不命中 `Top 10 customers` 的边界，本轮不改为大小写不敏感搜索。
- 现有标题由首问去除首尾空白后取前 40 个 Unicode 码点生成；未进入已存储标题的长问题后半段搜不到是预期。完整问句位于 `web_turns` 的 `question`，本轮不搜索该字段，不扩大为首问全文或问答全文搜索。
- 点击“搜索”或按 Enter 后，才把仅去掉首尾空白的关键字原文写入 `q` 并发起请求；输入过程中不请求。清空输入框本身不改变当前结果，需再次搜索或重置。
- 数据库条件与搜索条件取交集；改变已应用条件后清空旧列表和分页位置。
- “重置”去掉地址中的 `source_id` 和 `q`，恢复全部数据库、空关键字并重新加载。
- 搜索和统计必须在后端对完整会话范围执行，不能仅过滤当前已加载的 30 条。
- 首页与对话框各自用同一代请求标记管理列表、三项统计（total_all、total_filtered、total_turns_all，doc 12）、next_offset 及加载/错误状态。筛选变化、第一页刷新或对话框重新打开时切换请求代；第一页和加载更多均绑定所属代。过期的成功、失败和 finally 都不得修改当前代，既不能把新数量改回“—”，也不能追加旧页、改偏移或清除新请求的加载状态；同页不重复追加。
- 历史对话框内的数据库筛选和标题搜索仅在本次打开期间有效，不写入 `/query/new` 或 `/query/:sessionId` 的地址；关闭后再次打开时，按 §4 重置全部条件及分页。

### 3.3 新建查询

- 导航子菜单、首页标题栏和查询页标题栏上的“新建查询”都进入未选择数据库的 `/query/new`。不读取首页当前筛选，不附带 `source_id`，进入后也不自动执行就绪检查；由用户在新建页选择数据库后再检查。
- 会话行可另提供“在此数据库新建”。仅当该会话来源仍是已启用的登记数据源时显示；点击后进入 `/query/new?source_id=`，并执行现有就绪检查。来源已停用或登记已不存在时不提供该动作，历史行仍可打开。已启用但尚未就绪的来源仍可进入新建页，由现有检查结果说明不能开始提问。
- 预选仅在新建页持续响应 `route.query.source_id`：无预选变为 A、A 变为 B 时更新选择并做就绪检查；A 变为裸 `/query/new` 时清空旧选择和检查结果，等待用户手动选库。直接打开或刷新预选地址同样生效，不能只在 onMounted 处理，也不要由挂载和监听重复发起检查；已有会话仍以服务端绑定为准。这里只补齐路由参数变化的接线，选库、检查就绪的流程不变。
- 上述两类新建入口均使用 push 导航，保留来源首页及其筛选地址，不使用 replace。
- 新建页的数据库选择不能改变任何已有会话的来源绑定。
- 本轮（2026-11-11）原保留现有显式创建会话流程；该交互决定已由 [doc 11](11_首次提问创建会话与新建查询交互优化方案.md) 实施替代：删除“开始查询”按钮，就绪通过即可输入，首次发送时创建会话、接管会话并替换地址后提交首问，草稿由查询状态持有。导航布局、入口位置与来源绑定决定不变；创建阶段的忙碌禁用与晚到回调隔离仍按本节及 §4 执行。

## 4. 查询历史对话框与查询页

- “查询历史”按钮主要放在新建查询页、已有会话页顶部，与“新建查询”并列。
- 对话框复用首页的会话列表、数据库筛选、标题搜索、排序和分页能力。筛选和加载状态与首页各自独立，查询页初始化不得覆盖对话框正在使用的条件。
- 每次从新建页或已有会话打开对话框时，均重置为“全部数据库”、空搜索关键字和第一页，重新加载列表，不保留上一次打开的搜索、已加载页数或旧请求结果。已有会话只高亮当前行，不预先收窄到该会话绑定的数据库；关闭再打开时，前一次打开的晚到列表响应不得覆盖本次结果。
- 点击历史标题后关闭对话框并打开对应会话；仅打开、关闭或筛选对话框，不清空当前输入或重置对话。
- 首页已经展示完整列表，首期不再放一个打开相同列表的重复按钮；这是对前述讨论中按钮位置的建议裁定，审核时可调整。
- 查询执行期间统一禁用全局侧栏“新建查询”子菜单、页面上的“新建查询”和“查询历史”入口；对话框若已打开，其中的会话切换及行内新建动作同样不可用，不能只禁用查询页按钮而遗漏全局入口。关闭对话框只关闭层，不中止正在进行的请求。当前查询页没有用户可点的终止按钮，本轮不新增终止能力。直接修改地址或使用浏览器前进后退不受这些按钮禁用约束。[doc 11] 实施后，首次发送的创建会话阶段与查询执行同用该统一禁用与忙碌标记。
- 提问提交中同时禁用现有“刷新对话”按钮，刷新处理函数也应检查提交状态后直接返回；此时不能调用 openSession、清空会话状态或递增请求令牌，不能通过刷新把 askState 置回 idle、恢复输入及入口。提交结束后恢复既有刷新行为，不另设计“刷新即放弃跟踪”的分支。
- 执行状态由查询页通过应用布局同步给侧栏，只共享用于入口禁用的忙碌标记；不复制会话状态，也不引入状态管理框架。完成或离开当前查询页时更新标记，避免侧栏残留禁用状态。
- **离开策略：接受离开后开始新查询。** “智能问数”父菜单及其他模块导航保持可用；点击父菜单进入 `/query` 后清除当前页忙碌标记，首页和侧栏的新建入口可用。旧请求不取消，服务端仍按既有流程执行、保存结果；旧请求的结果不回写当前前端页面，之后可通过历史重新读取已保存结果。这与直接修改地址、浏览器前进后退采用相同边界，不增加全局后台请求锁。
- **既有限额保留：** 不增加全局后台请求锁，仅指不为这次导航新增跨会话锁；现有并发名额、每分钟提交频率限制和同一会话的会话锁均保持不变。离开后允许发起新查询，不保证服务端一定接收：旧查询仍在运行时，回到同一会话提交可能按现有规则返回 `session_busy`；另建会话后立即提问也可能被并发或频率限制拒绝。这些是正常限制，不能因允许离开新建而绕过，也不应在验收时当作回归。
- **晚到回调隔离：** 忙碌标记的更新必须核对当前页面实例和当前请求归属。已经离开或被替换的请求，其成功、失败及 `finally` 回调均不能修改新页面内容或当前忙碌标记；再次进入同一 sessionId 也不能把旧请求认作当前请求。
- 该隔离同时覆盖创建会话：发起创建时记录页面及创建请求归属；创建期间允许离开，但晚到的成功结果不能 router.push 把用户拉回，失败或 finally 也不能更改新页面提示、列表或忙碌标记。服务端可能已创建的空会话保留，之后可从历史查看；创建超时仍不自动重试，不增加取消、幂等或删除机制。

查询页继续展示对话、表格、SQL 和输入框；标题与数据库信息放在顶部左侧。历史选择采用覆盖式对话框，不挤压结果表格宽度。

## 5. 窄屏与状态展示

- 桌面保持全局导航＋内容区两列。窄屏（不超过 800px，更窄时沿用现有 53px 宽度）继续使用现有图标条，不改成抽屉，也不为了让内容区占满宽度而隐藏这条导航。
- 图标条沿用现有规则：箭头隐藏，“新建分析”与“系统设置”等禁用项隐藏。智能问数的子菜单整项隐藏，包括处于 active 状态的“新建查询”，不是只隐藏文字；`/query` 下各页仅以“智能问数”父项图标表示当前模块，不同时出现父、子两个图标。窄屏上的“新建查询”使用首页按钮和查询页标题栏按钮。
- 历史对话框在窄屏使用接近全屏的覆盖层。它盖住内容区，不把全局导航换成抽屉，也不要求导航再收起一层。
- 窄屏列表每条分两行：标题在上，数据库和更新时间在下；不强行压缩成三列小字。
- 首次加载、加载更多、失败重试、没有任何对话、筛选无结果分别展示状态。
- 智能问数首页及历史对话框沿用客户端惰性配置校验：`VITE_NL2SQL_API_BASE_URL` 缺失或非法时显示“查询服务未配置”及配置说明，不请求 NL2SQL 接口、不回退到 MetaWeave 地址。统计不伪造为 0，禁用依赖该接口的数据操作，不能把未配置显示成“暂无对话”或普通网络故障；其他模块仍可使用，不改现有 QueryView 的配置错误行为。
- 没有任何对话时提供新建入口；筛选无结果时保留筛选和重置入口；请求失败不能展示“0 条”冒充真实统计。
- 第一次加载或重新请求第一页（含筛选变化、重置、刷新）时，`total_all`、`total_filtered`、`total_turns_all` 先标记为未知，显示“—”；成功后才写入本次响应的统计，失败时保持未知并显示失败状态，不能沿用上一筛选的统计。加载更多失败则保留已加载列表、已确认数量和待重试偏移。仅重试数据源列表不影响会话数量及分页。
- 对话框支持键盘关闭、合理的焦点进入与返回，不能让关闭状态的内容继续接收焦点。

## 6. 已有能力与最小接口扩展

已核对代码：`GET /api/v2/sessions` 已支持 guest 范围、`source_id` 筛选、倒序与分页；前端 `listSessions()` 也已有 `sourceId` 参数。当前缺少标题搜索、全部数量及筛选数量。

**Store filter 的含义：** Store 是本项目读写会话 JSON 数据的统一接口，底层存储为 PostgreSQL；`filter` 是其查询接口的字段条件参数，可表达字段相等等条件，不能直接表达标题包含。本方案继续查询 PostgreSQL，但 Store 读取只限定 guest 命名空间，不传用于 source_id 的 filter 或用于关键字的 query；source_id 与 q 均留在同一遍 Python 枚举中判断。这样枚举能同时看到不同数据库的会话，一次得出全部数量和筛选数量，不另扫一遍或另写 SQL LIKE。

建议沿用现有接口：

```text
GET /api/v2/sessions?source_id=db_src_1&q=客户&limit=30&offset=0
```

- 新增可选 `q`，默认空；前端只将去掉首尾空白后的原文写入 `q`，为空时省略该参数。区分大小写的标题包含判断只在后端现有枚举循环中执行，不在前端筛选当前已加载列表。
- 后端对原始 `q` 使用 `Query("", max_length=100)` 校验，最多 100 个 Unicode 码点，超长沿用 422 参数错误；随后独立执行 `strip()`，为空则视为无搜索条件，不能依赖前端省略空值。首页及历史对话框提交前复用现有 `codepointLength()` 检查整理后长度，不使用 JavaScript `.length` 的 UTF-16 单元数；超限提示“关键字最多 100 个字符”，不截短或发起请求。直接请求 `q=%20` 必须等同不搜索。
- 100 码点仅为参数长度护栏，不扩大搜索正文。对现有最多 40 码点的首问派生标题，41～100 码点的关键字正常返回无匹配；验收要求其可以提交，不要求命中，更不能为命中而读取 web_turns.question。
- 在现有返回字段之外增加 `total_all`、`total_filtered`、`total_turns_all`；前两者均为本次读取时的真实数量，第三项为全部有效会话登记 `turn_count` 缓存之和（全局口径与校正语义见 [doc 12](12_智能问数首页问答次数统计修改方案.md)）。
- Store 一次完整枚举中完成合法登记检查、全部计数、条件筛选、排序及分页，不为三项统计再重复扫描两遍。
- 单条记录处理顺序固定为：归属校验 → 既有展示字段检查 → 累计 total_all → 累计 total_turns_all（doc 12，登记缓存、不读 web_turns）→ 按 source_id 和 q 筛选 → 累计筛选集合，最后排序、分页。只有展示字段检查已确认 title 是非空白字符串后，才执行 `keyword in record["title"]`。title 缺失、非字符串或其他展示字段损坏时，继续沿用跳过及按需校正规则，不计入三项统计；不能因包含判断顺序错误让单条坏记录导致整次列表 500。
- 保留现有扫描预算、损坏登记处理、会话归属校验及按需校正，不增加认证参数或新数据库表。
- 前端使用专门的会话列表响应类型；不要求轮次列表等其他分页接口返回会话统计字段。
- 不承诺跨请求快照；查询更新导致排序变化时可刷新列表，加载更多时按会话 ID 去重，避免重复展示。
- 分页位置独立保存后端返回的 `next_offset`。会话 ID 去重只影响展示列表，不能用去重后的列表长度计算下一次 offset；刷新或筛选变化时重置分页状态，加载更多失败时保留当前待加载偏移供重试。
