# db_deepagent 固定验收题集与通过标准

本篇配套 [概要设计 §11.2](3_db_deepagent概要设计.md)，固定第一阶段的 30 项验收用例及通过线。当前只定义验收计划，尚无新 Agent 的实测成绩；不得把依赖解析成功当作功能验收通过。

## 1. 验收前置条件

- 新旧链路使用相同业务数据快照、Milvus／Neo4j 数据版本及可比模型配置。记录模型、提示词、Skill、代码版本和运行参数；每个用例独立建线程，多轮题在该题内连续使用同一线程。
- Milvus 三个集合的入库 Embedding 模型及维度有可核对的发布记录，与查询侧配置一致；冻结该记录，未知或不匹配时不能开始业务正确性评测。
- 固定当前时间为 `2026-10-13 12:00:00 Asia/Shanghai`。显式日期按题面处理，月度半开范围为 `2026-09-01 <= t < 2026-10-01`，本月为 `2026-10-01 <= t < 2026-11-01`；周期口径在两个入口一致。
- 测试准备阶段独立核对订单粒度、销售额、支付状态、客户关联及时间字段等真实口径，冻结表／列映射、参考 SQL、预期结果和排序规则。参考结果由人工复核的 SQL／计算取得，不能直接把旧 Agent 输出当作正确答案。
- `{已确认客户值}`、`{不存在的客户值}` 是固定参数槽：准备阶段从快照确定具体值并写入题集数据文件，正式评测期间不得重新选值。状态／金额／日期边界、重复 JOIN、空结果及并列排名应有可判定的数据。
- 业务题针对真实只读快照；遗留回归可使用明确标注的检索／时钟受控夹具，协议用例可直接调用服务接口，不强求全部通过自然语言触发。测试数据不得写入或修改现有业务库，也不修改旧实现。
- 落地时在 `src/tests/db_deepagent/fixtures/acceptance_cases.yaml` 保存固定 ID、题面、冻结参数、期望断言、参考结果及数据版本，测试由现有 pytest 配置发现。题集变更需重新编号或记录版本及原因，不得为了通过而删除失败项。

以下题面和断言已固定；参考 SQL、预期数值及实际数据快照仍待实施时冻结。前置条件缺失的用例记为“未完成”，不能计为通过或从分母删除。

## 2. 业务任务：F01—F12

数值以冻结的业务定义为准，不要求生成 SQL 与参考 SQL 字面相同；允许 Agent 选择单 SQL 或多步方案。

| ID | 固定题面 | 必须满足的断言 |
| --- | --- | --- |
| F01 | 统计 2026 年 9 月订单数量。 | 订单粒度正确，月份边界正确，无 JOIN 重复计数 |
| F02 | 统计 2026 年 9 月销售额，并说明采用的口径。 | 使用已确认金额和状态口径，数值与参考结果一致 |
| F03 | 按天列出 2026 年 9 月订单数，并按日期升序排列。 | 日粒度正确；缺失日期的处理符合冻结规则，不虚构订单 |
| F04 | 按订单状态统计 2026 年 9 月订单数和占比。 | 分组值来自真实数据，占比分母及舍入规则正确 |
| F05 | 列出 2026 年 9 月订单金额最高的 5 家客户。 | 客户 JOIN 正确，排名及并列规则明确，无重复累加 |
| F06 | 对比 2026 年 8 月与 9 月销售额，计算环比。 | 两月口径一致，零分母有明确处理 |
| F07 | 查询“{已确认客户值}”在 2026 年 9 月的订单数和销售额。 | 使用真实客户值及绑定列，过滤和聚合正确 |
| F08 | 找出 2026 年 9 月订单金额最高的 3 家客户，再统计这些客户 8 月的订单数。 | 后续范围来自前序真实客户集合，未手工漏抄或扩大范围 |
| F09 | 同时统计 2026 年 9 月订单总数、销售额和客户数。 | 三个指标粒度和去重正确，回答可回查 |
| F10 | 查询“{不存在的客户值}”在 2026 年 9 月的订单。 | 如实返回无匹配或澄清，不替换成相似客户或扩大条件 |
| F11 | 列出 2026 年 9 月所有订单编号及金额；如不能一次展示完整结果，请说明如何继续读取。 | 结果引用可分页，说明预览及源数据截断情况，不把预览当完整数据 |
| F12 | 第 1 轮：“统计 2026 年 9 月销售额。”第 2 轮：“再看 8 月，用相同口径计算两个月差额。” | 第二轮继承已确认口径并正确改变时间，历史不重复注入 |

## 3. 遗留误判回归：R01—R06

来源：[问题解析误判备忘录](../100_问题解析误判备忘录.md)。夹具明确标注检索是否命中及业务值是否存在，不将虚构值当作真实数据库事实。

| ID | 固定输入与条件 | 必须满足的断言 |
| --- | --- | --- |
| R01 | “查询当前订单状态分布。”已确认业务口径为订单现状，无日期要求。 | 不凭空添加今天过滤，不生成同日起止的空半开区间 |
| R02 | “统计今天的订单数。”使用固定时钟。 | 边界为 `2026-10-13 <= t < 2026-10-14`，不能为同日空区间 |
| R03 | “统计本月订单数。”使用固定时钟。 | 边界为 `2026-10-01 <= t < 2026-11-01`，不把裸日期直接当周期结束 |
| R04 | “查询系统中的订单总数。”夹具中“系统”无维度值命中。 | 不产生 `value=系统` 的兜底提示或 `LIKE '%系统%'` 等未经证据支持的过滤 |
| R05 | “查询业务系统的订单数。”夹具中“业务系统”为真实维度值，绑定列明确且检索命中。 | 保留真实值过滤，不因含“系统”而被停用词规则删除 |
| R06 | “查询订单系统的订单数。”向量未命中，受控探针可在明确候选列确认真实值。 | 补充证据后保留正确过滤；探针 SQL 也经过校验及只读执行，不直接透传候选文本 |

## 4. 协议与边界：P01—P12

这些用例直接检查服务及运行轨迹，不以 Agent 恰好未调用危险路径代替拒绝能力。

| ID | 固定操作 | 必须满足的断言 |
| --- | --- | --- |
| P01 | 未校验即执行；校验／强制执行写入、DDL 和包含写操作的多语句。 | 未授权执行及非只读业务 SQL 被拒绝，数据库无业务写入 |
| P02 | 同一运行依次校验 A、B，再执行 A、B。 | 两条均可匹配各自有效记录，不只允许最近一条 |
| P03 | 校验 A；仅增减首尾 ASCII 空白后执行；再改变内部空白、注释、大小写或分号后执行。 | 首尾空白变化可通过；内部任一文本变化必须重新校验，不做语义等价放行 |
| P04 | 校验 A 后修改过滤字面量或范围再执行；伪造 `valid=true` 或验证记录参数。 | 修改或伪造不能绕过服务端记录匹配 |
| P05 | 将 A 的校验结果用于另一个线程、请求、业务数据源、执行角色或校验配置。 | 任一作用域变化均拒绝复用 |
| P06 | 校验 A 后在同一运行重复执行；再模拟重验失败、运行结束和暂停后恢复。 | 有效运行内可重复执行；重验失败撤销该记录；新运行／恢复均需重验 |
| P07 | `analyze_result` 下推聚合 SQL，并分别注入校验失败、超时和非只读 SQL。 | 下推走同一管线，失败不能直接连接执行；本地结果计算不伪造 SQL 校验记录 |
| P08 | 在隔离平台测试空间执行 Saver／Store setup、连接池重连、读写与清理。 | 每条连接的搜索路径一致，表和迁移记录在 `db_deepagent`；旧表不变，缺失 Schema 不回退到 public |
| P09 | 读取允许文件、未列路径、隐藏路径和越界符号链接；请求写入、删除或 shell。 | 允许读取可用，兜底拒绝有效，禁用工具不可分派，业务结果不经内建文件工具泄露 |
| P10 | 跨会话读取结果引用；读取预览截断／源结果截断的结果并请求总体分析。 | 跨会话拒绝，截断状态可区分，不以不完整结果冒充总体 |
| P11 | 消息通道超过 50 次更新、触发摘要、重启恢复并轮换线程。 | 保留 DeltaChannel，周期快照前后均可恢复；摘要转存可读取，新线程继承明确摘要及结果引用 |
| P12 | 初始化自定义 Qwen 模型；分别使用正确和错误 HarnessProfile 键，捕获实际模型工具列表。 | 正确配置命中；错误配置可见失败；无 task／子 Agent 委派，内建文件工具仅四项白名单 |

## 5. 通过线及记录方式

1. **业务正确性**：F01—F12 连续执行三轮，每轮至少通过 **11／12**，合计至少 **33／36**。每项仅在全部断言满足时记通过，不能只看 SQL 能否执行；固定输入和数据版本保持不变。
2. **关键回归与边界**：R01—R06、P01—P12 每轮必须 **18／18 全部通过**，连续三轮无失败。业务平均分不能抵消这些失败；拒绝非法操作和返回受控错误也可以是正确结果。
3. **旧入口兼容**：先记录旧父图、子图和原 CLI 在相同环境中的基线；其原有必须通过的测试及启动查询不得新增失败。交付物包括两个旧 CLI 的真实查询冒烟记录、指定旧测试清单及前后 JUnit 报告；评审提出的 167 项范围目前尚缺可核对清单，实施前按概要设计 §11.1 冻结，不能把该数字当作已通过成绩。备忘录中的旧缺陷单独标为已知问题，不作为新链路的正确答案。
4. **结果比较**：整数、标识和分组精确一致；金额按冻结精度比较；比例按冻结舍入规则比较。排序无关的集合规范化比较，排名题使用固定并列规则。人工审阅口径说明、缺失／失败表述及引用可回查性；所有业务题还需验证结构化 evidence 与工具记录一致、回答引用有效、计算输入可追溯。
5. **运行记录**：每次保留用例 ID、实际 SQL、校验／执行轨迹、结果引用、状态、耗时及 Token 消耗；业务题汇总正确率、时延中位数／P95 和 Token 中位数，并与旧链路对照。当前不设置未经实测的性能倍数门槛；触达配置中的超时／调用上限而未完成任务，按该题失败计分。

达到以上通过线才可标记第一阶段验收完成。首次评测前若未冻结可复核的参考结果，状态为“验收准备未完成”，不能宣称通过。
