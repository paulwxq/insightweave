# 独立摘要器接入修改方案

> **For agentic workers:** REQUIRED SUB-SKILL: 使用 `executing-plans` 按任务执行；步骤采用复选框记录。**本方案已于 2026-11-10 实施并通过两轮代码审核**；随后真实模型 `--run-llm` 低阈值冒烟测试也已通过，见文末记录。生产 96000 tokens 窗口、质量/成本及 PostgreSQL 验收仍未完成。

**Goal:** 在生产 `build_db_agent()` 中使用 SDK 公开的 `summarizer=` 参数，显式区分主模型上下文管理与摘要生成，并保持当前行为。

**Architecture:** 继续使用 SDK 的 `SummarizationMiddleware`。主模型作为 `model`，现有带摘要用途标记的模型副本作为 `summarizer`，摘要生成仍由 SDK 执行。沿用当前模型、后端和摘要策略。

**Tech Stack:** Python 3.12、DeepAgents 0.7.34、LangChain 1.4.9、LangGraph 1.2.20、pytest。

**Spec:** [4_DeepAgents实现简化与旧链保留价值分析.md](4_DeepAgents实现简化与旧链保留价值分析.md) §4.2；[已有离线对照测试说明](../tests/unit/db_deepagent/README.md)。

## 2. 每个文件具体怎么改

### 2.1 `agent.py`：修改生产摘要中间件的两个模型参数

在 `build_db_agent()` 中找到下面的构造，应用这一处差异：

```diff
     summary_mw = SummarizationMiddleware(
-        summary_model,
+        model=model,
+        summarizer=summary_model,
         backend=backend,
         summary_prompt=build_summary_prompt(prompts),
         trigger=("tokens", cfg.summarization.summary_trigger_tokens),
         keep=("tokens", cfg.summarization.recent_context_tokens),
         trim_tokens_to_summarize=cfg.summarization.trim_tokens_to_summarize,
     )
```

其前面的 `summary_model = model.model_copy()` 及 metadata 合并代码保留。其后的 `create_deep_agent(model=model, ...)` 和中间件列表保留。修改后，`model` 提供主模型上下文依据，`summary_model` 通过 `summarizer=` 执行摘要调用；仍是同一种模型、同一套摘要参数。

### 2.2 `test_summary_context.py`：修改一个测试和一个辅助函数，新增一个测试

**A. 替换现有弱断言。** 当前 `test_summary_middleware_instance_wired()` 只是调用装配并断言配置阈值大于零，不能证明接入了 `summarizer=`。为该测试增加 `monkeypatch` 参数，使用现有 `ScriptedChatModel` 作为假模型，并按下面方式记录真实构造参数。以下是该测试的关键实现片段，不是整个测试函数：

```python
import inspect
import deepagents.middleware.summarization as sdk_summary
import src.modules.db_deepagent.agent as agent_mod

model = ScriptedChatModel(responses=["offline"])
metadata_before = dict(model.metadata or {})
monkeypatch.setattr(agent_mod, "build_model", lambda _cfg: model)
real_constructor = sdk_summary.SummarizationMiddleware
signature = inspect.signature(real_constructor)
records = []

def capture_constructor(*args, **kwargs):
    records.append(dict(signature.bind_partial(*args, **kwargs).arguments))
    return real_constructor(*args, **kwargs)

monkeypatch.setattr(sdk_summary, "SummarizationMiddleware", capture_constructor)
handle = build_db_agent(assembly_services, session_id="t-summary")
production = records[0]
assert "summarizer" in production
assert production["model"] is model
assert production["summarizer"] is not model
assert model.metadata == metadata_before
assert production["summarizer"].metadata == {
    **metadata_before, "dbda_call_kind": "summarization"
}
```

继续在该函数中断言以下值，而不是仅检查阈值为正数：

| 断言对象 | 应满足的条件 |
| --- | --- |
| 摘要副本 | 与主模型类型相同，`model_dump(exclude={"metadata"})` 相同 |
| `production["backend"]` | 与本次 `build_backend()` 返回的实例相同；可用同样委托真实函数的包装记录其返回值 |
| `production["summary_prompt"]` | 等于 `build_summary_prompt(load_prompts())` |
| `production["trigger"]` | 等于 `("tokens", assembly_services.config.summarization.summary_trigger_tokens)` |
| `production["keep"]` | 等于 `("tokens", assembly_services.config.summarization.recent_context_tokens)` |
| `production["trim_tokens_to_summarize"]` | 为 `None` |

包装函数返回真实实例，不使用子类或改写 `.name`。必须保留所有构造记录，因为 SDK 也会构造默认实例；当前生产显式构造在 `create_deep_agent()` 之前，是第一条记录。不能断言总共只调用一次、取最后一次，或仅按 `summarizer` 键是否存在筛选。修改生产代码前，该测试应因生产记录缺少 `summarizer` 而失败；改完 §2.1 后再验证通过。

**B. 调整现有辅助函数。** `_invoke_with_context()` 增加可选的关键字参数，保留原来的上下文构造和调用行为：

```diff
-def _invoke_with_context(handle, thread_id: str, question: str):
+def _invoke_with_context(handle, thread_id: str, question: str, *, observer=None):
```

在它创建 `config` 后、调用 `handle.agent.invoke()` 前加入：

```python
config["metadata"] = {"dbda_call_kind": "agent"}
if observer is not None:
    config["callbacks"] = [observer]
```

这样新增测试可以观察真实 SDK 内部摘要调用；现有调用点无需传入新参数，继续按原方式运行。

**C. 新增 `test_production_summary_calls_keep_observer_classification()`。** 使用现有 `summary_agent_env` 低阈值完整图 fixture，创建 `ModelCallObserver`，通过上述辅助函数发起一轮调用，然后从检查点读取摘要事件并封存观测结果。关键调用和断言为：

```python
handle, _saver, _fake, _services = summary_agent_env
observer = ModelCallObserver("req-summary", "run-summary")
_invoke_with_context(handle, "th-observer", "统计上个月的订单量", observer=observer)
values = handle.agent.get_state(
    {"configurable": {"thread_id": "th-observer"}}
).values
assert read_summary_for_handoff(values)
snapshot = observer.finalize()
assert snapshot.anomalies == []
assert snapshot.total_model_calls > snapshot.summary_model_calls >= 1
```

新增测试需在文件中导入 `ModelCallObserver`。不要求假模型的 `token_usage_complete=True`。保留现有事件结构、冷读和 Runner 交接三个测试，迁移后它们会经过新生产接线。

- 保留 `summary_model = model.model_copy()`，继续隔离摘要用途元数据。
- 摘要副本合并原有 metadata，并设置 `dbda_call_kind=summarization`；主模型用途不被覆盖。
- 保留当前 `summary_prompt`、backend、96000 tokens 触发阈值、24000 tokens 近期保留预算和 `trim_tokens_to_summarize=None`。
- 测试可调低触发阈值，生产 YAML 参数保持原值；近期保留预算不是摘要长度。
- 本轮不增加摘要模型配置入口，不更换模型，不增加自研摘要逻辑、服务或 Agent。
- 不升级依赖，不改 UI、API、业务预算、最终答案门控、旧 LangGraph 链和数据库结构；不顺带清理其他中间件。
