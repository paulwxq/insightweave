本轮只修订 [6.2 解决方案](../6.2_db_deepagent最终答案兜底问题与补齐建议.md) 及 [详细设计 §13.3](../v4/5_db_deepagent详细设计.md) 的待实施契约，不修改业务代码。

| 反馈 | 核实与决定 |
| --- | --- |
| 1. 原始非法提交仍在资格判断中抛异常 | 成立。旧文档片段对非法 findings、字符串/列表 payload 可抛 AttributeError；None、空串、空列表也会被 or {} 改写。增加统一原值提取，按键存在性保留原值；评估、交付和归档资格仅使用验证后归一的视图，原值只用于归档。 |
| 2. 重试默认 True 对原生 provider 是启动变化 | 成立。采用代码默认 False、标准 YAML 显式 True；旧自备配置缺项时保持原行为。原生显式开启时错误提示设置 model.retry.enabled=false；使用新版标准 YAML 的原生配置仍需显式关闭，不承诺自动兼容所有配置合并方式。 |
| 3. 版本常量与历史读取职责 | 建议合理。版本集中到 persistence/archive.py，写读共同引用。选择历史浅投影职责，仅检查版本和字典容器，不验证 status/answer 等字段，也不把返回字典当作契约验证成功。 |
| 4. 结果读取文案 | 成立。改为首版不读取结果文件、不承诺当前可读；两处示例也取消“可供查看”承诺。 |

无拒绝项。归档原 answer 保留的范围是外层记录中已有 answer 键的可序列化原值；缺键采用 `{}`。损坏的外层记录和不可序列化对象不在强制原样归档保证内。
