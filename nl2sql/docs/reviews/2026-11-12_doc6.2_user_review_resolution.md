## 逐项决定

| 人工反馈 | 核实结果 | 处理 |
| --- | --- | --- |
| 1. 空白 completed 与系统兜底矛盾 | 成立。现模型可接受纯空白；现 `_evaluate()` 会采用 completed；原方案在其后替换文本不足以修复状态。 | 新增共享结构/非空白判断，提交参数模型拒绝空白；Runner 在评估阶段视其为无有效提交；归档条件 b 同样复用判断。保留原有故障优先级，不允许 completed + system_fallback。 |
| 2. 双层重试与时限口径 | 成立。安装 SDK 默认两次内部重试，与项目层最多三次相乘可达九次。 | 采用推荐的单层重试。工厂显式支持参数，主模型构造前设置 max_retries=0，验证实际同步/异步客户端。中间件管理重试，明确仍是协作式停止，不能强制取消在途请求。摘要与关闭项目重试的路径另行说明。 |
| 3. 结果读取失败验收越界 | 成立。首版模板不调用 ResultStore 或打开结果文件。 | 首版验收改为确认不探测文件、不承诺文件可读；受控读取及其失败回退归为后续增强。 |
| 4. 归档字段语义变更需要契约 | 成立。原方案改写 answer，影响正常答案的含义，任意字典可写不等于兼容验证。 | 改选保留原 answer，增加 delivery_answer、answer_source、archive_schema_version=2。取消重复 submitted_answer 字段；定义 v1/v2 兼容读取，详细设计同步，外部消费者未知范围明示。 |
| 5. 投影默认零不等于真实零 | 成立。当前缺字段时投影零，原模板不能区分未知。 | 内部从原始账本生成可选行数映射，未知时不输出零行结论。外部整数类型暂保留兼容，模板不依赖该默认值；同时补显式 None/非法类型的投影兼容和测试。 |

五项问题均采纳，无拒绝项。两项实现取舍是：优先保留归档原 answer，避免无必要地改变既有字段含义；行数的可选性先用于内部可信映射，不在本问题内扩大全部 API 的 nullable 协议。

## 离线验证证据

所有检查在项目 `.venv` 中运行，不连接真实模型或数据库；真实 OpenAI SDK 使用 httpx2.MockTransport 和合成 503 响应。

### 修订方案检查

- 在内存 AST 副本中将新增 validator 放入现参数模型，实际经提交工具与 ToolNode 验证空白输入返回 invalid_argument、不写最终提交；正常正文格式保留。
- 对 `_evaluate()` 的内存副本应用文档建议的有效性前置及分支修改，空白 completed 变成 failed，正文和 findings 不作为有效提交交付。
- 行数映射覆盖缺失、None、bool、负数、字符串、明确零、正整数；仅明确零展示为零。
- 直接运行归档核心片段：纯沿用空白提交进入 run_errors；真实执行空白仍可按 a 进入 QA；普通有效沿用可按 b 进入 QA；原 answer 与 delivery_answer 分别保留。
- v1 回退读取原 answer，v2 读取 delivery_answer，未知版本拒绝。
- 构造片段创建实际 ChatOpenAI 主模型，确认同步/异步 root client 的 max_retries 均为零；显式冲突 override 被拒绝。

这些是对方案关键片段和内存副本的验证，不是业务代码已实施或完整集成验收的证明。正式测试位置及实施前的外部读取方核查见修订后的 6.2 §7.8、§8。
