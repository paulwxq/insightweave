# doc 6.2 第三轮人工反馈处理

本轮修订 [6.2 解决方案](../6.2_db_deepagent最终答案兜底问题与补齐建议.md) 及 [详细设计 §13.3](../v4/5_db_deepagent详细设计.md) 的待实施契约，不修改生产业务代码。两项建议均采纳，没有拒绝项。

| 反馈 | 核实与决定 |
| --- | --- |
| 运行归属校验范围不明确 | 成立。此前片段只按当前 run_id 键取记录，再校验内部 payload，没有核对外层标识。采用严格语义：外层 run_id、request_id 分别与 Runner 本轮参数精确一致，任一缺失或不符都无效；不由字典键补齐。正常工具已写入 ctx.run_id、ctx.request_id，不改变正常提交。该检查不扩展为 tool_call_id/时间戳完整性校验。 |
| 重复解析及有效性判断可进一步收敛 | 合理，属于维护性改进。将布尔有效性函数替换为 normalize_valid_final_answer_payload()，一次 Pydantic 校验后直接返回归一字典或 None。normalize_final_answer_record() 先校验外层归属，再调用该函数。_finalize() 在评估之前只生成一次归一视图，供 _evaluate()、交付组装、_archive_run() 复用；后续不得修改视图或再次解析原始 payload。 |

原始提交继续仅供审计保存；归属不符也不改写 checkpoint 原值。外层 answer 键已有可序列化原值保留，缺失才用 `{}`。历史归档浅投影不承担当前运行校验职责。没有其他高优先级故障时，无效提交判 failed 并生成系统兜底；预算/持久化等优先级仍按原方案。归档条件 a 不变，条件 b 只能使用已通过归属与正文校验的归一视图。
