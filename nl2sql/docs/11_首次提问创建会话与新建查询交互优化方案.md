# 首次提问创建会话与新建查询交互优化方案

> 状态：2026-11-12 已完成 Claude 两轮设计审核、代码实施与测试，通过 Codex 两轮代码审核及 Kimi 两轮独立代码审核；已发现问题均已修复，无新增问题，审核循环结束。未提交 Git。
> 实施时逐项执行并验证；执行与 Agent 委派方式沿用用户指定方式，不自行创建额外 Agent。

**目的（Goal）：** 删除新建页的“开始查询”按钮；选库且就绪检查通过后直接开放输入，首次发送时创建会话并提交问题。

**实现方式（Architecture）：** 保留现有创建、提问两个后端接口，由 `useChat.ts` 顺序协调。先接管创建接口返回的真实会话，再替换新建页地址并提交首问；草稿由查询状态持有，避免创建失败或地址切换导致输入丢失。

**技术范围（Tech Stack）：** 现有 Vue 3、Vue Router、TypeScript 与 Node 内置测试；不新增依赖。

**依据（Spec）：** 用户确认的“校验通过即可输入，首次发送时创建会话”，以及 [doc 10](10_智能问数导航与会话首页设计方案.md) 中的来源绑定、页面归属、导航禁用与晚到回调隔离规则。本文实施后替代 doc 10 §3.3 中“保留显式创建会话”的交互决定。

## 1. 范围与约束

- 仅调整新建查询及首次发送流程。已有会话的查询、结果展示、历史分页、会话首页和历史搜索保持现有职责。
- 项目未上线，不做向下兼容或历史数据迁移。
- 不合并后端接口，不修改会话来源绑定、知识版本检查、限额、锁、持久化与 SDK 链路。
- 前端 readiness 成功只代表可以输入；创建接口和提问接口仍执行现有服务端校验，不能跳过。
- 不新增后台任务队列、全局草稿仓库、自动重试、创建幂等、取消请求或空会话自动清理。
- 选库及校验本身不创建会话、不执行查询。首次发送创建成功后、查询失败或用户离开时，仍可能留下空会话，沿用现有历史展示规则。

**审核重点：** 校验完成不产生会话；创建失败不丢草稿；路由接管不重置首问；重复发送不重复创建；离开或换预选后的旧回调不能继续提问。各项对应 §5 用例。

## 2. 页面行为

| 阶段 | 数据库选择 | 输入与发送 | 提示及动作 |
| --- | --- | --- | --- |
| 未选库 | 可选 | 禁用 | 请选择数据库 |
| 正在校验 | 可切换 | 禁用，保留草稿 | 正在检查数据源… |
| 校验失败或未就绪 | 可切换 | 禁用，保留草稿 | 显示现有具体原因 |
| 校验通过 | 可切换 | 可输入，非空且不超过 1000 个 Unicode 码点时可发送 | 数据源已就绪，请在下方输入问题 |
| 首次发送：创建会话 | 禁用 | 禁用，保留草稿 | 正在创建会话…；不展示 SQL 正在执行或查询计时 |
| 创建成功：进入提问 | 绑定会话后隐藏选择栏 | 沿用提交中状态 | 展示用户问题、正在执行及已耗时 |
| 创建失败 | 恢复可选 | 仍按 readiness 决定是否可输入，原问题保留 | 显示创建错误，不自动创建或提问 |
| 创建超时或网络失败 | 同上 | 原问题保留 | 会话创建结果尚未确认，请勿重复发送，可稍后从查询历史查看；不自动重试 |

补充规则：

- 校验成功仅响应式启用输入框，不自动创建、自动发送或强制抢焦点。
- 首问发送前，切换数据库保留已输入的文字，但立即禁用输入和发送，等待新数据库校验。旧校验结果不能开放新数据库的输入框。
- 创建与提问之间不出现可再次发送的交互窗口。侧栏新建、页头新建、查询历史、刷新对话，在“创建中或提问中”统一禁用。
- 父级“智能问数”、其他模块及浏览器导航仍允许离开；旧回调不得跳回页面、发送首问或改变新页面状态。
- 创建结果不确定时不自动查找同标题会话、不自动认领错误包内的定位 ID。用户手动再次发送可能创建另一空会话，此边界保持现状。
- 创建接口的 `timeout` / `network_error` 在 `useChat.ts` 创建错误分支统一显示“会话创建结果尚未确认，请勿重复发送，可稍后从查询历史查看。”：网络失败也可能发生在请求已送达之后，不能断言服务端未创建。不修改全局 `messages.ts` 的分码文案；其他创建错误仍用 `messageForNl2sql()`。

## 4. 按顺序实施

### 任务 1：先固定草稿与新建页的输入规则

**文件：** `format.ts`、`useChat.ts`、`QuestionInput.vue`、`QueryView.vue`、新增 `useChat.test.cjs`。

- [ ] 在测试中覆盖：未选库、校验中、blocked/error、ready，以及 ready 后换库等待新检查；目标行为在旧代码上应失败。
- [ ] `format.ts` 导出 `QUESTION_MAX = 1000`。发送入口与输入组件都按 Unicode 码点校验，不使用字符串 `.length` 判断问题长度。
- [ ] `useChat.ts` 增加 `questionDraft: Ref<string>`、`creatingSession: Ref<boolean>`、`busy: ComputedRef<boolean>` 和 `canCompose: ComputedRef<boolean>`。

状态定义：

```text
busy = creatingSession || askState === 'submitting'
canCompose = !busy && (
  无会话：selectedSourceId 非空且 readinessState === 'ready'
  有会话：现有 canSubmit 条件成立
)
```

- [ ] 原有 `canSubmit` 继续表示“已有会话允许提问”，不能直接放宽它并使底层 `ask()` 接受没有 session_id 的请求。
- [ ] `QuestionInput` 改为接收 `modelValue: string`，输入时发送 `update:modelValue`；`submit` 继续携带原问题，但删除发出事件后立即 `draft = ''` 的逻辑。移除 `draftEpoch` 及对应清空监听。
- [ ] `QueryView` 用 `v-model="chat.questionDraft.value"` 接线，输入禁用改为 `!chat.canCompose.value`。输入组件继续检查空白和超长；状态层发送入口再检查一次，防止重复事件绕过组件校验。
- [ ] 真正新建/打开其他会话时，由 `resetCurrentSession()` 清空草稿；仅选库、readiness 更新、历史对话框开关不清空草稿。
- [ ] 已有会话发送时，在底层 `ask()` 通过入口检查、准备实际调用 `submitQuery` 时清空所提交草稿；创建阶段和路由对齐失败阶段不清空。只清空仍等于本次问题的草稿，不让迟到回调删除后续输入。
- [ ] 落实根 doc 2 §7.2 对 `session_busy` 的输入保留约定：现行 `QuestionInput` 发出提交事件后立即清空，`ask()` 的忙碌拒绝分支也未恢复；本任务须先写在旧代码上失败的测试，再在当前请求归属仍有效且草稿为空时恢复本次问题，不覆盖新输入。查询超时不自动重发，已展示的问题仍保留在当前轮。
- [ ] 运行目标测试，确认输入规则和创建失败保留草稿的基础契约通过。

### 任务 2：实现首次发送协调，防止创建、跳转和提问互相打断

**文件：** `useChat.ts`、`QueryView.vue`、`useChat.test.cjs`、`pageGuard.test.ts`。

**对外接口：**

```ts
sendQuestion(question: string): Promise<void>
hasCurrentSession(sessionId: string): boolean
```

`hasCurrentSession` 仅在当前 ID、真实 `sessionInfo.session_id` 均与参数一致且详情已接管时返回 true；不能只比较地址字符串。

- [ ] 先写失败测试：首问严格按 `createSession → router.replace → submitQuery` 执行；双击/连续 Enter 只创建一次、提问一次；创建失败不提问且草稿不丢。
- [ ] 将现有 `createNewSession(): Promise<boolean>` 改为内部 `createSessionForFirstQuestion(): Promise<SessionInfo | null>`。保留错误分类及页面/请求/创建代检查；`timeout` / `network_error` 使用 §2 的创建结果不确定提示，不改全局错误映射。不在该函数中执行 `router.push`。成功返回真实 SessionInfo，失败或过期返回 null。
- [ ] `sendQuestion()` 同步检查 `busy`、输入条件、空白和长度，然后在第一次 await 之前置创建忙碌，快照原问题、来源、`requestToken`、创建代及页面归属。已有会话且当前地址已对齐时直接走现有 `ask(question)`，不再创建；已接管但地址未对齐的会话走下述路由补齐分支。
- [ ] 无会话时先调用创建接口。返回后再次检查归属；有效时将 `currentSessionId`、`sessionInfo` 设为返回值，接管绑定并检查现有 state/continuable 条件。接管不调用 `resetCurrentSession()`，不清草稿，不再额外请求详情和历史。
- [ ] 使用 `router.replace({ name: 'nl2sql-query-session', params: { sessionId }, query })` 将当前 `/query/new` 转为会话页。`query` 只保留经 `sessionBackTarget()` 规范化的 `home`，不保留预选 `source_id`。
- [ ] 这里使用 replace：首页到新建页仍为原有 push；新建页转为其刚创建的会话只是完成同一流程。浏览器后退应回到之前的首页筛选，而不是再次进入空白新建页。
- [ ] `QueryView` 的 sessionId 监听先调用 `hasCurrentSession(sessionId)`；对已接管的同一会话跳过 `openSession()` 和清空。直接打开、刷新或切换到其他 sessionId 仍走现有详情及历史加载。
- [ ] 不依赖 `router.replace()` resolve 就认定跳转成功：核对导航结果、实际路由的会话 ID 以及页面/请求/创建代归属。导航被阻止、取消或用户已离开时不得发出首问。
- [ ] 仅在仍属于当前流程且已有会话可提交时调用 `ask(原问题)`。创建忙碌转查询忙碌之间不能让第二次发送进入；同步完成状态交接，查询计时从实际进入 `ask()` 开始。
- [ ] 创建成功但导航失败时，保留已创建的真实会话和草稿，提示页面切换失败且尚未提交。再次手动发送先对齐该会话路由，再提问；不能再创建一个会话。用户也可从历史打开已有空会话。
- [ ] 创建接口失败沿用 `sessionsNotice`；会话已接管后的路由失败使用始终可见的 `askNotice`，不能把错误只写进已隐藏的选库栏。更换来源时清掉上一次创建提示，不让旧错误遮住新校验结果。
- [ ] 所有 await 后的成功、catch、finally 都检查归属；失效流程不接管会话、不跳转、不提交、不改草稿或忙碌。沿用 `pageGuard` 单调实例及创建代，不能把计数器重置为可能重复的值。
- [ ] `resetCurrentSession()` 和用户主动调用的 `invalidatePendingCreate()` 在作废旧请求时同步释放当前流程的 `creatingSession`；旧 finally 只在归属仍有效时收尾，不能清掉之后新发起的创建状态。否则同页更换预选会永久残留忙碌。
- [ ] 去掉无调用的旧手动创建导出及 `startNewConversation()`，先用 `rg` 确认调用点；不保留两套创建入口。
- [ ] 运行首问与隔离测试，确认旧例继续通过。

**路由复用依据：** 当前两个路由均使用同一个 `QueryView`，`App.vue` 的 `RouterView` 没有按 fullPath 设置 key，可复用组件实例；关键是阻止会话监听把刚接管的状态再次重置。禁止为这次改动添加 fullPath key、先跳转再在新实例自动发送，或把问题放进 URL、路由 history.state/localStorage 进行交接。

## 5. 测试与验收

### 5.1 自动化用例

新增 `useChat.test.cjs` 使用 `node:test`、现有 TypeScript `transpileModule` 和隔离模块加载，执行真实 `useChat.ts`、`pageGuard.ts`、格式化与提示代码；只替换 API 与路由边界。Vue 的 ref/computed 和生命周期使用真实运行时，可用 Vue `createRenderer()` 建立无浏览器的挂载/卸载宿主。每例隔离模块单例并清理计时器；不复制一份协调算法作为假实现，不依赖 `/tmp` 审核脚本。

| 用例 | 必须断言 |
| --- | --- |
| 校验与输入 | idle/checking/blocked/error 不可输入；ready 可输入；校验成功时 create/query 调用数均为 0 |
| 快速换库 | A ready 后换 B 立即禁用；A 的晚到结果不能使 B 可输入；B ready 后恢复；草稿保留 |
| 首次发送成功 | 来源正确；创建、地址替换、提问严格有序且各一次；提问使用返回的真实 session_id/source_id |
| 连续 Enter/双击 | 创建 await 前已经忙碌；不会重复创建或提交 |
| 创建明确失败 | 不导航、不提问；草稿原文保留；状态允许用户处理错误后手动再发 |
| 创建超时/网络失败 | 两个错误码均准确显示 §2 的创建结果不确定提示；不自动重试、不自动提问或认领定位 ID；草稿保留 |
| 创建后导航失败 | 不提问、不清草稿；已创建会话保留；重试只补路由与提问，不再创建 |
| 创建返回后状态不允许提问 | 不调用 query，展示既有阻断原因，不伪造可续聊状态 |
| 路由接管 | 真实页面监听不调用 openSession 重置首问；不额外加载历史；home 规范化保留，source_id 移除 |
| 旧创建归属 | 创建时离开、离开再进入、同页预选变化，以及创建中同组件导航到已有会话，迟到成功/失败/finally 都不接管、不跳转、不提交、不改当前草稿或忙碌；覆盖创建代失效与 resetCurrentSession 递增 requestToken 两条路径 |

| 已有会话 | 发送不创建；详情、历史、只读/失效/continuable 阻断规则继续生效 |
| 问题长度 | 空白不提交；1000 个非 BMP 字符可提交；1001 个不可提交；未通过校验不创建会话 |
