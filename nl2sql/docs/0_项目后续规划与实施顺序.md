# 项目后续规划与实施顺序

记录日期：2026-11-10

本文记录 InsightWeave 下一步的工作范围、建议实施顺序和各阶段完成标准，作为后续细化设计与实施的依据。本文为规划记录，不表示相关改造已经完成。

## 1. 工作范围

1. 删除 NL2SQL 中的 Streamlit 和其他旧前端模块，统一使用仓库根目录的 Vue 前端。
2. 在已完成的依赖升级基础上，充分利用 DeepAgents 及其他组件的新能力，细化 NL2SQL 设计，评估精简或删除旧 LangGraph 编排模块。
3. 调整统一前端中 NL2SQL 板块的入口位置与页面布局。
4. 明确项目模块边界，将三个数据库、统一前端、MetaWeave 和 NL2SQL 容器化，并建立按需更新的自动发布流程。

## 2. 建议实施顺序

将上述四项需求拆分为七个可独立验收的阶段：

| 顺序 | 要做的事情 | 完成标准 |
| --- | --- | --- |
| **1** | **清理 NL2SQL 旧前端**：删除 Streamlit、专用依赖、启动入口和过时说明。 | 统一 Vue 前端的查询、历史、结果展示和终止功能正常。 |
| **2** | **明确 NL2SQL 目标架构**：梳理 DeepAgents、旧父图和子图的职责，确定保留、替代、删除清单。 | 每项能力的归属与迁移方式明确。 |
| **3** | **实施 NL2SQL 内部重构**：利用已升级 SDK 的能力，逐项简化自研实现，退出不再使用的旧图。 | 固定验收题集及会话、证据、预算、终止等关键行为通过验证。 |
| **4** | **调整统一前端的 NL2SQL 入口与布局**：导航位置、历史会话、对话区、SQL 和结果展示。 | 主要用户操作顺畅，适配不同屏幕。 |
| **5** | **完成部署边界改造**：梳理模块依赖、环境配置、持久化目录、数据库初始化与迁移、任务停机收尾。 | 三个应用模块能独立构建和启动。 |
| **6** | **完成 Docker 部署**：容器化 PostgreSQL、Neo4j、Milvus，以及前端和两个后端，用 Compose 编排。 | 能在新环境部署，并验证数据迁移、持久化、重启和恢复。 |
| **7** | **建立自动发布流程**：按变更模块执行检查、构建、推送和部署，记录版本组合。 | 修改哪个模块就更新对应镜像，发布后自动检查，应用版本可回退。 |

## 3. 推进方式与边界

- 从第 1 阶段开始，同时在讨论中细化第 2 阶段。
- 第 3、4 阶段稳定后，再进入容器部署，减少反复调整镜像和发布配置的工作。
- 删除旧前端时保留 NL2SQL FastAPI 服务；CLI 可继续作为调试与验收入口。删除依赖前检查实际引用，历史升级证据保留归档。
- 区分旧的自定义 LangGraph 父图、子图与 LangGraph 运行底座。前者按能力迁移结果评估退役；DeepAgents 及现有持久化仍使用的运行底座继续保留。
- NL2SQL 当前已有 DeepAgents 0.7.34 等依赖的升级记录，后续重点是利用已升级 SDK 的能力简化实现；如需继续升级版本，应另行评估和验收。
- 暂按“三个数据库”指 PostgreSQL、Neo4j、Milvus 理解，具体数据库实例、逻辑库及迁移范围在部署设计阶段核实。
- 数据库镜像、版本升级和数据迁移单独管理，不随每次应用代码更新一起重建。持久化数据独立于应用镜像保存。
- 自动发布按受影响模块更新镜像，并记录整套服务的版本组合；数据库迁移与应用镜像回退需要分别设计。

## 4. 下一步

先落实第 1 阶段：确认统一前端覆盖所需功能，清理旧前端及相关依赖和说明，并验证现有 NL2SQL API 与统一前端正常。

第 2 阶段随后形成具体的架构设计与迁移清单，再据此拆分第 3 阶段的实施任务。
