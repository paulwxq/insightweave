# 新建查询入口数据库沿用与跳过页面检查方案

> 状态：代码与测试已完成，Codex R2 审核通过；实施总结见 §8。
> 日期：2026-11-16。
> 依据：当前前端、API v2 代码及用户对两个“新建查询”入口的要求。
> §1—§7 保留设计与验收约定；实际实施和验证结果以 §8 及审核记录为准。

**目标：**在正在对话的查询窗口中，点击顶部蓝色“新建查询”，自动沿用当前数据库并立即允许输入；点击左侧导航的“新建查询”，始终进入未选择数据库的新建页面。

**实现方式：**使用一次站内跳转的临时状态传递当前数据库，接收页面跳过单独的页面就绪检查。保留首次发送时创建会话的现有流程和后台检查，不修改 Agent 或 SQL 执行链路。

**技术范围：**Vue 3、Vue Router 4、现有 `useNl2sqlChat()`。

本文最初作为开发方案编写，后由 Hy4 实施、Codex 审核。下文中的函数与接线建议保留为设计记录，实施结果见 §8。

## 1. 入口行为

| 入口或操作 | 数据库选择 | 页面就绪检查 | 能否直接输入 |
| --- | --- | --- | --- |
| 正在对话的查询窗口，点击顶部蓝色“新建查询” | 沿用当前会话绑定的数据库 | 跳过 | 可以 |
| 从任意位置点击左侧导航“新建查询” | 清空，不带数据库参数 | 尚未选库，不检查 | 选择数据库并检查通过后可以 |
| 新建页面手动选择或切换数据库 | 使用新选择的数据库 | 按现有流程检查 | 检查通过后可以 |
| 直接打开带 `source_id` 的新建页面地址 | 仅预选该数据库 | 按现有流程自动检查 | 检查通过后可以 |
| 刷新带预选数据库的新建页面 | 保留地址中的预选 | 按现有流程自动检查 | 检查通过后可以 |

顶部沿用只适用于已经加载到当前会话绑定数据库的对话窗口。没有可用会话信息时，进入普通新建页，不猜测数据库、不选择列表第一项。

顶部蓝色“新建查询”只在会话页显示（使用现有 `onSessionPage` 判断）；在 `/query/new` 页面不渲染该按钮。新建页需要清空选择和草稿时，使用左侧入口。

本次不改变问数首页、查询历史对话框等其他“新建”入口的检查规则，也不把顶部沿用机制扩大为全局数据库记忆。

## 2. “沿用数据库”的含义

传递的是当前会话的 `sessionInfo.source_id`，不是账号密码或数据库连接对象。

- 当前数据库为 Orders，新建页面默认选择 Orders。
- 原会话的聊天记录、查询结果、任务及证据不带入新会话。
- 进入新建页面时不提前创建服务端会话；仍在首次发送问题时创建。
- 首次发送成功后进入新的会话地址，不继续使用原会话 ID。
- 新建页仍允许手动切换数据库；切换后恢复正常就绪检查。

## 3. 当前代码事实

以下路径以仓库根目录为基准。

| 文件和位置 | 当前行为 | 本次需要调整的原因 |
| --- | --- | --- |
| `frontend/src/modules/nl2sql/views/QueryView.vue`：`newQueryTo`、顶部 RouterLink | 目标为 `/query/new`，仅保留 `home`，未携带数据库 | 顶部入口没有沿用当前会话数据库 |
| 同文件：`route.params.sessionId` 监听 | 进入新建页时清空当前会话与 readiness | 沿用数据库必须在旧会话信息清空前取得，并在目标页重置后应用 |

| `frontend/src/modules/nl2sql/composables/useChat.ts` | `canCompose` 和首次创建流程要求已选库且 readiness 为 `ready` | 需要允许本次沿用选择直接达到可输入状态 |
| `frontend/src/components/AppSidebar.vue` | 固定跳转 `/query/new`，不带数据库参数 | 保留独立入口语义，并覆盖目标路由相同但页面仍有选库状态的情况 |

| `nl2sql/src/api/v2/runs.py`：`create_web_session()`、查询执行入口 | 创建会话及查询仍执行后台检查 | 本次保留；与页面单独调用 readiness 接口是不同层次 |

## 4. 跳过检查的准确范围

本次跳过的是新建页面单独发起的：

```text
GET /api/v2/sources/{source_id}/readiness
```

沿用入口进入新建页后，不显示“正在检查”流程，不要求用户点击检查或再次选择数据库，直接允许输入并发送问题。

后台创建会话、执行查询时仍按现有逻辑检查数据源与知识状态。现有完整检查有 30 秒成功缓存，但是否命中由后台判断；本方案不承诺后台永远不发生检查或网络访问。

如果数据库在两次操作之间停用或发生配置变化，首次发送可以按现有接口返回错误。前端正常展示错误，不自动重复提交，不新增后台跳过参数或长期有效的检查凭证。

## 5. 修改方案

### 5.1 顶部入口：取得数据库并传递一次沿用意图

在当前会话仍存在时读取 `chat.sessionInfo.value?.source_id`。普通站内点击携带该 `source_id` 进入 `/query/new`，并附带仅本次跳转使用的临时沿用意图。

数据库预选可以继续使用现有 `source_id` 地址参数；“跳过页面检查”不能仅由该参数决定，也不增加可永久复用的 `skip_check=true` URL 参数。

优先利用当前 `QueryView` 在会话页与新建页之间复用的组件状态保存临时意图。它只需要记录目标数据库和本次跳转归属；消费后清除，导航失败或离开组件也清除。不增加持久缓存、TTL 或新的状态管理框架。

接收流程必须协调现有两个路由监听：

```text
点击顶部新建
→ 保存当前会话数据库及本次沿用意图
→ 跳转 /query/new?source_id=当前数据库
→ 清空旧会话、结果和 readiness
→ 识别并消费本次沿用意图
→ 应用数据库选择，允许输入，不调用页面 readiness 接口
```

不能先调用 `checkReadiness()` 再覆盖状态，否则仍会发出用户希望省去的检查请求。也不能在应用沿用状态后，又被另一条监听重置。

**消费落点固定在现有 `presetSource` 监听内部**，即监听 `[apiReady.value, route.name, presetSource.value]` 的 `watch`：

- `apiReady` 未就绪时直接等待，保留本次沿用意图；就绪变化会重新触发同一监听。
- 目标路由为 `nl2sql-query`、临时意图属于本次跳转且 `sourceId` 匹配时，消费意图并调用 `chat.adoptSourceForNewQuery(sourceId)`，随后返回，替代原有 `chat.checkReadiness(sourceId)`。
- 沿用分支应在“预选数据库未变化则返回”的去重判断之前识别，避免有效意图被提前跳过；保留必要的旧创建流程作废处理。
- 没有匹配意图时，按原有普通预选、空选择流程处理；失配意图清除，不继续留给后续导航。
- 顶部点击处理只负责保存意图和导航；`onMounted` 不消费意图、不另行应用沿用状态。

当前会话重置监听声明在预选监听之前。实施时保持“先重置旧会话，再在预选监听中应用沿用”的执行结果，重置过程不得提前清掉待消费意图；通过真实组件及路由测试覆盖正常跳转和 `apiReady` 延迟场景，不把声明顺序当作可以省略测试的保证。

修饰键点击、复制链接、新标签页和刷新不依赖旧组件的临时状态；按普通带预选地址的流程自动检查即可。

### 5.2 useChat：增加小型入口方法

建议在现有 composable 中增加：

```ts
function adoptSourceForNewQuery(sourceId: string): void
```

该方法只供已确认的顶部沿用流程调用，职责为：

- 作废仍在途的旧 readiness 响应，复用已有 `readinessToken` 机制。
- 设置 `selectedSourceId`，清空上一轮检查错误与创建提示。
- 将前端输入就绪状态设为 `ready`，使现有 `canCompose` 和首次发送流程继续工作。
- 不调用 `getReadiness()`，不伪造 `ReadinessData`、检查项或检查时间；`readinessData` 保持为空。

手动选择仍调用原有 `checkReadiness()`。在 composable 中增加局部布尔标记 `sourceInherited`，初始为 `false`，由沿用方法设置为 `true`，在 `resetReadiness()` 和手动检查开始时清除；它只表示选择来源，不代表后台检查结果。

### 5.3 左侧入口：始终清空

保留 `/query/new` 的无参数目标，不继承当前会话数据库，也不消费顶部入口的沿用意图。

特别处理已经位于 `/query/new` 的情况：用户可能手动选过数据库，此时再次点击左侧入口，即使 Vue Router 判定为重复导航，也必须清空数据库选择和未发送草稿，恢复普通新建页。

采用一个小型辅助文件 `frontend/src/modules/nl2sql/newQueryReset.ts`，只提供当前已挂载 `QueryView` 的同步重置通知：

```ts
function registerNewQueryReset(handler: () => void): () => void
function notifyNewQueryReset(): void
```

- `QueryView` 注册重置回调，卸载时注销。返回的注销函数只注销自己的注册，不误清其他实例的回调。
- `AppSidebar` 复用已有 `onNewQueryPage`：普通站内点击、非忙碌且当前已在新建页时，同步调用 `notifyNewQueryReset()`，然后继续现有无参数导航；从其他页面进入时，由正常路由初始化负责清空。
- 接收回调确认当前在新建页后，清除顶部沿用意图、作废旧创建流程，并复用现有方法清空会话状态、草稿及 readiness。即使目标路由完全相同，也能执行清空。
- 通知只调用当前已注册的接收者；没有接收者就直接结束。**不保存待消费信号、不排队、不重放**，因此无需“下一 tick 过期”或 TTL 机制。
- 修饰键点击、新标签页不重置原标签页；继续遵守普通链接行为。

同步通知只负责清空页面状态，不能阻止后续无参数导航。Vue Router 判断重复导航时会比较查询参数：`/query/new?source_id=X` 跳到 `/query/new` 是正常导航，会移除 `source_id`（以及其他原有查询参数）；地址已为 `/query/new` 时，重复导航所缺少的页面重置由同步通知补齐。重置回调不额外调用 `router.replace()`，避免一次点击发起两次导航。

这只是左侧入口的局部接线，不建立通用导航事件系统。使用共同祖先 `App.vue` 提供回调也能实现，并非组件结构不允许 `provide/inject`；本文选择小型同步通知文件以避免额外修改 `App.vue`。

顶部和左侧都继续遵守现有忙碌限制，创建会话或执行查询中不切换流程。现有 `home` 返回地址处理保持原意；左侧入口不携带它。

### 5.4 提示文案

`SourceSelector` 原有 `readinessState === 'ready'` 主文案按以下关系替换，而不是额外叠加一条提示：

| 条件 | 主文案 |
| --- | --- |
| `ready` 且 `sourceInherited === true` | 已沿用当前数据库，可直接输入问题。 |
| `ready` 且 `sourceInherited === false` | 数据源已就绪，请在下方输入问题。 |

普通新建页继续提示选择数据库。顶部标题说明、空状态步骤及 `SourceSelector` 必须与可输入状态一致，不能仍要求“完成检查后开始提问”。

### 6.1 函数、状态与接入位置

以下名称作为实施建议，目的是让执行者能直接定位和接线；不要求复制已有逻辑或拆分更多文件。

#### QueryView.vue

- 修改现有 `newQueryTo`：在会话页且 `sessionInfo.source_id` 已取得时增加 `query.source_id`，保留现有规范化 `home` 处理。新标签页只能得到普通预选地址，不能获得跳过检查资格。
- 增加组件内变量 `pendingSourceInheritance`，保存 `{ sourceId: string, targetFullPath: string } | null`。`targetFullPath` 由 `realRouter.resolve(target).fullPath` 得到，用于与实际落地地址匹配，不写入 URL、历史状态或本地存储。
- 增加 `createFromCurrentConversation(event: MouseEvent): Promise<void>`，用于顶部按钮的普通站内点击：先处理忙碌限制及修饰键，再保存导航目标和数据库快照，设置临时意图，最后调用一次 `realRouter.push(target)`。普通点击需要阻止链接默认跳转；修饰键点击保留链接行为，不设置意图。
- 顶部 RouterLink 增加 `v-if="onSessionPage"`，采用 custom 插槽输出真实 `href`，绑定上述点击函数。该入口使用函数内的 `push`，不再同时调用插槽 `navigate`，避免一次点击导航两次；原 `guardNewQuery()` 的职责并入新函数后可移除。
- 增加 `clearPendingSourceInheritance(): void`。导航返回失败、抛异常、组件卸载或后续导航失配时清除对应意图；导航成功但 `apiReady` 未就绪时不能在 `finally` 无条件清除。导航结果只清理属于本次操作的意图，不覆盖后来的操作。
- 修改现有 `presetSource` 监听：按 §5.1 消费匹配意图，匹配时检查数据库和 `route.fullPath`；消费后调用 `adoptSourceForNewQuery()` 并返回。普通分支继续调用原有 `checkReadiness()`，不另起一套预选监听。
- 保留现有 `route.params.sessionId` 监听的会话加载、重置及首次创建接管逻辑；进入新建页时不能清掉仍待消费的顶部沿用意图。
- 增加 `resetNewQueryFromSidebar(): void`，仅在新建页、非忙碌时执行：清除沿用意图，调用 `chat.invalidatePendingCreate()`、`chat.resetCurrentSession()` 和 `chat.resetReadiness()`。`resetCurrentSession()` 已清空草稿、结果及当前会话，不再复制这些字段重置代码。
- 在 setup 中调用 `registerNewQueryReset(resetNewQueryFromSidebar)`，保存返回的注销函数并交给 `onUnmounted`；不等 `apiReady` 才注册。
- 修改现有 `headerMeta`：沿用可输入时显示与 §5.4 一致的提示。现有 `guideStep` 根据 `ready` 到第 3 步的逻辑可复用。
- 在 `SourceSelector` 接线处增加 `:source-inherited="chat.sourceInherited.value"`，保留 `@select="chat.checkReadiness"`。

#### useChat.ts

- 在选源状态附近增加 `const sourceInherited = ref(false)`。
- 增加 `adoptSourceForNewQuery(sourceId: string): void`，复用 `resetReadiness()` 清空旧状态、使旧检查令牌失效，再设置选源、`readinessState = 'ready'` 和 `sourceInherited = true`；不调用 API、不创建会话。
- 修改 `resetReadiness()`，同步设置 `sourceInherited = false`；修改 `checkReadiness()`，在发起检查前同步设置为 `false`。
- 在 `useNl2sqlChat()` 的返回对象中增加 `sourceInherited`、`adoptSourceForNewQuery`，供页面读取和调用。
- `canCompose`、`createSessionForFirstQuestion()`、`sendQuestion()` 继续使用现有就绪判断及首次发送流程，本需求无需为它们增加“跳过后台检查”分支。

#### AppSidebar.vue 与 newQueryReset.ts

- 修改侧栏现有 `guardNewQuery(event, navigate)`：保留忙碌限制；普通左键、无修饰键、未被阻止且 `onNewQueryPage` 为真时，先调用 `notifyNewQueryReset()`，再继续一次 `navigate(event)`。不要在此增加 `router.replace()`；修饰键等情况只保留现有链接处理，不发送清空通知。
- 新文件导出 `registerNewQueryReset(handler: () => void): () => void` 和 `notifyNewQueryReset(): void`。用一个模块内当前回调引用即可：注册替换当前引用，注销时核对是否仍是自己的注册，通知时同步调用当前回调；没有回调直接结束。无需响应式信号、队列或定时器。

#### SourceSelector.vue 与测试

- 在 `defineProps` 中增加 `sourceInherited: boolean`，按 §5.4 修改现有 `ready` 文案分支；不新增第二个提示条、不修改数据库选择事件。
- 更新 `SourceSelector.test.cjs` 的公共挂载参数，普通场景显式提供 `sourceInherited: false`；增加沿用为 `true` 及切回 `false` 的文案断言，保留现有错误展示测试。

| 场景 | 必须满足 |
| --- | --- |
| Orders 对话页点击顶部新建 | 新建页已选 Orders，能立即输入；页面 `getReadiness()` 调用增量为 0 |
| 顶部沿用时 `apiReady` 延迟就绪 | 就绪前不消费意图、不检查；就绪后由预选监听应用沿用一次，仍为零页面检查；不被旧会话重置覆盖 |
| 沿用后首次发送 | 使用 Orders 创建新会话一次，并在新会话提交；不向旧会话发送、不携带旧历史 |
| 任意页面点击左侧新建 | 地址不带数据库参数，页面未选库 |
| 从带 `source_id` 的新建页点击左侧新建 | 同步清空后仍执行一次无参数导航；导航完成后地址不含 `source_id`，刷新不恢复预选、不触发该库的页面检查 |
| 已选库的新建页再次点击左侧新建 | 即使路由重复，也清空选库、草稿及旧错误 |
| 无 QueryView 时发出重置通知，之后再进入查询页面 | 通知不残留、不重放，不误清后来页面；旧实例注销不清除新实例注册 |
| 沿用 Orders 后手动改选其他库 | 对新库按现有流程检查；检查前不能发送 |
| 沿用就绪与普通检查就绪 | 前者显示沿用主文案，后者显示原主文案；不叠加两种主文案 |
| 旧检查响应晚到 | 不覆盖新的沿用数据库、手动选择或清空状态 |
| 刷新、直接打开预选地址 | 不保留跳过检查资格，正常自动检查 |
| 顶部导航失败、后续改用左侧入口 | 不残留沿用意图，不错误恢复数据库 |
| 当前会话信息尚未加载 | 不猜测数据库，进入普通新建页 |
| 新建页与会话页的顶部按钮 | 新建页不渲染；会话页显示并保留既有忙碌限制 |
| 修饰键点击左侧入口 | 保留链接行为，不清空原标签页选择或草稿 |
| 页面创建中或执行中 | 顶部和左侧保持既有忙碌限制 |
| 后台首次发送拒绝或创建失败 | 按现有流程展示错误，不自动重复创建或提交 |
