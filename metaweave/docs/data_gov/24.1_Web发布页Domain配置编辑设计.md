# 24.1 Web 发布页 Domain 配置编辑设计

状态：**主体已实施**（后端单测 `tests/unit/test_domain_config_api.py`；前端为发布页编辑按钮与弹窗）。配合 [25.1 Web 采集 SQL 样例生成步骤改造设计](25.1_Web采集SQL样例生成步骤改造设计.md) 增加的 Domain PUT 源行锁已实现，覆盖当前文件读取、校验、原子写回及写回后核验。

发布页 b 组 `domain` 行增加「编辑」按钮，弹出窗口编辑受管产物 `output/<source_id>/<job_id>/domain/db_domains.yaml`，保存时原子写回该文件。采集仍由 [21.1](21.1_Web采集Domain生成步骤与数据源描述编辑改造计划.md) 生成这份 YAML；发布仍由 [21.2](21.2_Domain产物加载平台库设计.md) 读取它并整份替换平台库 `table_domain`。本篇只增加发布前的人工修订，不把编辑保存写成一次发布。

交互参照发布页 `dim_value` 的行内编辑按钮（[22.2](22.2_Web发布DimValue到Milvus设计.md) §8）和 `rel` 的编辑弹窗：产物就绪才可打开，保存只改作业目录里的文件。

## 1. 目标与范围

### 1.1 需求对应

| 需求 | 落点 |
|---|---|
| `domain` 选项后增加编辑按钮，样式对齐 `dim_value` | §4 |
| 弹窗展示 YAML：标题为只读的库名与库描述；表格可编辑 domain 名称、domain 描述、归属该 domain 的表 | §4.2 |
| 可新增 domain（名称 + 描述），再为它添加表；一个 domain 可有多张表 | §4.3 |
| 每个 domain 可增加表、删除表；同一张表可加入多个 domain | §4.3 |
| 添加表时下拉框可搜索 | §4.3 |
| 保存写回 `db_domains.yaml` | §5 |

### 1.2 明确不做

- **保存不写 `table_domain`。** 平台库映射只在用户再次勾选 `domain` 并发布时，按 [21.2](21.2_Domain产物加载平台库设计.md) 整份替换。编辑保存之后、重新发布之前，库里仍是上一次发布的映射。
- **不改 domain 采集。** 重跑 domain 步骤会重写 `db_domains.yaml`，覆盖本次手工编辑。并发规则用文件指纹拦住过期保存（§5.3）。
- **不重跑、不改写 rel 产物，也不为 Rel 新鲜度增加提醒或指纹。** 编辑保存不改 domain 步骤行。§5.3 新增的源行锁只约束 Domain PUT 的写回并发，不追改 Rel 产物。之后若直接发布 rel，预检仍只比较 rel 行与 domain 行的时间（[23.2](23.2_Web发布Rel到Neo4j设计.md) §6.2），锁内 `DomainResolver` 读的是当前 YAML，`JOIN_ON` 仍来自旧 rel 产物。结果是 Table 的 `table_domains` 用新 YAML，边用旧关系。本阶段接受这个组合，不改 23.2 的新鲜度判据，不在 rel 产物里记录 YAML 哈希，保存成功时也不提示用户重跑 rel。需要两边一致时，由用户自行重跑 rel 后再发布。另有一条硬失败：保存成 `domains: []` 后，`verify_domain_artifact` 会因 `domains` 为空失败；rel 采集准备链和 rel 发布预检都调用它，重跑或发布 rel 会被「Domain 产物 domains 为空」拒绝。只是每个 domain 都没有表时，列表仍非空，不走这条拒绝。
- **不编辑 `llm_inference`。** `max_domains_per_table` 原样保留写回。生成提示词用它限制「一张表最多归入几个主题」，发布侧 [21.2](21.2_Domain产物加载平台库设计.md) §2 已经不核对该上限。编辑器同样不拦截超出上限的归入，只在界面提示。
- **不提供自由输入表名。** 表只能从本作业 MD 清单的候选里选择，避免保存出 [21.2](21.2_Domain产物加载平台库设计.md) 发布会整次拒绝的三段式。
- **不改发布校验规则。** 空 `tables` 的 domain 发布时仍跳过、不产生行；全部 domain 都没有表时，发布仍失败，文案仍是「Domain 产物没有表映射，请检查产物后重试」。编辑器允许保存这种文件，并在保存前提示。
- **不改数据库信息。** `database.name` 与 `database.description` 都只展示。库描述在采集 domain 时确定，发布页编辑不能改它，也不能改 `job_info.db_desc` 和 `db_source_info.description`。重跑 domain 时，生效描述仍按 [21.1](21.1_Web采集Domain生成步骤与数据源描述编辑改造计划.md) 取 `db_desc`（空则回退数据源描述），并覆盖 YAML 里的库描述。保存只改 `domains`。

## 2. 现有产物与发布约束

受管文件：`output/<source_id>/<job_id>/domain/db_domains.yaml`。样例结构：

```yaml
# 数据库业务主题配置
database:
  name: orders
  description: ...
llm_inference:
  max_domains_per_table: 3
domains:
- name: 用户管理
  description: ...
  tables:
  - orders.public.users
```

`tables` 每一项是三段式 `库名.schema.表名`。同一张表可以出现在多个 domain。MD 清单 `md/manifest.json` 的 `files` 与之对应，文件名是三段式加后缀，例如 `orders.public.users.md`。

发布解析（`backend/profile_loading/domain_loader.py` 的 `read_domain_rows`）要求：

- `database.name` 去空白后等于登记 `db_name`。
- 每个 domain 的 `name`、`description` 去空白后非空。
- 同名 domain 的描述必须相同；描述相同则不是冲突。
- `tables` 缺失或 `[]` 时跳过该 domain，不入库。
- 表名 `split(".")` 后恰好三段，首段等于登记库名，次段在 `selected_schemas` 内。
- `库名.schema.表名.md` 必须在同一作业 MD 清单里，且该文件仍是普通文件。
- 同一 `(schema_name, table_name, domain_name)` 重复出现只保留一行。

编辑器的读取、候选和保存校验与上面对齐。保存成功的文件，下一次 domain 发布不应因为结构不合法被拒绝。唯一仍会在发布失败、但编辑允许的情况是：没有任何一张表被归入任何 domain（§1.2）。

`database.description` 不写入 `table_domain`。它由采集写入 YAML，发布页编辑原样保留。采集时的生效描述另存在 `job_info.db_desc`；重跑弹窗的预填来自作业列表里的这个字段。本篇不改这两处，避免出现「YAML 里是新手写描述、重跑却用旧 `db_desc` 盖回去」的分叉。数据源基本信息卡上的 `db_source_info.description` 同样不随这次保存变化。

## 3. 数据形态

弹窗与 API 使用结构化 JSON，不把 YAML 原文交给前端编辑。

```json
{
  "fingerprint": "<sha256 hex>",
  "database": {
    "name": "orders",
    "description": "..."
  },
  "max_domains_per_table": 3,
  "domains": [
    {
      "name": "用户管理",
      "description": "...",
      "tables": ["orders.public.users"]
    }
  ]
}
```

- `fingerprint`：当前 `db_domains.yaml` 原始字节的 SHA-256。保存时原样带回，用于乐观并发（§5.3）。
- `database.name`、`database.description`：只读，来自当前文件。描述按文件中的字符串返回，不去空白、不补默认句。文件没有 `description` 时返回 `null`。
- `max_domains_per_table`：只读展示，来自文件里的 `llm_inference.max_domains_per_table`；缺失或不是正整数时接口返回 `null`，写回时仍保留文件中的原值，不替用户改这个字段。
- `domains[].tables`：有序字符串列表，元素为三段式。界面展示时去掉库名前缀，显示 `schema.表名`；写回仍用完整三段式。

候选表接口：

```json
{
  "tables": [
    {"id": "orders.public.users", "label": "public.users"}
  ]
}
```

`id` 是写入 YAML 的值，`label` 是下拉框与表格里的展示。清单文件名去掉 `.md` 后，须同时满足：恰好三段、首段等于当前登记 `db_name`、次段在登记 `selected_schemas` 内，才进入候选。登记库名可以事后修改，旧作业清单里的 `旧库名.schema.表名.md` 不得进入候选，否则 PUT 会接受、发布时被 `read_domain_rows` 的首段校验拒绝。

## 4. 页面

### 4.1 编辑按钮

`frontend/src/views/PublishView.vue` 的 `domain` 行，在步骤名右侧增加与 `dim_value` / `rel` 相同的 `nj-step-edit` 按钮。

出现与可点条件与 `dim_value` 一致：`domain` 在可选步骤内，且本次预检 `publishable`。采集未成功、产物缺失或整作业不可发布时不提供编辑。发布进行中按钮禁用。

点编辑不勾选、也不取消勾选 `domain`。

### 4.2 弹窗结构

新组件 `frontend/src/components/DomainConfigDialog.vue`。

自上而下：

1. **标题区**：库名与库描述，都是只读文本。库描述为空时显示「采集时未写入库描述」。这里不能进入编辑。
2. **提示**：一张表可以属于多个 domain；`max_domains_per_table` 有值时显示「采集时建议每表不超过 N 个主题，保存不强制」。
3. **表格**，三列：
   - domain 名称（可改）
   - domain 描述（可改）
   - 该 domain 的表：标签列出已选表，每个标签可删除；行内「添加表」打开可搜索下拉
4. **「新增 domain」**：追加一行空的名称、描述和空表列表。
5. **每行「删除 domain」**：去掉整行及其表归属。`_未分类_` 没有特殊保护，可以改名、清空表或删除。
6. **底部**：取消、保存。取消丢弃未保存修改。保存中禁用重复提交。

打开时请求 §5.1 的配置与候选表。读取失败时弹窗只显示错误，不给半份可编辑数据。

### 4.3 编辑规则（前端先拦，服务端再验）

- domain 名称、描述去首尾空白后不能为空。
- 去空白后的 domain 名称在本次列表内唯一。
- 同一 domain 内同一张表只出现一次。跨 domain 允许重复，这是本需求的正常情况。
- 添加表的下拉只含候选接口返回的表，按 `label` 做子串过滤（不区分大小写）。已在当前 domain 中的表从该下拉移除，仍可被其他 domain 选中。候选很多时下拉可滚动，过滤在前端完成，不另做搜索接口。
- 表列表为空的 domain 可以保存。若所有 domain 都没有表，保存按钮仍可用，点击后先确认：「保存后的文件没有任何表归属，发布 domain 时会失败」。用户确认后才提交。domain 列表被删空时同样先确认，并加上「之后重跑或发布 rel 会因 domain 列表为空失败」。
- 一张表当前归属的 domain 个数大于 `max_domains_per_table` 时，在该表标签旁显示提示，不阻止保存。

## 5. 接口

路由挂在现有 publishing router（前缀 `/api/data-sources`），实现放在新文件 `backend/profile_loading/domain_config_api.py`。目录解析用 `resolve_domain_output_dir`。读文件用 `backend/profile_loading/file_utils.read_regular_text`（返回状态和正文，与 rel、dim 编辑相同）。不要复用 `domain_loader._read_regular_text`，那个函数抛异常并只返回字符串。不读 CLI 的 `output/domains/db_domains.yaml`。

### 5.1 端点

| 方法与路径 | 用途 |
|---|---|
| `GET /{source_id}/collection-jobs/{job_id}/domain-config` | 读当前 `db_domains.yaml`，返回 §3 的配置对象 |
| `GET /{source_id}/collection-jobs/{job_id}/domain-config/tables` | 返回 §3 的候选表。同样要求 `db_domains.yaml` 存在且为普通文件，缺失时 404，不因只读清单而放行。通过后再读同一作业 `md/manifest.json`，按 §3 过滤，并确认对应 `.md` 仍是普通文件 |
| `PUT /{source_id}/collection-jobs/{job_id}/domain-config` | 按 §5.2 校验后写回 YAML。请求体为 §3 的对象（含打开时拿到的 `fingerprint`） |

三个端点都要求：数据源存在且启用、作业属于该源、`domain` 步骤行存在且 `last_status = success`。不要求整作业当前可发布；预检不过时前端本来就不会打开弹窗。步骤行缺失、`last_status` 不是 `success`（含 `failed` 与 `running`）、产物不是普通文件，或文件不存在：404 `domain_config_output_missing`。这与 rel 编辑的「行缺失或非 success」同一口径。

GET 配置做结构校验，任一条失败即 400 `domain_config_invalid`，`details.reason` 为短原因。弹窗只进入错误态，提示重跑 domain 步骤后再编辑，不返回可编辑正文，也不在这个接口里改文件。校验到条目为止，不查表名三段式、登记 schema 和 MD 清单；那些留给 PUT 的候选集。

容器与库名：

- 空白文件、YAML 无法解析、顶层不是对象、`database` 不是对象、`domains` 不是列表。
- `database.name` 去空白后必须等于当前登记 `db_name`。采集后改过登记库名时，旧文件在这里被拒绝。名称在弹窗里只读，不能留到 PUT 再拒，否则用户看到的是「请求里改过库名」，却改不了这个字段。

条目（与 `read_domain_rows` 的条目口径对齐，但不做表名成员校验）：

- 每一项必须是对象。`name`、`description` 去空白后非空。去空白后的 `name` 在这一份列表里必须唯一；出现第二次就整份 400，描述相同也不合并。这不是目录里有两个文件：`db_domains.yaml` 只有一个，同名是 `domains` 列表里的两条。采集不按名称去重，模型若返回两个同名主题会原样落盘。这种文件发布可以过（同名同描述会合成一批表映射），编辑不支持，请重跑 domain。本弹窗保存不会写出同名条目。
- `tables` 缺失视为 `[]`。值为 `null`、不是列表，或元素不是字符串：整份 400。不检查字符串是否为三段式、是否仍在候选集。用户可以在弹窗里删掉已失效的表再保存。

候选接口与 PUT 在逐表比对之前先读 MD 清单。目录不可解析、`manifest.json` 缺失、不是普通文件、JSON 无法解析，或 `files` 不是非空、无重复的 `.md` 文件名列表：400 `domain_config_invalid`，`details.reason` 为「MD 采集清单缺失或不合法，请重跑 md 后再编辑」。不使用 404 `domain_config_output_missing`，那个码只表示 domain 步骤行缺失、不是 `success`，或 `db_domains.yaml` 缺失；这里 domain 文件可以是好的。也不把清单故障变成空候选集，否则 PUT 会把文件里每一张表都报成未知表。

md 重跑会先清空 MD 目录再生成。生成失败时清单已经不在，domain 步骤行仍可能是 `success`。清单合法但过滤后一张表都不剩，候选接口返回空列表；这和清单缺失不同，PUT 里不在该列表中的表仍按未知表拒绝。

### 5.2 保存校验与写回

Domain PUT 在读取当前文件及其指纹之前，先在同一平台库会话中通过 `lock_db_source_row(session, source_id)` 取得数据源行锁；取得锁后核对数据源与作业归属、Domain 步骤行状态。整次校验、渲染、临时文件写入、`os.replace` 及写回后核验都在持锁期间进行；文件替换完成前不得提交或结束持锁事务。GET 与候选表只读接口不要求持锁。整次校验任一条失败都不写文件。

1. **指纹**：请求里的 `fingerprint` 必须等于当前文件原始字节的 SHA-256（完整十六进制，不截成 rel 编辑的前 16 位）。GET 与 PUT 各自对同一次二进制读取的字节计算指纹并解析 YAML；PUT 先核对指纹，通过后直接解析该份字节，不再重新读取当前文件。不要先按文本解码再 `encode`，否则换行或编码差异会变成假的 409。不等则 409 `domain_config_regenerated`，优先于 YAML 解析错误；文案说明文件已被重跑或另一次保存改过，请关闭后重新打开。写回后的核验读取仍保留。不按 `job_info.updated_at` 做版本：编辑保存不更新步骤行，步骤时间看不出两次手工保存之间的覆盖。
2. **库名**：`database.name` 去空白后必须等于登记 `db_name`，否则 400 `domain_config_invalid`，原因是「库名与登记库名不一致」。这是防请求被改写的复查；文件里的库名已在 GET 拒绝，正常弹窗不会把只读库名提交成另一个值。
3. **库描述**：请求里的 `database.description` 必须与当前文件中的值相同（文件没有该键时，请求必须是 `null`）。不同则 400 `domain_config_invalid`，原因是「库描述不可在发布页修改」。写回使用文件里的原字符串，不采用请求体里的文本。
4. **domains**：必须是列表，允许空列表。每项必须有去首尾空白后非空的 `name`、`description`。去空白后的名称重复一律拒绝，不合并，与描述是否相同无关。这里的描述是 domain 描述，不是库描述。校验通过后，`name` 与 `description` 换成去掉首尾空白的值。写出和自检都用这份值，不再使用请求里的原文。表名不在这里改。
5. **tables**：先按上一段检查 MD 清单；清单不合法时直接返回该 reason，不进入逐表比对。清单合法时，每项必须是字符串，且等于本次候选集中的某个 `id`。这样同时满足三段式、库名、schema 范围和 MD 清单四条发布规则。同一 domain 内重复的 `id` 拒绝，不静默去重，避免用户以为加了两次。跨 domain 重复允许。不在候选集中的表才报未知表。
6. **写回顺序与字段**：保留文件中的 `llm_inference` 对象原样放回；文件里没有该键时写回也不新增。`database.name` 用登记库名，`database.description` 用文件中的原字符串；文件没有该键时不新增。`domains` 按请求顺序写出，不重排。每个 domain 固定三个键：`name`、`description`、`tables`。`name` 与 `description` 是第 4 步去掉首尾空白后的值，`tables` 按用户在界面中的顺序写出。不更新 `job_info.db_desc`，也不更新 `db_source_info.description`。
7. **原子替换**：先用 `mkstemp(prefix=".tmp-domain-", dir=domain 目录)` 写临时文件，`os.chmod(tmp, 0o644)`（`mkstemp` 默认是 `0600`），再 `os.replace` 到 `db_domains.yaml`。替换成功后临时名消失；写入或替换失败时在 `finally` 中删除仍在的临时文件。残留不影响发布预检（`check_domain_output_ready` 只认 `db_domains.yaml`），采集重跑也会清掉目录顶层。渲染复用 `domain_generator.LiteralDumper`：`yaml.dump(..., Dumper=LiteralDumper, default_flow_style=False, allow_unicode=True, sort_keys=False)`。多行描述写成 `|` 块标量，与采集写盘一致；普通 `yaml.dump` 会把同一段描述折成双引号字符串，重跑前后风格会跳。`safe_load` 两种写法都能读回，这只对齐风格。文件首行保留注释 `# 数据库业务主题配置`。替换前确认临时文件能被 `yaml.safe_load` 读回，且读回的 `domains` 与第 4 步那份去掉首尾空白后的结果一致，不与带空白的原始请求比较。写盘失败返回 500 `domain_config_write_failed`，原文件保持不变。
8. **成功响应**：返回写盘后的配置对象和新的 `fingerprint`。不更新 `job_info` 的 domain 行，不写 `table_domain`，不写 `publish_info`。

保存后的发布行为不变：下一次发布 domain 仍调用现有 `read_domain_rows`。编辑器不复制一套入库逻辑。

### 5.3 并发

- 用户 A 打开弹窗后，作业重跑 domain 覆盖了文件：A 保存时若 Domain 步骤正在运行，按步骤未成功拒绝；重跑已完成且文件指纹改变，则返回 409，必须重新打开。若保存先完成，后续重跑仍可覆盖这次人工编辑。
- 用户 A、B 同时保存：两次 PUT 在同一数据源行锁上串行。先写回者改变文件指纹；后获得锁者在锁内读取新文件并返回 409，不会发生双方都通过旧指纹后互相覆盖。
- Domain PUT 从读取指纹到 `os.replace` 完成都持有源行锁，与同样持锁的 Domain 发布、Rel 编辑及 [25.1](25.1_Web采集SQL样例生成步骤改造设计.md) 已实现的 SQL 结束复查串行。SQL 在同一次持锁事务内完成最终指纹复查与 `finish_step`，保证复查通过后、标记成功前没有受管 Domain PUT 落盘。锁不覆盖绕过 API 直接修改工作区文件的行为；编辑保存仍不更新 domain 步骤行，已完成的发布也不会自动重做。

## 6. 与发布、采集的关系

| 动作 | YAML 中的 domain | YAML 中的库描述 | `job_info.db_desc` 与数据源描述 | `table_domain` | domain 步骤行 |
|---|---|---|---|---|---|
| 采集 domain 成功 | 生成或覆盖 | 按当时生效描述写入 | 写入 `db_desc`；勾选同步时更新数据源描述 | 不变 | `success`，`updated_at` 更新 |
| 本篇保存 | 按请求覆盖 | 原样保留 | 不变 | 不变 | 不变 |
| 发布 domain 成功 | 只读 | 只读，不入库 | 不变 | 按文件中的 domain 整份替换 | 不变 |
| 重跑 domain | 整份覆盖，含手工改过的 domain | 按 `db_desc` 重新生成 | 仍以 `db_desc` 为准 | 不变 | `updated_at` 更新 |

因此：只点编辑里的保存，改的是 YAML 里的 domain 列表。库描述、作业上的 `db_desc`、数据源描述都不变。平台库 `table_domain` 也要等再次勾选 `domain` 并发布才替换。

重跑 domain 会覆盖手工编辑的 domain，并用 `db_desc` 重写库描述。弹窗不阻止重跑；过期保存由 409 拒绝。要改库描述，回到采集阶段编辑描述后重跑 domain，不在本弹窗里改。

## 7. 错误码

在 `backend/api/errors.py` 注册，响应形如 `{code, message, details}`。

| HTTP | code | 何时 |
|---|---|---|
| 404 | `domain_config_output_missing` | 步骤行不存在或 `last_status` 不是 `success`，或 `db_domains.yaml` 缺失 / 不是普通文件 |
| 400 | `domain_config_invalid` | domain YAML 不可解析，MD 清单缺失或形状不合法，或请求不满足 §5.2 的结构与候选校验。`details.reason` 说明第一条失败原因 |
| 409 | `domain_config_regenerated` | `fingerprint` 与当前文件不一致 |
| 500 | `domain_config_write_failed` | 临时文件写入或替换失败 |

前端：GET 的 400 只显示错误态，不渲染表格。PUT 的 400 留在弹窗内并保留正在编辑的内容。409 提示重新打开，丢弃本次草稿。404 关闭可编辑区并显示缺失说明。

## 8. 测试

后端单测覆盖 `domain_config_api`：

- GET 把样例 YAML 转成 §3 的 JSON，表名保持三段式，指纹稳定。空白文件、YAML 无法解析、顶层不是对象、`database` 不是对象、`domains` 不是列表、`database.name` 与登记库名不符、domain 项不是对象、名称或描述为空白、名称重复、`tables` 不是字符串列表时，GET 返回 400 且无 `domains` 正文。`tables` 缺键按空列表返回。不因表名不在候选集而拒绝 GET。
- `llm_inference.max_domains_per_table` 缺失或不是正整数时，GET 返回 `null`；PUT 写回保留文件中的原值，不补默认整数。
- 候选表只来自 MD 清单，且去掉不可用文件、非三段式、首段不等于当前登记库名、schema 不在登记范围内的条目。清单缺失、不是普通文件或形状不合法时，候选接口与 PUT 都返回 400，reason 指明重跑 md；PUT 不把这些表报成未知表。
- domain 步骤行缺失或 `last_status` 不是 `success` 时，三个端点都返回 404。
- PUT 写回后再次 GET，domain 顺序、表顺序与请求一致，库描述文本与保存前相同，`llm_inference` 仍在。多行的 domain 描述在文件中是 `|` 块标量。`job_info.db_desc` 与 `db_source_info.description` 不变。
- 同域重复表、未知表、空名称、空的 domain 描述、改库名、改库描述、指纹过期，分别拒绝且原文件字节不变。
- domain 名称或描述带首尾空白时，PUT 成功；文件和响应里都是去掉首尾空白后的值，不因自检与原始请求不一致而返回 500。
- 允许同一张表出现在两个 domain；允许某个 domain 的 `tables` 为空。
- 写回文件能被现有 `read_domain_rows` 解析；空表 domain 不产生行；有表时行与编辑结果一致。
- 替换失败时返回 500 `domain_config_write_failed`，原文件字节不变。把替换收成可单独替换的函数，测试里替换它。
- 保存 `domains: []` 后，`verify_domain_artifact` 返回失败，原因含「domains 为空」。
- MD 清单合法、但过滤后没有候选表时，候选接口返回 200 和空列表，不是 400。
- 并发 PUT 使用同一旧指纹时，第二个请求须在源行锁内看到首次写回的新内容并返回 409；验证从指纹读取到 `os.replace` 始终持锁。与 SQL 结束复查并发时，PUT 先落盘则 SQL 指纹复查失败；SQL 先复查则须等其 `finish_step` 完成后 PUT 才能落盘。

前端无单测框架时，用构建与一次手工路径验收：打开弹窗、搜索并添加表、把同一张表加入第二个 domain、删除表、新增 domain、保存、确认磁盘 YAML 变化，再发布 domain 后查询 `table_domain` 与文件一致。
