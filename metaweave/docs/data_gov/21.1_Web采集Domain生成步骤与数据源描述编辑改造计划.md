# 21.1 Web采集Domain生成步骤与数据源描述编辑改造计划

状态：**已实施**（代码、测试与平台库迁移已完成；前端人工清单 F01–F03 待浏览器验收，见 §10）。

本篇在 Web「数据采集与画像」中激活 `--generate-domains --description "…"` 步骤（后台步骤名 `domain`）：页面可勾选执行、弹窗展示本作业 `db_desc` 优先且为空时回退数据源 `description` 的生效描述、可编辑并选择在执行时同步到数据源，产物写入当前作业目录。Domain 启动时把本次执行已确定、拟传给 LLM 的描述保存到 `job_info.db_desc`。CLI 的 `--generate-domains` 不做任何修改，两套产物互不读取（§13.3）。

## 2. 目标与范围

### 2.1 需求到设计映射

| 需求 | 落点 |
|---|---|
| 1. 页面可勾选 `--generate-domains --description "…"` | §8.1、§8.2 |
| 2. 描述优先取本作业 `job_info.db_desc`，为空时取当前数据源 `db_source_info.description` | §5.3、§8.3 |
| 3. 点击 `--description` 链接弹窗显示并可修改 | §8.3 |
| 4. 弹窗勾选"执行时同步到数据源描述"，Domain 执行时与本作业 `db_desc` 同事务写入 | §5.3、§7.1、§8.3 |
| 5. job 级描述存储（`db_desc`），无弹窗编辑时也保存本次执行已确定的描述快照 | §4、§5.3 |
| 6. job_info 的 step_name 为 `domain` | §6 |
| 7. 在 md 之后执行；md 产物就绪才可勾选 | §5.2、§6、§8.2 |
| 8. 写入 `output/<source_id>/<job_id>/domain/`，生成逻辑与脚本一致 | §5.4、§5.5 |
| 9. CLI 不修改，允许 Web 改造后 CLI 产物不再被使用 | §13.3 |

### 2.2 明确不做

- **不改 CLI**：`metaweave metadata --generate-domains` 保持现状，仍写 `output/domains/db_domains.yaml`（非受管路径）。唯一例外：共享组件 `_build_md_context` 的读取加固不跟随符号链接（§13.2），CLI 正常输入（普通文件）行为不变。
- **不做前端就绪接口**：不新增"md 就绪"查询接口，不向作业列表返回文件级就绪字段（§8.2 说明粒度）。
- **不写 manifest.json**：domain 目录只落 `db_domains.yaml`（§5.5）。
- **不做并发定制防护**：多用户同时定制同一作业描述时后执行者覆盖（用户确认，§13.1）。
- **不做 md 变更复查**：不引入 md→json 式的运行标识复查（§13.2，含事实澄清与可选补充成本）。
- **不改发布侧代码**：发布准入与候选列表按既有汇总口径自动包含 `domain` 行（§6.4）。
- **不做 domain 产物的下游消费**：当前 Web 流程没有 rel/cql 步骤，本改造只负责生成、登记与展示；消费属后续文档（如后续把 rel 引入 Web）。
- **不在弹窗保存时写库**：弹窗保存只写入页面已保存状态，不发任何写库请求；新作业此时尚无 `job_id`，描述与可选的数据源同步都在 Domain 执行时提交（§5.3、§8.3）。
- **准备链失败与同请求阻断暂不落库**：与 json、md 的现状相同，`start_step` 之前的失败和阻断都不写 `job_info`。有 `job_id` 时直接写成 `failed` 已记在 [100 备忘录](100_备忘录.md) 第 3 条，等 Domain 接入完成后再统一改，本篇不实施（§5.6）。

- **数据源描述**：`db_source_info.description` 可空（`models.py:44`）；API 校验规则为去首尾空白、空→NULL、≤1000 字符（`backend/api/schemas.py:60-66`）；页面已能拿到该值（`getDataSource` 返回 `DataSourceListItem.description`，页面 :360 已展示）。

## 4. 数据模型与平台库迁移

`JobInfo` 增加一个可空列：

```python
db_desc: Mapped[str | None] = mapped_column(Text, nullable=True)
```

语义：仅 `step_name = 'domain'` 的行会写该列，保存**本次 Domain 执行已确定、拟传给 LLM 的描述快照**（成功进入生成时两者相同；若在 LLM 调用前失败——清理目录、构造生成器等——该值已提交但未实际送达 LLM），包括从数据源描述回退取得的值；其他步骤行恒为 NULL。首次执行前没有 domain 行；执行时两处都没有描述才允许该列为 NULL，并沿用生成器的无补充说明路径（§5.3）。不新增 CheckConstraint（自由文本，NULL 合法）。

平台库（metaweave）由开发直接执行迁移（沿用 doc 16 惯例：应用不自动建表；先核对、再备份、后执行、再核验；备份表名按实际日期）：

```sql
-- 平台库（metaweave），开发环境直接执行；备份表名按执行日期（示例：job_info_bak_20261007）。
-- 1) 执行前核对：列是否已存在（已存在则跳过第 3 步，防止重复执行报错）
SELECT column_name, data_type, is_nullable
  FROM information_schema.columns
 WHERE table_schema = 'public' AND table_name = 'job_info' AND column_name = 'db_desc';

-- 2) 备份
CREATE TABLE public.job_info_bak_<YYYYMMDD> AS SELECT * FROM public.job_info;

-- 3) 新增可空列
ALTER TABLE public.job_info ADD COLUMN db_desc text NULL;

-- 4) 执行后核验：列存在、data_type=text、is_nullable=YES；既有行 db_desc 均为 NULL（期望 0）
SELECT column_name, data_type, is_nullable
  FROM information_schema.columns
 WHERE table_schema = 'public' AND table_name = 'job_info' AND column_name = 'db_desc';

SELECT count(*) AS db_desc_non_null FROM public.job_info WHERE db_desc IS NOT NULL;
```

`backend/jobs/repository.py` 的 `start_step` 增加带哨兵的可选参数 `db_desc`（`def start_step(session, job_id, source_id, step_name, db_desc: str | None | object = _UNSET) -> None`）：不传（既有全部调用方）不触碰该列；传入字符串或 `None`（写入 NULL）时 INSERT 分支写入新行、UPDATE 分支覆盖既有行——`None` 不能同时表示"不改列"与"写入 NULL"，必须用哨兵区分。**末尾现有的一次 `session.commit()` 保持为唯一提交点，不新增"延后提交"机制**：`platform_session` 的 Session 在离开 `with` 时关闭，commit 之后写入的修改会随会话关闭回滚丢弃；因此 domain 按 §5.2 第 6 步的固定顺序，把可选的数据源描述更新放在同一 session 内、`start_step` **之前**（挂起未提交），由这一次 commit 一并提交两表，失败一起回滚。不得先提交 running 行，再单独更新数据源描述。本篇不新增在 `start_step` 之前直接写 `failed` 的函数。

## 5. domain 步骤服务

新增 `backend/data_sources/domain_step_service.py`，对外暴露：

```python
run_domain_step(config_path, source_id, job_id=None, *,
                domain_description=_UNSET, sync_domain_description=False)
```

- `domain_description=_UNSET`（哨兵）：`_UNSET` 表示本次会话未保存过描述，按 §5.3 从数据库解析；携带时为 API 层已校验的非空规范字符串（§7.1）。
- `sync_domain_description: bool = False`：为 True 时按 §5.2 第 6 步③在同一事务更新 `db_source_info.description`。API 契约保证 true 必与显式 `domain_description` 成对出现（§7.1）；直调服务若出现"True 且 `domain_description` 为 `_UNSET`"，在入口抛 `DbStepConfigError`（与 `job_id` 缺失同类的入口参数校验，不登记）。
- 两参数由编排层原样透传：路由（§7.1 的 `model_fields_set` 判定）→ `start_collection_job` → `start_db_collection` → 本函数，三处签名各加这两个可选参数；仅 domain 步骤消费，本次 `steps` 不含 domain 时两参数被忽略、不改写任何描述字段。

无工作区、源禁用、工作区归属失败、MD 未就绪、目录或快照的受控 `ValueError`、LLM 配置错误，都抛 `DbStepConfigError` / `SourceDisabledError`（与 db/ddl/json/md 同一套映射），在 `start_step` 之前返回，不写 domain 行；**平台库连接或读取异常**（按 §5.2 返回失败字典，`results` 为空时映射 503 `platform_unavailable`）与**准备阶段故障**（抛 `DomainPreparationError`，映射 503 `domain_preparation_error`）不在此列。同请求里 MD 已经失败时，编排层在调用本函数之前阻断（§6）。

### 5.1 步骤名与产物

- 步骤名常量 `DOMAIN_STEP_NAME = "domain"`（写入 job_info 的 step_name；前端展示标签仍为 `--generate-domains --description "…"`）。
- **日志步骤名同为 `domain`**（与 job_info.step_name 一致，不采用 `generate-domains`），分两类进程：
  - **共同前提（两种进程都必需）**：服务入口按 md 同款在开头调用 `set_operation_step("domain")`，`metaweave/core/metadata/execution.py` 的 `OPERATION_STEP_MAP` 增加 `"domain": "domain"`——该函数直接下标取值，缺键会在任何登记之前 `KeyError`；Web 采集在 API 进程内执行本函数，同样需要这条。Web 步骤不加入 `METADATA_OPERATIONS`，同步把 `tests/unit/metaweave/metadata/test_execution_shared.py` 的 `set(OPERATION_STEP_MAP) == set(METADATA_OPERATIONS)` 断言放宽为 **`set(METADATA_OPERATIONS) <= set(OPERATION_STEP_MAP)`**（方向为 ops ⊆ map：每个 operation 必须有映射，map 允许额外包含 Web 步骤；写成 `map <= ops` 会因 domain 不在 ops 中而失败）。
  - **script profile（`configs/logging.yaml` 顶层）**：增加 `domain_filter`（`allowed_steps: ['domain']`）与 `domain_file`（`logs/script/domain.log`），并加入 root handlers——只服务 script 场景（测试、脚本直接调用 `run_domain_step`）；CLI `--generate-domains` 仍写 `logs/script/generate_domains.log`，不受影响。
  - **API 进程（Web 实际路径）不写 `logs/script/domain.log`**：`configure_logging("api")` 只装配 `x_profiles.api`，script 顶层 handlers 不装载；`/api/data-sources` 请求内的记录按 `x_modules` 归属进 `logs/backend/metaweave.log`（无请求上下文的记录回落 `logs/backend/platform.log`）。不为 domain 增设 API 侧专属日志文件；验收按 §10 A14 分进程写。
- 产物：`output/<source_id>/<job_id>/domain/db_domains.yaml`（文件名与 CLI 产物同名，目录不同）。

### 5.2 准备链与依赖判定

`job_id` 必填（与 md 相同："新作业 Domain 单选没有任何工作区可用"）。函数入口处 `job_id is None` 时立刻抛 `DbStepConfigError("同一作业的 MD 产物未就绪；请先执行 MD 或指定已有 job_id")`，不写行。

准备链先执行步骤 1 的入口校验，再按操作来源分为平台库读取段与本地文件/配置段。**不得把平台库不可用归入配置错误，也不得把本地文件/配置错误归入平台库故障**：

- **入口校验段**（下列步骤 1，在 `platform_session` 和本地文件/配置段之前）：按 md 入口（`md_step_service.py:249-265`）分别处理异常：UUID 规范化的 `ValueError` → `DbStepConfigError(str(exc))`；`load_main_config_snapshot` 的 `ValueError` → `DbStepConfigError(str(exc))`，其他 `Exception` → `DbStepConfigError(f"主配置加载或校验失败（{type(exc).__name__}）")`；`load_platform_settings_from_env` 的 `ValueError` → `DbStepConfigError(str(exc))`。这些错误不进入后续平台库或本地段的异常兜底，均不写 domain 行；平台设置加载的其他异常不在此处额外改写为 400。
- **平台库读取段**（会话 1，无凭据，只读；`with platform_session` 内只放数据库操作：源校验查询、`assert_workspace_owner`、md 步骤行读取——对应下列步骤 2 与步骤 3 的行检查）：调用 `assert_workspace_owner` 时，**单独捕获 `(WorkspaceMissingError, WorkspaceSourceMismatchError)` 并抛 `DbStepConfigError(str(exc))`**（与 `md_step_service.py:279-282` 相同），使不存在或不属于该源的 `job_id` 都按配置错误处理。段外层再按 `except DbStepConfigError: raise`、`except ValueError: 转 DbStepConfigError`、**`except Exception`（如 `SQLAlchemyError`）→ 对齐 md（`md_step_service.py:306-312`）返回 `_failure(started, f"平台库连接或读取失败（{type(exc).__name__}）")`**（不带 `job_id`、不写 domain 行）；编排层按 `_UNREGISTERED_FAILURES` 前缀既有语义处理——本次 `results` 为空时整体 503 `platform_unavailable`，已有结果时该步计入 failed（HTTP 200）。平台库兜底**只覆盖这一段**。
- **本地文件与配置段**（在平台库段之后执行，不依赖数据库连接：`resolve_md_output_dir` 与 `*.md` 枚举、`resolve_domain_output_dir`、快照构造、LLM 预检——对应下列步骤 3 的文件检查、4、5）：`except DbStepConfigError: raise`（含 md 文件就绪判定）；**受控的配置/路径/产物校验异常（`ValueError` 家族）转 `DbStepConfigError(str(exc))`**；**其余异常（`OSError`/`PermissionError`/`RuntimeError`、LLM 预检的非受控故障如 `ImportError`、未预期的程序错误）→ 抛 `DomainPreparationError(f"Domain 准备阶段故障（{阶段}：{type(exc).__name__}）")`**（阶段取值：md 目录枚举 / domain 目录解析 / 快照构造 / LLM 预检），不转 400「请求不合法」，也不落入平台库兜底。**捕获处按阶段记录 ERROR 日志，只记「阶段 + 原始异常类型」两个安全字段，不带 `exc_info`、不写异常原文**（原文可能带配置细节/凭据：`llm_service.py:179-186` 导入失败分支同款只记类型，doc 15 §8 验收 3 要求后端日志不含密码与 API Key）——仅靠 API 边界日志只能看到封装后的类型。`DomainPreparationError` 为 `PlatformUnavailableError` 子类（定义在 `backend/data_sources/domain_step_service.py`）：编排层既有 `except PlatformUnavailableError` 分支直接覆盖（分支注释同步说明 domain 服务会直接抛其子类）——`results` 为空时重抛，API 侧新增更具体的 handler（按 MRO 先于 `platform_unavailable` 命中）返回 **503 `domain_preparation_error`「Domain 准备阶段故障，请查看日志」**（不回显异常原文，同 `platform_failed` 的边界日志原则）；已有结果时以封装后的消息计入该步 failed（HTTP 200）。
- 源属性类检查（存在性、`db_type`、连接字段、`is_active`、md 行 success）判定为不合法时，在平台库段内直接抛 `DbStepConfigError`（源禁用抛 `SourceDisabledError`）。

准备链各步骤及其受控判定点：

1. 规范化 `source_id` / `job_id`；加载主配置快照（`load_main_config_snapshot`）与平台设置。此步独立执行，异常按上述入口校验段转换；主配置读取失败不进入本地段的 `DomainPreparationError` 分支。
2. 源校验：存在、`db_type == 'postgresql'`、连接字段完整、`is_active`；`assert_workspace_owner` 校验工作区归属。源不存在、源禁用、工作区不存在、工作区不属于该源，都在这里抛错并结束；工作区两类异常先按上述局部捕获转成 `DbStepConfigError`，不得落入平台库故障兜底。
3. **依赖判定（与 md 检查 json 同款）**：
   - md 步骤行存在且 `last_status == success`；
   - md 目录（`resolve_md_output_dir(source_id, job_id)`）下至少有 1 个 `*.md` 文件。
   - 两者任一不满足，抛 `DbStepConfigError`：**"同一作业的 MD 产物未就绪；请先执行 MD 或指定已有 job_id"**（与 md 步骤的 JSON 依赖消息同句式）。
   - `resolve_md_output_dir` 自身抛错（目录符号链接、越界）转 `DbStepConfigError(str(exc))`。
   - md 目录内的非常规 `*.md`（符号链接/FIFO）**跳过并告警、不参与生成**：只要仍有一个普通 `.md` 即继续；全部候选都非常规（或目录为空）时按「MD 产物未就绪」拒绝。生成器读取侧另有 `O_NOFOLLOW` 加固（§13.2）保证被跳过文件的内容不进入提示词；不采用 md 产出核验式的整步拒绝——那是 md 对自己产物的规则，不施加到 domain 的读入侧。
   - 不做清单核对、不做内容级校验（md 步骤自己的 `manifest.json` 不在 domain 的判定范围内）。
   - 同请求里 MD 已经失败时，不会进入这里：编排层先按 §6 阻断，本函数不被调用。
4. `resolve_domain_output_dir(source_id, job_id)` 解析产物目录（§5.5）；复用 `build_managed_output_snapshot` 构造无凭据快照（`database.database` 已替换为登记库名，`DomainGenerator` 据此写 `database.name`）。受控 `ValueError`（符号链接/越界/非对象节点）转 `DbStepConfigError`，其他异常按准备阶段故障（`DomainPreparationError`）；不清理、不写入该目录，不构造 `DomainGenerator`。
5. **LLM 预检**：`resolve_module_llm_config(config, "domain_generation.llm")` + 构造 `LLMService`——**只构造 `LLMService`，不得在此构造 `DomainGenerator`**（其构造期立即读取 `yaml_path` 旧文件，须等 §5.4 清理后再构造）。失败（如缺 API Key，`llm_service.py:37-56`）属受控 `ValueError`，转 `DbStepConfigError`，消息用异常原文；其他异常按准备阶段故障处理（`DomainPreparationError`，阶段=LLM 预检）。预检不通过则不进入会话 2，不解析描述，不同步数据源描述。

会话 2（锁下；只有准备链已通过才进入）：

6. 会话 2 内按固定顺序执行（同一 session、同一事务；`try` 包住整个 `with`，`with` 内只做检查和 `start_step`）：①取源行锁（`lock_db_source_row`）并复查 md 步骤行仍为 success。锁返回 `None` → 抛 `DbStepConfigError("未找到指定 source_id 的数据源")`（编排层转 404）。复查 md 不再是 success → 在 `with` 内抛与步骤 3 相同的 `DbStepConfigError`，不解析描述、不同步、不调用 `start_step`。②按 §5.3 用锁下读数（请求值、本作业 domain 行、数据源行）解析生效描述。③若 `sync_domain_description=True`，**先**更新 `db_source_info.description` 与 `updated_at`（直接改锁下返回的行对象；同一 session 内挂起、不提交）。④**再**调用 `start_step(..., db_desc=本次生效值)`（§4 哨兵语义），由它末尾唯一的一次 commit 一并提交步骤行与数据源描述两表，失败一起回滚。若抛 `StepAlreadyRunningError`，返回带 `job_id` 的 failed 结果，行保持 running，对齐 md（§9）；挂起的源描述更新随会话关闭回滚。⑤commit 成功并离开 `with` 之后才用该描述调用 LLM（§5.4）。本篇不实现 md 在 `start_step` 周围的「作业状态登记失败（类型）」兜底；该缺口与失败落库一起记在 [100 备忘录](100_备忘录.md) 第 3 条，本阶段不处理（§5.6）。

### 5.3 描述解析与落库

输入三方：POST 请求字段 `domain_description`（仅当本次会话在弹窗中保存过才携带，§8.4）、`job_info.db_desc`（本作业上次执行已确定的描述）、`db_source_info.description`（数据源登记描述）。另有布尔字段 `sync_domain_description`，控制是否在本次 Domain 执行时同步到数据源。

规范值规则：弹窗保存的描述及显式提交的 `domain_description` 必须是字符串；`strip()` 后不能为空、长度不得超过 1000 字符，空串、纯空白、显式 `null` 或非法类型均拒绝。本次会话未保存过时请求省略此字段，不把缺省等同于提交空值。数据源原有 `description` 可为 NULL；两处数据库描述均为 NULL 且请求未携带时，沿用生成器的无补充说明路径。

生效规则（**请求携带的已保存值优先；未携带时只有 db_desc 为空才读取数据源 description**）：

| 请求携带 | 执行前 db_desc | 生效描述（拟传给 LLM） | 执行后 db_desc |
|---|---|---|---|
| 非空值 v | 任意 | v | v（覆盖） |
| 空串/纯空白/显式 null | 任意 | 拒绝请求，不执行 | 不变 |
| 未携带 | 非空 v | v | v（保持本次使用值） |
| 未携带 | NULL | `db_source_info.description` | 写入本次读取的描述；源描述为 NULL 时仍为 NULL |

- "请求携带"按 Pydantic v2 `model_fields_set` 判定；显式空值在 API 层 422，未携带才走数据库回退。`sync_domain_description=true` 只允许与显式非空 `domain_description` 同时提交，否则 422。
- 锁下从库里读出的描述（`job_info.db_desc`、`db_source_info.description`）先 `strip()`，strip 后为空按 NULL 处理。这样写入的 `db_desc` 与传给 `generate_from_context(user_description=…)` 的参数相同。生成器只在拼提示词时再 `strip()` 一次（`domain_generator.py:139-146`）；提示词里还有任务说明和表结构摘要，A06 不拿 `db_desc` 和整段提示词比较。
- 解析与两表写库在会话 2 的源行锁下同一事务内完成（固定顺序见 §5.2 第 6 步）；不勾选同步时只写 `job_info.db_desc`，勾选时同事务写两表。源描述在锁下重新读取，避免准备与执行之间发生变化；提交成功后的内存值即本次执行确定的描述（成功进入生成时与 `user_description` 参数相同）。
- 该字段与同步标志仅当本次执行包含 domain 步骤时消费；未包含时不得修改这两个描述字段。
- 步骤随后生成失败时 `db_desc` 保留为**本次已确定的值**（供重跑查看）；若勾选了同步，数据源描述也已在生成前提交，不随 LLM 失败回滚。
- `start_step` 之前的准备链失败不写 domain 行，已有 `db_desc` 与数据源描述都保持原值。

### 5.4 生成与核验

- **先清理、后构造（顺序不可交换）**：先 `clean_top_level_files(domain_dir)`（与 ddl/md 同款"每次完整集合"），再构造 `DomainGenerator`。`__init__` 会立即 `_load_yaml()` 读取 `yaml_path` 现有文件——先构造会让旧文件产生影响：旧 `database.description` 在生成描述为空时作为回退值、其他遗留键随内存 `db_config` 整体写回并入新产物；旧 `llm_inference.max_domains_per_table` 会进入本次提示词（`_build_prompt` 从 `db_config` 读取），该字段本身由 `write_to_yaml` **重写**为固定值（`domain_generator.py:360`），不随旧值保留。
- 构造只传 `config=快照` / `yaml_path=domain_dir/"db_domains.yaml"` / `md_context_dir=md_dir`：`md_context_mode` 省略即为参数默认 `name_comment`（该项没有配置项，省略即可）；`md_context_limit` 省略（None）由生成器自读配置 `domain_generation.md_context_limit`（缺省 100）。Web 不引入 CLI 的 `--md-context-mode` / `--md-limit` 覆盖。
- **md 读取加固（§13.2）**：`DomainGenerator._build_md_context` 以 `O_NOFOLLOW`/`O_NONBLOCK` + `fstat` 常规文件复核读取 `.md`；符号链接与 FIFO 等非常规文件跳过并告警、不进入提示词；全部被跳过时生成前即以「md 摘要为空」失败（不会静默产出空域）。
- 调用顺序：`generated = generator.generate_from_context(user_description=生效描述)`；`generator.write_to_yaml(generated)`（`write_to_yaml` 必须接收生成结果，与 CLI 调用一致，`metaweave/core/metadata/execution.py:290-293`）。生成异常（LLM 调用/响应解析/写盘）→ `finish_step(FAILED)`，消息 `Domain 生成失败（{异常类型}）`（不静默留在 running）。
- **成功判定**（用户确认）：`db_domains.yaml` 存在且为普通文件（拒符号链接）→ YAML 可解析为对象 → `domains` 为非空列表。不逐项校验域内容，不做重渲染比对。
- 失败与状态写回错误的消息格式、锁下 `finish_step`、`SourceRegistrationMissingError` 处理均对齐 md 步骤（`md_step_service.py:359-418`），仅去掉 md 变更复查与清单写入。

### 5.5 产物目录 resolver

`metaweave/core/clean_targets.py` 增加 `resolve_domain_output_dir(source_id, job_id)`：`output/<source_id>/<job_id>/domain/`，与 `resolve_md_output_dir` 同款——两级 UUID 规范化、逐级拒绝符号链接、项目根边界与预期路径核对；清理与写入共用。

### 5.6 准备链失败与同请求阻断暂不落库

本篇与 md 依赖 json 的现状相同：

- 准备链在 `start_step` 之前的失败：依赖或配置类抛 `DbStepConfigError`（源禁用抛 `SourceDisabledError`）；平台库连接或读取失败返回「平台库连接或读取失败（…）」失败结果；准备阶段故障抛 `DomainPreparationError`（§5.2）。三类都不写 `job_info`。
- 同请求里 MD 已经失败时，`_BLOCK_MESSAGES` 阻断 Domain：不调用 `run_domain_step`，不清理 domain 目录，不写 domain 行。结果里的失败消息是阻断文案（§6），不是准备链的「MD 产物未就绪」。

因此前面的步骤已经成功、Domain 只出现在本次结果里时，`rollup_job_status` 看不到这次失败，作业汇总仍可能是 success，发布入口仍会打开。

有 `job_id` 时把这类失败直接写成 `failed`，并让本次选中的依赖步骤一并落 `failed`，已记在 [100 备忘录](100_备忘录.md) 第 3 条。同条还记下：`start_step` 登记过程中的其他异常，本篇不复制 md 的「作业状态登记失败（类型）」兜底。两件都等 Domain 接入完成后再与 json、md 统一改。本篇不新增 `record_failed_step`，不在准备链失败或阻断时写 domain 行。

## 6. 编排：白名单、顺序与失败传播

1. **白名单**：`collection_run._SUPPORTED_STEPS` 增加 `("domain",)`；`normalize_collection_steps` 与循环兜底两处报错文案改为"当前仅支持 db、ddl、json、md、domain 步骤"，循环兜底保留原有"（收到: {step}）"后缀（`collection_run.py:163-166`）。
2. **顺序**：`_ensure_managed_step_order` 追加 `_move_after(chosen, "domain", "md")`。偏序为 ddl→json→md→domain；只做"后继移到锚点紧后"，不引入全序重排。同请求未勾选 md 时 domain 保持传入位置，直接读既有 md 产物（即使同请求重跑了 ddl/json，也不会自动重跑 md，domain 使用既有 MD；前端按 §8.2 显示提示，不新增编排规则）。
3. **失败传播（与 md 依赖 json 相同）**：`_BLOCK_MESSAGES` 增加 `(MD_STEP, DOMAIN_STEP)`，文案为「本次请求的 MD 未成功，Domain 未启动；如需使用已有 MD 产物，请单独重跑 Domain」。`_blocked_by_same_request_upstream` 对 domain 走现有通用扫描即可：本次选了 md 且 md 已在 `results` 中失败，则阻断。不要把 md 那段「未选 json 时改看 ddl」的特例复制到 domain；本次没选 md 时不阻断，由 §5.2 检查既有 MD 产物。阻断只把失败记入本次 `results`，不调用 `run_domain_step`，不写 domain 行。json、md 的阻断与准备失败仍然不登记。
4. **作业新建与发布准入零改动**：domain 不创建作业（`job_id` 必填）；请求首步骤为 domain 且无 `job_id` → `DbStepConfigError`（400），不写行。阻断和准备链失败都不写 domain 行，汇总只看表里已有的步骤行；生成阶段 `finish_step` 写下的 `failed` 才会让整作业 failed。采集页「下一步发布」和发布候选列表仍按 `job_status === 'success'` 过滤。`rollup_job_status`、发布服务和前端发布判断都不改。准备失败不落行导致汇总仍为 success 的缺口见 §5.6，本篇不补。

## 7. API 契约

### 7.1 创建采集作业（扩展）

`CollectionJobCreateRequest`（`backend/api/schemas.py:322-326`，`extra="forbid"` 不变）增加：

```python
domain_description: str | None = None
sync_domain_description: StrictBool = False
```

- `domain_description` 省略表示从数据库读取；显式传入时必须是 `strip()` 后非空且不超过 1000 字符的字符串。显式空串、纯空白、`null`、非字符串及超长均为 422。`sync_domain_description=true` 必须同时显式携带合法的 `domain_description`，且本次 `steps` 包含 `domain`，否则 422；未勾选同步时默认 false。
- **上述 422 需要校验器落地，`str | None = None` 声明本身不承担校验**（`model_fields_set` 只区分"传了/没传"，不会拒绝显式 `null`）：在 `CollectionJobCreateRequest` 增加——①`field_validator("domain_description", mode="before")`（只在字段被提供时执行；省略时校验器不运行、默认 `None` 保留）：显式 `null`、非字符串、`strip()` 后为空、>1000 → `ValueError`，通过后存 `strip()` 规范值；②`model_validator(mode="after")`：`sync_domain_description is True` 时要求 `"domain_description" in self.model_fields_set` 且值非空、且 `"domain" in self.steps`，否则 `ValueError`。两者都在请求解析阶段生效（FastAPI 422），先于路由与执行逻辑。该组合已在本项目 Pydantic 2.12 实测：省略通过、显式 `null`/空白/超长拒绝、sync 配对校验生效。
- 路由判定 `"domain_description" in payload.model_fields_set` 后以哨兵传给 `start_collection_job`；执行层经 `start_db_collection` 透传到 `run_domain_step`（三处签名各加 `domain_description` 与 `sync_domain_description` 两个可选参数，服务签名见 §5）。仅在 domain 步骤消费；不包含 domain 时不得改写 `job_info.db_desc` 或数据源描述。
- 若同步标志为 true，**本次作业创建接口就是描述回写入口**：Domain 准备链通过后，在一次平台库事务中写 `job_info.db_desc` 和 `db_source_info.description`；不调用源库，不另发 PATCH。平台库写入失败时两处一起回滚，按步骤状态写入故障的既有规则返回；LLM 生成失败时不撤销已成功提交的描述快照。
- `CollectionJobCreateResponse` 不变；`results` 中 domain 行 `step = "domain"`。

### 7.2 重跑弹窗所需的作业描述读取

- `CollectionJobItem` 增加可空 `domain_description`：取同一 `(job_id, 'domain')` 行的 `db_desc`，没有该行或值为 NULL 时返回 NULL；不得返回其他作业的值。组装落点在 `backend/jobs/listing.py`：`JobStepRecord` 增加 `db_desc` 字段、`_record()` 读取该列、`assemble_collection_jobs` 输出 `domain_description`（`backend/data_sources/repository.py` 不参与该字段组装）。数据源 `description` 已在列表响应的 `source` 中，前端据此按 `domain_description ?? source.description ?? ''` 预填弹窗。
- 新作业尚无 `job_id`，只用当前数据源描述预填。页面不需要提前创建 `job_info` 行，也不新增弹窗保存 PATCH；描述写库时机统一为 §7.1 的 Domain 执行阶段。

## 8. 前端交互

### 8.1 步骤定义

- `STEP_GROUPS` 中 'b' 组的 domain 条目：**id 由 `'domains'` 改为 `'domain'`**（与后台 step_name、results 行、`storedSelection` 的 `job.steps` 匹配对齐）；label 保持 `--generate-domains --description "…"`，其中 `--description "…"` 为可点击链接（§8.3）。描述链接文本只在步骤列表单独渲染；执行结果区（`resultGroups`，现直接取 `step.label`）使用不含动态值的基础标签，结果标题保持稳定。
- 该条目的可用性由 §8.2 动态计算（不再用静态 `enabled: false`）；**可用性函数只对 domain 生效**——dim-config、rel、cql、sql-rag 继续按各自静态 `enabled: false` 不可勾选。`chosenSteps`、`storedSelection`、`selectAvailable`、分组全选等既有逻辑经该函数判定时，除 domain 外结果与现状一致。

### 8.2 可勾选规则（前端信号粒度）

可勾选条件 = **本次选择含 `md`**，或（重跑模式（URL 带 `job_id`）且该作业 `steps` 含 `'md'`）。前者由同请求顺序保证 md 先执行；后者由既有作业的 md 产物支撑（页面已通过作业列表加载 `steps`，零新接口）。

- 不满足时：勾选框禁用（disabled 样式），步骤区显示提示（与 `jsonWithoutDdlHint` / `mdWithoutJsonHint` 同容器）：
  - 新作业未勾 md："Domain 依赖同作业已成功的 MD 产物；请同时勾选 MD，或从已有 MD 的作业重跑。"
  - 重跑作业无 md："该作业没有 MD 步骤，无法运行 Domain；请先执行 MD。"
- 重跑模式下勾选了 domain 但未勾选 md、且本次勾选了 ddl 和/或 json 时：显示使用流程提示（同容器，不阻断执行）："Domain 读取既有 MD 产物；本次 DDL/JSON 不会更新 MD——如需基于本次 DDL/JSON 重新生成 MD，请同时勾选 MD。"该行为是 §6.2 顺序规则的既定结果，不新增编排规则。
- 失去可用性时自动清除已被勾选的 domain（避免出现可提交但必失败的选择）。
- 「全选」按点击瞬间的可用性执行：新作业下第一次点「全选」不会勾选 domain（当时 md 尚未选中）；md 被勾选后 domain 变为可用但不自动勾选，再点一次「全选」或手动勾选即可。「清空」一律清除已勾选项（含 domain）。
- **文件级校验不在前端**：前端信号只到"步骤已登记 / 本次已选"粒度；"md 目录至少有 1 个 `.md` 文件"由后端准备链强制（§5.2），实际失败以执行结果区消息呈现。这是"不做就绪接口、不过度设计"决策的直接结果（§2.2）。

### 8.3 描述链接与弹窗

- 链接文本（步骤行内）只反映**本次会话相对页面加载时生效描述（基准值）的变化**（基准值 = 重跑 `job.domain_description ?? source.description ?? ''`，新作业 `source.description ?? ''`）：
  - 本次会话未修改，或"已保存值 = 基准值"（含打开后未改动直接保存、改为其他值后又改回基准值；重跑时本作业已存 `db_desc` 与源描述不同但本次未改同此）→ 保持 `--description "…"`；
  - 已保存值 ≠ 基准值 → 显示 `--description "前 6 个字符…"`（**按 Unicode 码点**取前 6 个字符——与后端 `len` 计数口径一致，不拆断代理对；不足 6 个取全部，后加省略号，如 `--description "订单管理系统…"`）。判据是与**基准值**比较、不是与当次弹窗预填值比较：第一次修改保存后，重开弹窗（预填为上次保存值）不改文字直接保存，链接**仍显示前 6 字**；
  - 不再提供"修改后清空"状态。
- 点击链接打开 `DomainDescriptionDialog.vue`（新增组件，样式对齐 `DeactivateSourceDialog.vue` / `DeleteSourceDialog.vue`）。未勾选 domain 也可打开（编辑描述与勾选解耦）。
- 弹窗内容：
  - textarea 优先预填本次会话已保存的描述；否则重跑作业按 `job.domain_description ?? source.description ?? ''` 预填，新作业按 `source.description ?? ''` 预填。重跑所需的 `domain_description` 来自 §7.2；用户保存后该值随执行请求送往后端，保证与 LLM 入参一致。本次会话未保存过时，执行阶段仍以锁下重新读取的数据库值为准；
  - 长度上限 1000、**按 Unicode 码点计数**（与后端 Python `len` 一致）：计数器与保存校验都按码点；不使用原生 `maxlength`（其按 UTF-16 码元计数，emoji 等字符会与后端口径不同）；
  - 复选框"执行时同步到数据源描述"，打开时恢复上次已保存的状态（本次会话从未保存过则不勾选）；
  - 单个「保存」按钮；放弃编辑用右上角叉号关闭。
- 打开弹窗后，textarea 与复选框都是草稿。点「保存」先 `strip()` 校验：空串/纯空白或超过 1000 字符时留在弹窗并显示错误，已保存的页面值不变；校验通过即视为已保存——**无论文字与预填是否相同**——把规范描述和同步标志写入页面已保存状态并关闭弹窗。点右上角叉号关闭只丢弃本次草稿，不改变页面已保存状态。保存与关闭都不发写库请求；即使勾选同步，未点击执行也不修改两表。
- **弹窗不允许清空描述（产品决定）**：保存校验拒绝空串/纯空白，也没有"清空"入口；已有描述（数据源或本作业 `db_desc`）时无法经弹窗回到"无补充说明"（`user_description=None`）生成路径——该路径仅在数据源描述与本作业 `db_desc` 均为空时自然出现。这与 CLI 把空白 `--description` 收成 `None` 的语义不同，属有意的产品取舍。

### 8.4 执行

- `createCollectionJob` 增加可选 `domain_description` 和布尔 `sync_domain_description`：仅当勾选了 domain 且本次会话在弹窗中保存过时成对携带（`domain_description` = 已保存的描述，`sync_domain_description` = 已保存的同步标志；文字与预填相同也携带）。未保存过则都不携带，由后端按 §5.3 解析 `db_desc → 数据源描述`；未勾选 domain 时两字段都不携带。
- 执行 Domain 时，即使用户从未打开弹窗，也要把后端本次实际解析确定、拟传给 LLM 的描述写入 `job_info.db_desc`。新作业先由前面的步骤创建 `job_id`，Domain 启动时才建其步骤行并写描述；不因弹窗保存而提前创建作业。勾选同步时，Domain 启动阶段按 §5.3 同事务写入数据源描述；此后 LLM 调用失败也保留已提交的两处描述。
- 执行结果区显示 domain 行（映射使用 §8.1 的稳定基础标签，不渲染描述链接），成功/失败计数、作业汇总提示、发布入口均走既有 `job_status` 逻辑，无新增代码。准备链失败和同请求阻断不写 domain 行，汇总仍只看表里已有的步骤行，发布入口因此可能仍打开；该缺口见 §5.6，前端不为它再写分支。
- **执行后刷新数据源描述**：执行请求返回后 `runJob` 本就会重新读取作业列表（取 `job_status`），该响应自带 `source.description` 即最新值——用同一响应**部分更新**页面 `source.description`（只替换该字段，不整对象替换），使"数据源基本信息"卡显示同步后的新值；不额外调用 `getDataSource`。勾选同步但 Domain 生成随后失败时描述也已提交，页面同样显示新值；作业列表请求失败时沿用现有容错跳过刷新（与 `job_status` 同处理）。
- 重跑页面：`storedSelection` 会把含 domain 的作业预勾选 domain（受 §8.2 可用性约束）；描述保存状态初始为"未保存"，弹窗按本作业 `db_desc` 优先预填。点击执行前不修改既有 domain 行。

## 9. 错误与失败语义

准备链错误按本次请求是否已有步骤结果分流（既有编排行为，`backend/jobs/collection_run.py:168-188`，本篇不修改该分支）。domain 与 md 相同：依赖或配置类准备失败抛 `DbStepConfigError`；平台库连接或读取失败返回失败结果（不带 `job_id`，按 `_UNREGISTERED_FAILURES` 分流）。另有一处细化：准备阶段故障（本地文件与配置段的非 `ValueError`、LLM 预检的非受控异常）抛 `DomainPreparationError`（`PlatformUnavailableError` 子类，专用 503 映射，见下表）。三者都不在服务内先写成 `failed`。HTTP 200 在此只表示「返回了本次请求的执行结果」，不代表全部步骤成功。另有既有例外：数据源登记在请求中途被删除（消息为「未找到指定 source_id 的数据源」）一律转 404。有 `job_id` 仍不落失败行的缺口见 §5.6。

| 场景 | 呈现 |
|---|---|
| 无 `job_id` | 抛 `DbStepConfigError("同一作业的 MD 产物未就绪；请先执行 MD 或指定已有 job_id")`。本次 `results` 为空时 400；已有结果时 HTTP 200 并把该步记为 failed。两种都不登记 domain 行 |
| 主配置加载失败，或平台设置加载抛 `ValueError` | 按 §5.2 步骤 1 的独立异常规则转 `DbStepConfigError`（主配置加载的非 `ValueError` 只显示「主配置加载或校验失败（{类型}）」）；`results` 为空时 400，已有结果时 HTTP 200 计入 failed。不进入平台库或本地准备故障分支，不写 domain 行 |
| 工作区不存在，或步骤行不属于该源 | `assert_workspace_owner` 的 `WorkspaceMissingError` / `WorkspaceSourceMismatchError` 均先转 `DbStepConfigError`，消息保留原文（`指定的 job_id 不存在: …` / `指定的 job_id 不属于该数据源: …`），不得由平台库兜底收成 503。分流同上：`results` 为空时 400，已有结果时 HTTP 200。不写 domain 行 |
| 源禁用 | 抛 `SourceDisabledError`。`results` 为空时 409 `source_disabled`；已有结果时 HTTP 200 计入 failed。不登记 domain 行 |
| 会话 1 平台库连接或读取异常（建连、查询的非配置类失败，如 `SQLAlchemyError`） | 对齐 md 返回「平台库连接或读取失败（{类型}）」失败字典（不带 `job_id`、不写 domain 行）。`results` 为空时整体 503 `platform_unavailable`；已有结果时该步 `status=failed` 计入 `results`（HTTP 200），前面步骤结果保留 |
| Domain 准备阶段的非 `ValueError` 异常（本地文件段的 `OSError`/`PermissionError`/未预期程序错误；LLM 预检的非受控故障如 `ImportError`） | 抛 `DomainPreparationError`（`PlatformUnavailableError` 子类，消息「Domain 准备阶段故障（{阶段}：{类型}）」，不写 domain 行；捕获处记录阶段与原始异常类型——只记类型字段，不带 `exc_info`、不写异常原文）。`results` 为空时 503 **`domain_preparation_error`**（「Domain 准备阶段故障，请查看日志」；专用 handler 按 MRO 先于 `platform_unavailable` 命中，不回显异常原文）；已有结果时经既有 `PlatformUnavailableError` 分支以封装后消息计入 `results`（HTTP 200）；不转 400「请求不合法」 |
| 同请求 MD 已失败 | 编排层阻断，不调用 `run_domain_step`。`results` 中 domain `status=failed`，消息为「本次请求的 MD 未成功，Domain 未启动；如需使用已有 MD 产物，请单独重跑 Domain」。不登记 domain 行。前面步骤的结果保留，接口 HTTP 200 |
| MD 未就绪、MD 或 domain 目录/快照的受控 `ValueError`、LLM 配置错误、锁下复查 md 不再 success | 抛 `DbStepConfigError`（消息分别为「同一作业的 MD 产物未就绪；请先执行 MD 或指定已有 job_id」或 `str(exc)`）。`results` 为空时 400，已有结果时 HTTP 200 计入 failed。不调用 `start_step`，不登记 domain 行，不更新数据源描述，已有 `db_desc` 保持原值 |
| 会话 2 `start_step` 抛 `StepAlreadyRunningError`（domain 行仍为 `running`，存在并发执行） | 返回带 `job_id` 的 failed 结果（消息「当前步骤可能已有作业正在执行」），该行保持 `running`，HTTP 200；`db_desc` 与数据源描述均未写入（抛错发生在 commit 之前，挂起的源描述更新随会话关闭回滚） |
| 生成/核验/写盘失败 | results 中 `status = failed`（HTTP 200）；此时行已经是 `running`，由 `finish_step(FAILED)` 改为 failed。`db_desc` 保留本次已提交的描述 |
| 状态写回失败 | 消息追加「作业状态更新失败（{类型}），请查看日志确认作业状态」，对齐 md |
| 弹窗保存空白/超长 | 弹窗内报错，页面已保存描述不变；不发写库请求 |
| POST 显式描述为空、非法类型、超长，或同步标志缺少合法描述/domain 步骤 | 422；不写两表 |
| 执行时同步的两表在 `start_step` 提交时失败 | 本篇不捕获，不按 md 的「作业状态登记失败」兜底处理。与失败落库一起记在 [100 备忘录](100_备忘录.md) 第 3 条，以后统一改（§5.2 第 6 步、§5.6） |

## 10. 验收

**数据模型与后端**

- A01 平台库 `job_info` 含可空 `db_desc` 列，`models.py` 与库结构一致；既有行 `db_desc` 均为 NULL；备份表存在（§4）。
- A02 作业创建接受 `steps` 含 `domain`；未知步骤报错文案含 domain 全清单。
- A03 任意传入顺序下，同请求执行序满足 `…→md→domain`；`_BLOCK_MESSAGES` 含 `(md, domain)`，本次 md 失败时 domain 不执行。
- A04 domain 作为首步骤且无 `job_id` → 400，"同一作业的 MD 产物未就绪；请先执行 MD 或指定已有 job_id"；`job_info` 不出现 domain 行。
- A05 md 行非 success、md 目录无 `.md` 文件、md 目录**仅有非常规文件**（符号链接/FIFO，无普通 `.md`，按「MD 产物未就绪」拒绝），或 `resolve_md_output_dir`/枚举的**受控 `ValueError`**（其他异常按 A15 的 `DomainPreparationError` 验收）：a) 本次 `results` 为空（含无 `job_id`、以及重跑只跑 domain）→ 400、不登记 domain 行；b) 本次已有步骤结果（如前面的 db/ddl/json 已成功，或 `[md, domain]` 中 MD 已成功而 Domain 预检仍失败）→ HTTP 200、`results` 中 domain `status=failed`、不登记 domain 行，已有 `db_desc` 与数据源 `description` 不变；c) 同请求 MD 本身失败 → domain 被阻断，消息为「本次请求的 MD 未成功，Domain 未启动；如需使用已有 MD 产物，请单独重跑 Domain」，不调用 `run_domain_step`，不登记 domain 行；d) md success 且有 `.md` 文件 → 进入生成；e) 请求携带的 `job_id` 不存在或不属于该源 → `assert_workspace_owner` 的两类异常均转 `DbStepConfigError`，本次 `results` 为空时 400，消息保留「指定的 job_id 不存在/不属于该数据源」，不写 domain 行；f) 混合目录（普通 `.md` 与符号链接/FIFO 并存）跳过非常规文件后正常生成，不整步失败。
- A06 §5.3 四种组合逐一验证：显式非空值覆盖、显式空值拒绝、未携带时复用旧 `db_desc`、未携带且旧值为 NULL 时复制数据源描述；写入 `db_desc` 的字符串与 `generate_from_context` 的 `user_description` 参数相同，不与整段提示词比较（成功进入生成时；LLM 调用前失败时 `db_desc` 保留已提交值，见 §9）。源描述也为 NULL 且未打开弹窗时沿用无补充说明路径。这四条都发生在会话 2 的 `start_step` 成功之后。
- A07 产物落在 `output/<source_id>/<job_id>/domain/db_domains.yaml`；生成前目录顶层被清空。越界路径与符号链接在 `start_step` 之前被 resolver 拒绝：抛 `DbStepConfigError`，不调用 `DomainGenerator`，不清理、不写入该目录，不登记 domain 行（`results` 为空时 400，已有结果时 HTTP 200）。
- A08 核验：坏 YAML、`domains` 为空、产物为符号链接 → failed；正常产物 → success 且目录内无 manifest.json。空 `domains` 用例不能靠成功写盘复现（`write_to_yaml` 恒注入 `_未分类_`）：测试在写盘后替换文件，或直接把坏内容交给核验函数。
- A09 LLM 配置缺失：抛 `DbStepConfigError`，消息为配置错误原文，不调用 LLM，不登记 domain 行，不更新数据源描述。`results` 为空时 400；本次已有步骤结果时 HTTP 200，`results` 含该条 failed。已有 domain 行的 `db_desc` 保持原值。
- A10 弹窗保存且勾选同步时，保存本身不写库；Domain 执行前将规范描述写入本作业 `db_desc`，并在同一平台库事务更新数据源 `description` 与 `updated_at`。事务失败两表都不变且不调用 LLM；成功后 LLM 失败仍保留两处描述。未勾选时仅写 `db_desc`；全程不连接源库。两表原子性的**实库事务证据**见 §11 批次 1 的 live 用例（一次 commit 一起提交、失败分支与 commit 失败两径一起回滚）。
- A11 `POST .../collection-jobs`：省略 `domain_description` 时按 `db_desc → 数据源描述` 取值并将本次已确定值写入 `db_desc`；显式空串、纯空白、null、非法类型、>1000 及无合法描述却要求同步 → 422；同步标志不允许非布尔值，未知字段仍被 `extra="forbid"` 拒绝。作业列表仅返回本作业 domain 行的 `db_desc` 供重跑预填。
- A12 汇总口径回归：生成阶段 `finish_step` 写下的 domain `failed` 行使作业 failed → 采集页「下一步发布」不可用、发布候选不出现。准备链失败和同请求阻断不写 domain 行，汇总仍只看已有行（缺口见 §5.6，本篇不补）。domain 之外步骤全 success、且没有 domain 失败行的作业不受影响。
- A13 domain 执行不改动 ddl/json/md 的产物与状态行。json/md 准备链失败和阻断仍然不写自己的 `job_info` 行。
- A14 日志路由（分进程验收）：a) `OPERATION_STEP_MAP` 含 `"domain"`、断言放宽为 `set(METADATA_OPERATIONS) <= set(OPERATION_STEP_MAP)`，`set_operation_step("domain")` 不抛 `KeyError`（单元级，进程无关）；b) script profile：在 `configure_logging("script")` 上下文执行 domain 步骤/发一条 `step=domain` 记录 → 写入 `logs/script/domain.log`；CLI `--generate-domains` 仍写 `logs/script/generate_domains.log`；c) API 进程：一次 Web 采集执行**不产生** `logs/script/domain.log` 写入，domain 步骤日志出现在 `logs/backend/metaweave.log`（`/api/data-sources` 请求归属；无请求上下文记录回落 `logs/backend/platform.log`）。

- A15 平台库不可用与配置错误分离：模拟会话 1 平台库连接/读取异常（`platform_session` 建连或查询抛 `SQLAlchemyError`）→ 返回「平台库连接或读取失败（{类型}）」失败字典、不带 `job_id`、不写 domain 行；`results` 为空时接口 503 `platform_unavailable`，已有结果时该步 `status=failed` 计入 `results`（HTTP 200）。反向用例：本地文件段受控 `ValueError`（如目录符号链接/越界）→ 转 `DbStepConfigError`（400/计入 failed）；非 `ValueError`（如 md 目录枚举 `PermissionError`、LLM 预检 `ImportError`）→ 抛 `DomainPreparationError`：`results` 为空时 503 `domain_preparation_error`（「Domain 准备阶段故障，请查看日志」，不是 `platform_unavailable`）；已有结果时该步 `status=failed` 且消息含阶段与原始异常类型（「Domain 准备阶段故障（…：…）」）（HTTP 200）；捕获处日志含阶段 + 原始异常类型，且**不含异常原文或凭据**（不带 `exc_info`，doc 15 §8 脱敏要求）。不报 400。
- A16 md 读取不跟随符号链接（§13.2）：目录内 `.md` 为符号链接或 FIFO 时被跳过并告警、内容不进入提示词；全部文件被跳过时以「md 摘要为空」拒绝；普通文件路径行为不变（CLI 与 Web 共用同一加固，用例在 `test_domain_generator.py`）。

## 13. 边界与已知取舍

1. **并发定制覆盖**：多人同时在各自页面定制同一作业的描述、先后执行时，后执行者覆盖 `db_desc`（用户确认暂不处理该极端场景）；勾选同步者还会覆盖数据源描述。本次未保存新值的执行在源行锁下按 `db_desc → 数据源 description` 读取，并把当次已确定值存为快照。
2. **md 变更复查（不做，含事实澄清）**：事实核对——`start_step` 只拒绝**同一 (job_id, step_name)** 的重入；同一作业的不同步骤可并发，重跑入口在作业 running 时也未禁用（`CollectionJobsView.vue:188-191` 仅按 `is_active` 控制）。domain 的准备链要求 md 行为 success，可拦截"md 正在运行"的多数情形，但"准备链检查完成之后、读取 md 文件之前"存在窄并发窗口（md 恰在此时清目录重生成），此时 domain 可能读到部分/旧文件。21.1 按"结果传递、不做状态复查"决策暂不处理；如评审决定补充，实现为：准备链记录 md 行 `updated_at`，结束锁下比对一次，变化则本次标 failed（约 10 行，与 json→md 的机制同款）。
   同窗口的另一形态是**文件类型替换**（已检查的普通 `.md` 在生成器读取前被换成符号链接）。本篇在**读取侧**防护：`domain_generator._build_md_context` 经 `_read_md_text` 读取——`os.open(O_RDONLY|O_NOFOLLOW|O_NONBLOCK)` 不跟随符号链接、FIFO 打开不阻塞，`fstat` 复核常规文件；非常规/不可读文件跳过并告警，全部被跳过时沿用既有「md 摘要为空」拒绝。准备链跳过非常规文件、无可读普通 `.md` 时才拒绝（§5.2），与之互为纵深；检查-读取窗口在读取侧被消除。该组件与 CLI 共享：CLI 正常输入（普通文件）行为不变，仅符号链接/非常规 `.md` 不再被跟随读取，属防御性硬化。
3. **CLI 互不影响**：`--generate-domains` 仍写 `output/domains/db_domains.yaml`；Web 产物在 `output/<source_id>/<job_id>/domain/`；两边互不读取、不迁移。Web 改造后 CLI 产物不再被 Web 使用（用户明确允许 CLI 后续不可用）。
4. **弹窗预填与写库时机**：弹窗展示本次会话已保存值，否则按本作业 `db_desc → 数据源 description` 预填；新作业没有 `job_id`，弹窗保存不建 job 行，也不回写数据源。描述与可选同步均在 Domain 执行前同事务提交；未打开弹窗直接执行时，同样把当次已确定的描述复制到 `db_desc`。已保存值在请求中成对显式携带（保存后即使文字与预填相同也携带），确保展示值与本次拟传给 LLM 的值相同；本次会话未保存过时以执行时锁下重新读取为准。
5. **描述长度上限 1000**：弹窗保存值与显式提交值须非空且不超过 1000 字符；`db_desc` 列本身无长度约束。数据源原有描述为 NULL 且本次未保存新值时，沿用无补充说明生成路径。
6. **LLM 为硬依赖**：domain 无降级路径，LLM 不可用即步骤失败（与 json 的「可关闭 LLM 增强」不同）；Web 端 json 步骤已在运行 LLM（`json_generation.*.llm_enabled: true`），不构成新的部署依赖。预检失败在 `start_step` 之前抛错，不写 domain 行。
7. **准备失败暂不落库**：同请求阻断和 `start_step` 之前的失败都不写 `job_info`，与 md 依赖 json 的现状相同。有 `job_id` 时仍要落 `failed`，以及 `start_step` 登记过程中其他异常的兜底，见 [100 备忘录](100_备忘录.md) 第 3 条，本篇不实施。
