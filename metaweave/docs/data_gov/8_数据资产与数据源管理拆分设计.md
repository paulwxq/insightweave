# 数据资产与数据源管理拆分设计

> 状态：已实施。本文是 [doc 7：数据源查看与删除设计](7_数据源查看与删除设计.md) 的增量。不实现画像采集、发布、导入资产、搜索或侧栏折叠。

原型：[2.数据资产管理首页](ui/2.数据资产管理首页.html)（[图片](ui/2.数据资产管理首页.png)）、[2.1.数据源管理首页](ui/2.1.数据源管理首页.html)（[图片](ui/2.1.数据源管理首页.png)）。

## 1. 需求

当前 `/data-assets` 的标题是“数据资产”，主体却是“数据源连接”卡片。按原型把它拆成两个页面：

1. “数据资产”页改为资产目录。目录列出各数据源的画像概览。本阶段还没有画像作业，目录留空，不放示例库，也不调用画像接口。
2. 左侧导航在“数据资产”下方增加子菜单“数据源管理”。点击进入数据源管理页。
3. 现在卡片上的“删除”“查看”“修改”“采集”，以及“创建数据源连接”“刷新列表”，随卡片搬到数据源管理页。行为与 doc 7 相同。
4. 从实现上看，是把现在的数据资产页下沉为数据源管理页，原地址改成只放资产目录。

仍只支持 PostgreSQL。不改登记、查看、修改、删除接口，不回显密码或密文。

## 2. 导航

`AppSidebar.vue` 在“数据资产”下增加“数据源管理”，缩进显示。两项都可点击，本阶段不做展开/收起。

高亮按当前路径判断，不用 `RouterLink` 的默认激活类。这些地址是平级路由，Vue Router 不会因为路径以 `/data-sources/` 开头就让指向 `/data-sources` 的链接处于激活状态。

| 菜单 | 条件 |
| --- | --- |
| 数据资产 | `route.path === '/data-assets'` |
| 数据源管理 | `route.path === '/data-sources'`，或 `route.path.startsWith('/data-sources/')` |

因此创建、修改、查看页高亮“数据源管理”，“数据资产”只在资产目录页高亮。不必改成嵌套路由。侧栏其余部分不动：品牌仍是 MetaWeave，“新建查询”“新建分析”“系统设置”和“分析项目待接入”保持现有占位。不按原型改成 DataWeave，也不搬“最近分析项目”里的示例项目。首页“进入数据资产”仍指向 `/data-assets`，不改 `HomeView.vue`；它进入的是资产目录，不是数据源管理。

## 3. 路由

导航上是子菜单，地址仍用同级路径。高亮规则见第 2 节，不依赖路径前缀自动匹配。

| 路径 | 页面 |
| --- | --- |
| `/data-assets` | 数据资产，资产目录留空 |
| `/data-sources` | 数据源管理，即现在的卡片页 |
| `/data-sources/new` | 现有创建页 |
| `/data-sources/:sourceId/edit` | 现有修改页 |
| `/data-sources/:sourceId` | 现有只读页 |

`/data-sources/new` 仍排在带参数的路由前面。创建、修改、查看组件不重写，只改它们的路由和页内链接。

以下旧地址重定向到对应新地址，查询参数保留。原有路由名称 `create-data-source`、`edit-data-source`、`data-source-detail` 迁到 `/data-sources` 的正式路由；这三条旧重定向不设置 `name`，避免名称冲突：

- `/data-assets/new`
- `/data-assets/:sourceId/edit`
- `/data-assets/:sourceId`

doc 7 里 `notice=not_found` 改为回到 `/data-sources`。列表上的“数据源不存在”仍显示在数据源管理页。创建页和查看页上可见的“返回数据资产”改为“返回数据源管理”，目的地是 `/data-sources`。表单“取消”只改目的地，按钮文字不变。doc 7 里对应的按钮文案一并改成“返回数据源管理”。

## 4. 数据资产页

页头按原型：眉题 `DATA ASSETS`，标题“数据资产”，说明“把常用数据库统一登记、画像并复用。资产属于系统，只有明确绑定后才会进入某个分析项目。”

页头按钮：

| 按钮 | 行为 |
| --- | --- |
| 创建数据源连接 | 进入 `/data-sources/new` |
| 导入资产 | 保持禁用，不发请求 |

上方三张统计卡按图 2 的标题，不沿用现在的“已登记数据源”“可用表数量”和“数据库大小”，也不抄原型里的 4、1 和 334.6 万。本阶段没有发布和绑定，三张都不调用列表接口，数字都是“—”：

| 卡片 | 说明 |
| --- | --- |
| 可复用资产 | 当前仅支持 PostgreSQL，资产发布待接入 |
| 已服务项目 | 跨项目复用，项目内仍保持隔离 |
| 已画像数据行 | 以最新画像基线为准 |

资产目录仍显示“还没有画像数据”的空状态。这里没有“数据源数量加载失败”。

下方原“数据源连接”卡片区改为“资产目录”：

- 眉题 `ASSET CATALOG`，标题“资产目录”，说明“已发布数据库画像的名称与概览。后续可在此刷新画像或管理资产。”
- 主体只有空状态：“还没有画像数据。完成画像采集并发布后，这里会列出各数据源的画像概览。”
- 不放搜索框，不放“4 个数据库”，不放原型中的 MySQL、SQLite、Excel、CSV 示例行，也不放每行的刷新和删除。

本阶段不读取 `output/` 里的画像文件。数据资产页不再读取 `notice` 参数，也不显示“数据源不存在”。内部跳转直接去 `/data-sources?notice=not_found`。不为 `/data-assets?notice=not_found` 增加条件重定向：Vue Router 按路径匹配，查询参数不能单独变成另一条路由。打开这个旧地址时留在资产页，忽略该参数。

## 5. 数据源管理页

把 `DataAssetsView.vue` 里现有的数据源连接区域搬到新页面，交互保持不变。

页头按原型：眉题 `DATA SOURCE`，标题“数据源管理”，说明“登记并管理数据源连接。登记仅表示接入系统，完成画像采集并发布后，才会进入数据资产目录；明确绑定后才会进入分析项目。”页头保留“创建数据源连接”。“导入资产”保持禁用。

统计卡按 2.1 原型的三张，不沿用现在的“可用表数量”和“数据库大小”，也不抄原型里的示例数字：

| 卡片 | 数字 | 说明 |
| --- | --- | --- |
| 已登记数据源 | 现有列表接口的条数。加载中为“—” | 来自平台库的真实登记记录 |
| 可用数据源数量 | “—”。本阶段没有采集和发布，不能把已登记条数当成可用数量 | 待接入采集与发布 |
| 已禁用数据源数量 | “—”。本阶段没有停用状态，不能计算已禁用数量 | 数据源状态管理待接入 |

列表加载失败时，沿用现在的列表错误和“重试”；“已登记数据源”不把空列表显示成 0，数字为“—”。刷新列表、卡片字段和按钮顺序保持现状：右上角“已登记”“删除”“查看”，页脚“修改”和禁用的“采集”。删除仍用现有确认窗。查看、修改仍进入第 3 节的新路径。空列表、加载失败和 `notice=not_found` 仍留在这一页。

不按原型增加第二枚“可用”标签，也不改卡片已经实现的字段。

## 7. 实施步骤

审核通过后再改代码。

1. 抽出数据源管理页，并把创建、修改、查看链接改到 `/data-sources`。
2. 为三条旧路径加保留查询参数的重定向。
3. 数据资产页换成资产目录空状态。
4. 侧栏增加子菜单。
5. 在 `frontend/` 执行 `npm run typecheck`，以及 `VITE_API_BASE_URL=http://127.0.0.1:8001 npm run build`。不要裸执行 `npm run build`。这两项不能验证导航高亮和重定向，按第 8 节做页面手测。不引入前端测试框架。

## 8. 验收

- “数据资产”页下方是空的资产目录，没有数据源卡片，也没有原型中的示例数据库。
- “数据源管理”在侧栏“数据资产”下方，打开后能看到现有卡片。
- 卡片上的查看、修改、删除和禁用的采集与搬迁前一致；查看和修改进入 `/data-sources` 下的页面。
- 旧的 `/data-assets/new`、`/data-assets/:sourceId`、`/data-assets/:sourceId/edit` 打开后落到新地址，原有查询参数仍在。
- `/data-sources/new`、详情页和修改页高亮“数据源管理”。`/data-assets` 只高亮“数据资产”。
- 创建页和查看页的返回按钮显示“返回数据源管理”，并进入 `/data-sources`。
- 数据资产页和数据源管理页的“创建数据源连接”都进入 `/data-sources/new`。创建或修改保存成功后回到 `/data-sources`。表单“取消”回到 `/data-sources`。详情页删除成功，或数据源不存在时，也回到 `/data-sources`。
- 数据资产页三张统计卡是“可复用资产”“已服务项目”“已画像数据行”，数字都是“—”，不显示已登记条数，也没有“数据源数量加载失败”。资产目录仍是“还没有画像数据”。
- 数据源管理页“已登记数据源”显示列表真实条数；加载中或失败时为“—”。“可用数据源数量”和“已禁用数据源数量”始终为“—”，不使用原型示例数字。
- `/data-assets?notice=not_found` 留在资产页，不显示“数据源不存在”。`/data-sources?notice=not_found` 才显示这句话。
- “导入资产”、资产目录的搜索、刷新画像和删除都不出现为可操作功能。
