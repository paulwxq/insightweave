# 数据仓库 / 数据集市：数据库元数据治理

若限定为对**数据仓库**或**数据集市**进行数据库元数据治理，其核心工作可归纳为以下六类。

## 1. 技术元数据采集

自动采集数据库中已有的结构信息：

- 数据库、Schema、表、视图、字段
- 字段类型、长度、精度、默认值
- 主键、外键、唯一约束、索引
- 分区、存储过程、函数等数据库对象
- 对象创建时间、修改时间和状态

**作用**：回答「数据库里有哪些数据对象」。

## 2. 元数据补充与完善

补充数据库自身通常没有，或记录不完整的信息：

- 表和字段的中文名称
- 表用途、字段业务含义
- 表的数据粒度
- 所属主题域和业务对象
- 数据负责人、维护部门
- 生命周期状态（如在用、停用、待下线）

部分内容可由 AI 推荐，但应由**人工审核确认**。

## 3. 元数据规范管理

制定并执行元数据自身的管理规范：

- 表、字段和数据库对象的命名规范
- 中英文名称及缩写规范
- 表和字段描述的填写规范
- 主题域和数据分类规范
- 负责人、状态、来源等属性的填写要求
- 元数据变更和审批规范

> 这里规范的是**元数据如何描述和管理**，不是实际数据值是否合格。

## 4. 元数据检查与整改

检查元数据本身是否完整、规范和一致：

- 表或字段是否缺少注释
- 注释是否没有有效业务含义
- 命名是否违反规范
- 同一缩写是否表达多个含义
- 同类字段的名称和描述是否明显冲突
- 是否缺少主题域、负责人等必填属性
- 元数据记录是否与数据库实际结构同步

输出问题清单，并推动补充、确认和整改。

## 5. 数据资产目录与检索

按照业务和技术视角组织元数据：

- 按数据库、Schema、主题域展示
- 支持按表名、字段名、中文名称和描述搜索
- 展示表结构、字段含义和对象关系
- 标记重要表、核心字段、敏感字段
- 支持查看负责人、状态和变更记录

**说明**：「目录」本质上是元数据的组织、检索和展示方式。

## 6. 变更与版本管理

持续发现并记录数据库结构变化：

- 新增、删除和修改表或字段
- 字段类型、长度、约束变化
- 视图定义或数据库对象变化
- 变更前后的元数据版本对比
- 对元数据负责人发送变更通知
- 对受影响对象进行提示

### 可作为扩展（需说明边界）

- **业务术语映射**：把人工确认的术语关联到表和字段
- **敏感字段登记**：记录字段的分类分级结果
- **数据库内部依赖**：解析视图、存储过程等能够观察到的依赖关系
- **局部血缘**：只有获得视图、SQL 或过程定义时才能建立，**不能等同于完整血缘**

---

## 小结

狭义数据库元数据治理可以概括为：

> **采集数据库结构 → 补充业务描述 → 建立元数据规范 → 检查并整改元数据问题 → 形成可检索的数据资产目录 → 持续跟踪结构变化。**

它**不包含**：

- 实际数据质量检测
- 主数据统一
- 完整 ETL 血缘分析
- 指标口径治理
